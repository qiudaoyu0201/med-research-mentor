# UI 用户流程验收（2026-10-28）

## 环境与范围

- 在 `codex/ui` 上验收，以 `2cf67b1` 的 UI 精修为起点；本轮仅修复取消反馈，并补充回归测试。
- 使用独立数据目录与 `http://127.0.0.1:4322/`，不导入、覆盖或删除真实用户资料。既有 4321 UI 预览与 4336 功能服务未重启。
- 首先断开模型验证失败恢复；随后显式使用现有 `codex-configured:klapi`、`gpt-6.1-sol` 通道完成真实生成，没有更换模型或修改凭据。
- 实际生成只使用软件验收用合成 PDF 与合成课题，不是医学、动物实验或临床方案的科学验收。

## 按用户顺序实测

| 流程       | 操作与结果                                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 整理资料   | 新建课题、重命名、导入论文、重命名论文、移动到另一课题、搜索定位均可操作，数量与当前论文同步。                                                                      |
| 无效文件   | 导入伪 PDF 明确提示“文件内容不是 PDF”；重试原文件仍正确拒绝，关闭提示后可重新选择有效文件。                                                                         |
| 原文阅读   | 有效合成 PDF 导入成功；原页渲染、放大到 125%、固定对照、返回讨论、引用跳转可用。宽度不足时提示收起导航，桌面空间足够时可并排。                                      |
| 提问与恢复 | 故意断开模型后显示请求失败，可编辑后重发；恢复真实通道后，阅读请求完成并展示中文回答。复制回答与查看 PDF 原文可用。                                                 |
| 生成汇报   | 从“新建汇报”选择合成论文与 2 页设置，真实完成生成；两页预览、上一页/下一页边界、独立讲述提示可用。                                                                  |
| 汇报下载   | 经页面准备 PPTX 后实际点击下载 PPTX 和讲述提示，均触发下载事件；再次获取真实文件，检查 PPTX ZIP 与两张幻灯片 XML 均有效，讲述提示包含两页。                         |
| 生成方案   | 从“新建方案”填写问题、条件、补充要求并选参考论文，真实完成生成与核对；正文、版本、设计理由及下载入口可见。                                                          |
| 方案下载   | 实际点击 Word 与 Markdown 均触发下载事件；真实 DOCX 包含内容类型与正文 XML，Markdown 和 DOCX 均保留首末章节。未进行 Word 桌面排版验收。                             |
| 取消生成   | 分别启动汇报与方案的新版本后取消；生成停止、输入恢复，之前完成的成果仍可预览和下载。                                                                                |
| 版本恢复   | 用真实保存 API 补入一份手动方案草稿，再在页面选择历史版本并“以此版本继续修改”；原版、手动稿及恢复稿均保留。未核对新稿不继承旧版的导出资格，历史已核对版本仍可下载。 |
| 重新打开   | 刷新后重新进入模块，汇报页数、要求、生成成果、方案条件与取消状态恢复，没有重新提交模型请求。阅读历史、待重发问题亦能恢复。                                          |
| 设置与键盘 | 保存默认“深入”偏好；深色与字体选择在刷新后保留；完成和 Escape 关闭设置可用，关闭后焦点回到设置入口。稳定状态下深色按钮、正文及表单可读。                            |

## 发现与修复

- 发现：用户主动取消 PPT 生成后，把底层 `This operation was aborted` 当作红色错误直接展示。
- 修复：汇报与方案统一显示中文“已取消生成，已有内容已保留，可调整要求后重新生成。”，使用 `role="status"`；真实错误仍使用 `role="alert"` 并保留诊断。
- 增加 4 项单元测试，覆盖有/无底层错误的取消、真实失败与澄清信息保留、缺失错误信息时的可行动兜底。
- 修复后在浏览器重新验证两种生成任务的取消、成果保留与刷新恢复。

## 边界

- 内置开发示例未附带真实原图时，示例 PPT 的导出会被缺图校验拒绝，这是既有保护。本轮成功导出验证使用实际生成、没有缺失图片引用的两页合成汇报，不能据此声称真实复杂图件已全部复测。
- 本轮覆盖桌面常用主流程，不等于穷尽所有操作、复杂扫描 PDF、长文献、网络异常或所有生成内容的科学准确性；不作“绝无 bug”承诺。
- 正式用户数据未迁移；开发分支的运行服务未自动切换到 main。合并推送与本地服务重启是两件事。
