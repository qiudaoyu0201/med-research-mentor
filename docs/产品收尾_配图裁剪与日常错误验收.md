# 产品收尾：配图裁剪与日常错误验收

更新：2026-10-07。实现起点 `76a3167`，当前需求以[落地方案 v2.7](科研能力培养与三类Agent协作_整体落地方案.md)为准。

本轮修好可直接定位的产品问题：配图链路、裁剪保存、预览／导出一致性、日常失败恢复和本地数据结构恢复。按用户最新约定，讲解水平、研究设计深度、PPT 组织与选图能力、教学迁移效果留到内部训练；真人核验与国内模型暂缓。工程通过不代表上述能力已达标。

## 工程验证

- `npm run check`：类型检查、生产构建和 **148 项测试通过**。本轮新增六个有独立判定依据的产品测试，覆盖图形／双栏定位、晚页方法与真实范围、异常结构、像素／PPTX／版本、失败草稿和共享布局。
- 十组浏览器检查通过：core-generation、research-plan、ppt-reading-notes、reading-focus、stability、scheduling、materials-tools、learning-intent、simplification、ppt-crop。零模型调用；固定响应只验证流程。原文返回、打字笔记、取消与迟到响应、未保存草稿、完整稿编辑与 MD／TXT 下载继续可用。
- 新配图浏览器检查在 1440×960 下实际拖动选择，读取提交区域，并刷新恢复；原核心检查还覆盖 1440／1024／768、浅深色，没有水平溢出或页面异常。工作台整体布局没有重做。
- 两篇真实 PDF 通过普通导入 API 提供图件。固定正文工程产物为 7／3 页：全部九张完整原图，另加一个 Figure 1a 局部图。用本机 PowerPoint 打开并逐页导出 1600×900 PNG，实际查看原图、坐标轴／图例和局部标签。此处不称为模型生成 PPT 验收。
- 两个已有数据目录的历史记录只读结构检查结果见 `runs/product-finish/historical-shapes.json`；没有用用户记录测试损坏隔离。
- 历史记录共 137 份通过只读结构兼容检查。用户预览 `http://127.0.0.1:4328/` 已更新，原索引、4 篇论文和 11 段聊天的 ID 保持一致；旧成功 PPT 版本仍可导出。结果见 `user-preview-final.json`。测试记录仅在独立端口／数据目录。

## 真实模型检查与失败记录

脚本 `scripts/product-acceptance.ts` 从普通入口运行，两篇论文不指定隐藏来源，四类方案以设计草案为目标。真实调用与零调用回归分开。`TUTOR_ACCEPTANCE_LIVE=1` 才运行；`TUTOR_ACCEPTANCE_RESUME=1` 复用原论文、保留失败历史，仅补未通过案例。遇额度不足停止未开始的模型案例，等待超时请求取消，不自动重发。

本轮基础／转化、临床观察、临床干预、二次研究四类方案均有真实成功生成与导出样本，各用两次调用。样本保留未知条件，未把建议写成已完成结果；只证明这些请求下的正常生成，不代表研究设计可直接实施或广泛科学质量通过。

初次检查复现了普通汇报“方法”误路由，已修复并新增零调用回归。模型额度限制导致若干任务失败；恢复后的续验保留这些历史。本轮账本共记录 38 次调用尝试，包含失败与续验，没有把额度失败当成成功。

## 数据保存与部署边界

已保存的论文、原 PDF／附件、聊天、笔记、PPT／方案版本在服务端数据目录；导出文件在 `exports/`。未保存草稿、偏好、阅读选区存在当前浏览器，待发附件还使用 IndexedDB。当前标签页通过 sessionStorage 记住自己的聊天，服务端保存的内容不依赖该标签页。

以后多人部署需要账号和用户隔离、持久化服务端数据／文件、访问约束和备份，用户导出则下载到自己的设备。当前仅本机单用户监听，没有实现多人账号隔离，不将它报为部署就绪。本轮不为这项未来用途扩张界面。

## 证据位置与余项

代码和当前文档提交 Git；个人数据和检查产物留在忽略目录：`runs/product-finish/`。其中 `check.log`、`browser-*-final.log`、`browser-crop/report.json`、`export-probe.json`、`render-paper-1/`、`render-paper-2/`、`live/report.json` 分别保存测试、操作、真实文件和模型结果。历史模型失败及早期图件验收不删除。

本轮不交付 DOCX／PDF 方案导出、PPT 页重排、跨产物同步或账号后台。后续工作是内部能力训练与真人核验；国内模型暂缓。已有功能的具体产品缺陷继续按复现修复，不能用训练延后解释保存、取消、导出等流程错误。
