## 已实现

- 导航导入 PDF 自动创建并进入论文主聊天。点击论文恢复该主聊天，取消论文内“开始新讨论”入口。旧多讨论首次按最近使用时间确定主聊天并持久保存，其余讨论保留回看，页面提供返回主聊天入口；旧 API 与 `/assistant` 保持兼容。
- 服务实例共用两个生成名额，覆盖聊天回答及直接 PPT 修改。一个问题中的作答、核对和修订共用一个名额；聊天内的 PPT 修改沿用该名额，不重复排队。同论文的历史聊天与 PPT 也按所属论文串行执行。
- 就绪任务按提交队列顺序启动，忙碌论文的后续任务等待，其他空闲论文可启动。等待任务可逐项取消；取消执行任务终止后续步骤并释放名额。问题、选区、论文与来源版本保存在服务端，等待期间来源版本变化会在调用前拒绝并提示重新选择。
- 同一聊天排队问题执行时读取先前已完成回答。并发提交不会覆盖历史消息 ID，运行中重命名不被完成结果覆盖。等待时间不消耗原有 480 秒执行额度，单任务调用和修订上限不变。
- 生成时导航、原文、笔记和输入继续可用，支持准备并提交下一条问题。轮次取消及失败后可恢复问题和原有引用编辑；切换后晚到的提交响应不会追加到当前另一篇论文。草稿及引用按论文保存，阅读位置与笔记继续使用原有持久存储。
- 刷新读取服务端轮次；后台重启将运行及等待任务标记为中断，保留记录，不自动重发。启动时迁移旧主聊天归属。
- PDF 上传使用提交标识与内容哈希去重，重试复用论文和聊天，标识对应其他文件时拒绝。解析单独限制为一个任务，不占模型生成名额。上传失败可使用同一标识重试；解析期间切换到其他论文时不强制切回。
- 同论文的 PPT 保存、恢复、导出及个人反馈显示对应冲突状态；其他论文的生成不再全局阻断这些操作。独立研究笔记可以在生成时保存。

## 验证

`npm run check`：类型检查、正式构建和 **81 项测试**通过。新增 `checks/scheduler.test.ts` 的 8 项确定性检查覆盖双聊天并行、第三任务等待／取消、执行取消释放、同聊天承接及并发重命名、过期资料阻断、PPT 共用名额、主聊天迁移／恢复、后台重启中断、导入去重及解析资源限制。任务输入、输出及保存路径经过真实服务类，Provider 使用工程固定响应，未发起真实模型请求。

在独立 `TUTOR_DATA_DIR`、端口 4318、正式构建及本机 Edge 下运行：

- `checks/browser-workspace.ts`：真实 PDF 上传和提取、错误文件、课题归组、原文引用、停止、笔记保存／编辑／导出、刷新恢复、键盘及多屏宽通过。
- `checks/browser-scheduling.ts`：真实上传重试产生一篇论文及一个主聊天；模拟双任务运行时导航／原文／下一条问题继续可用；逐项取消恢复问题；论文切换及刷新恢复草稿与引用；延迟提交响应归属及发送期间新草稿保留；1440、1024、768、390 像素无水平溢出。

浏览器运行／等待响应明确使用 HTTP 工程模拟，后端真正的队列执行另由上述服务测试验证，两者均为零真实模型调用。报告保存于 `runs/workspace/browser-report.json` 和 `runs/workspace/scheduling/report.json`；截图在对应目录，已检查桌面及手机截图。这些运行文件及隔离数据不提交。

首次浏览器回归因两个空主聊天同名“新讨论”而误判切换完成；将空主聊天标题显示为实际论文名并更新等待条件后回归通过。状态操作按钮补充间距与点击区域，避免文字挤在一起。回归还暴露同毫秒保存导致主聊天最近使用时间并列的问题，已使会话更新时间单调递增并通过迁移检查。
