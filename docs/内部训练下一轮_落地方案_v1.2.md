## 3. 唯一候选 C：精简来源到解释合同

只改变教学生成合同及其内部输出结构。普通请求、自动材料选择、模型配置、在线试读／核对、独立评价和实际交付结构均固定。当前在线规则继续作为正式基线，候选只在隔离快照中装载。

现有 B 会在内部重复输出目标、来源原句、交付位置和最长 500 字的完整解释。C 保留最多 8 项追踪，但采用短引和定位片语，服务器从实际来源及交付字段还原完整文本：

| 内部字段 | 拟定约束 | 验证 |
| --- | --- | --- |
| `purpose` | 研究对象／测量／干预／比较 | 按当前问题判断适用性；完整性仍由评价判断 |
| `sourceIds` | 最多 4 个实际可见来源 | 真实 ID，不增加模型不可见材料 |
| `sourceQuote` | 最多 96 字；背景解释可为空 | 在所列可见片段中逐字定位，歧义拒绝 |
| `artifactLocation` | 实际正文、备注或完整稿字段 | PPT 的辅助 unit 不能替代讲稿 |
| `artifactAnchor` | 最多 64 字的实际解释片语 | 在该字段唯一逐字定位；不能只在内部记录出现 |
| `gap` | 最多 80 字，或 null | 工作缺口留在记录；真实科学限制进入相应结论 |

删除重复 `goal` 和长篇 `explanation`；保留服务器计算的来源位置、交付位置、全文及哈希。追踪仍与交付在同一次模型生成完成，不新增规划角色。数值、单位、比较对象和修订前后稿继续使用已有共同追踪。

拟修改 `server/explanation-links.ts`、`server/internal-training.ts`、`server/skills.ts`、`server/orchestrator.ts`、`server/research-plans.ts`。快照显式记录合同版本及追踪模式，保留旧合同解释，不再仅凭周期编号选择 B。零调用回归覆盖虚构引文、定位歧义、非法路径、只写内部记录、丢失讲稿解释、缓存隔离及正常请求未加载候选。源文本保留内容与定位，不能用短引长度限制截掉实际讲解。

防御性写作检查延续已读 GitHub skill 的原则：先回答并解释，真实限制贴近结论说明一次；角色编号、核验进度和重复免责留在工作记录。不得靠删掉必要术语、机制或证据条件取得简短。

在线核对的提示、图件组包和阻断政策本周期保持固定。读图争议以保存的实际图像走查，旧误判不能硬编码为“这篇论文都应通过”。若新候选持续被误阻断，保留真实失败；后续单独选择核对输入变量，不把放宽核对和教学生成改动混为一次收益。

## 4. 逐阶段运行与精确预算

P0 通过后冻结 `iteration-c` 的新恢复协议、模型、代码、来源、候选、案例和评价。B 已知未完成，C 两侧重新生成；A／B 的旧稿只作诊断。六份评价校准只有在模型、评价指令、schema、样例输入及预定各维判断完全相同且原派发记录可核对时复用。通过 `reusedFrom` 追溯 A 的原记录，不把 B 的复用记录当成新派发。

| 阶段 | 单元 | 最大新调用 | 进入下一步的条件 |
| --- | --- | ---: | --- |
| P1 | 评价校准 | 6；严格复用时为 0 | 每份评价有效，各适用维度符合预定判断 |
| P2 | D1：六页 PPT＋逐页稿＋完整稿，两侧 | 10 | 候选正常交付成功；必要解释完整、事实及参照正确、图稿一致；C 通过全部适用项 |
| P3 | D2：论文讲解，两侧 | 14 | 有必要推理连接，事实与范围通过 |
| P3 | D3：同课题资源变化，两侧 | 10 | 调整对应设计，保留目标、历史和条件版本；正常交付通过 |
| P4 | H1／H2／H3 留出，两侧 | 14＋10＋6＝30 | 先有全部开发通过，再逐例运行；候选与评价保持冻结 |
| 合计 | 一个第三候选周期 | **70**；校准复用时为 64 | 不含学习试验 |

每批最多 24 次、45 分钟；实际模型请求串行。完整单元准入时间按各角色 180 秒上限之和加本地操作余量计算，不再用每调用 60 秒替代最坏时间。D1 上界约 30 分钟、D2／H1 约 42 分钟，分别加 2 分钟操作余量。新校准 6 次与 D1 合计最坏 48 分钟，必须拆批；校准复用也不能绕过单元准入。不能在期限临近时启动已知无法完整容纳的两侧比较。

拟在 `scripts/internal-training.ts` 增加独立校准阶段，并调整 `scripts/internal-training-batches.ts` 与 `server/internal-training.ts` 的时间准入。校准完成后再启动 D1；各批沿用同一协议、同一产物账本与已保存结果。新的恢复／校准入口尚未存在，实施时先补入口及回归，再执行正式比较。

每单元前检查在线队列、本机资源及余量；在线有用户任务则延后。每个正常任务最多一次自动修订。开发任一阻断失败就停止 C，留出不启动；留出出现失败就停止后续。超时、取消、未知派发或冻结变化结束当前运行，不自动重发。

上述质量门槛针对候选。基线的已确认失败按真实稿评价并保留交付状态，不要求先把基线修到通过；没有基线产物或结果未知时保留缺失，不当作已确认的候选优势。

C 即使花满 70 次，新增产物累计也为 22＋70＝92，包含旧历史后为 136；授权总额度仍余 118，但三个候选周期已满，不自动安排第四轮。

## 5. 科学质量、文件与成本验收

D1 必须核对实际讲稿中研究对象、相关测量、干预选择与对照作用；出现名词、合法引用或核对通过标记均不能替代准确解释。原文已提供的原理应进入交付，真实材料不足明确其影响。首稿／修订逐项核对参照、单位、方向、对象和证据边界。独立评价出现事实分歧时对照具体原图与原句，记录可确认和未确认项。

三类功能回归以 `ac23516` 的 171 项检查为工程起点。影响生成、修订、导出或取消的改动运行对应浏览器路径。成功 PPT 用 PowerPoint 原生渲染逐页查看图、轴、图例、裁剪和文字；备注及完整稿对照保存内容和实际文件。讲解与方案检查真实正文及其原有导出；失败稿和诊断恢复文件保持各自状态。

H1 的 Passos 自动路径已知无图件。本周期按文字证据评价并标注范围；H2 承担新论文原图与图稿检查。修复 H1 图像解析若会改变冻结材料，应另行冻结，不能运行后悄悄补图。

成本按角色报告调用、输入／输出／缓存 token、缺失用量、首次通过／修订、等待、provider 与端到端时间，以及训练进程 CPU／峰值内存。增加首个响应与输出活动信息以判断生成耗时。只有成功且必要解释完整的相同请求才能比较成本；用量或耗时增加超过 20% 触发具体收益复核。字符数不换算 token，取消缺失用量不填零，没有账单不估现金费用。

通过全部开发、留出、文件和工程检查后才允许有限启用 C；验证新请求确实加载对应合同与版本，原任务保留原版本。否则保留在线基线。回退使用新提交并核对未来请求，不重写历史。

## 6. 学习试验：产物验收后的独立阶段

保留现有三类目标与四条件：未学、仅材料、材料＋基线教学、材料＋候选教学。实际曝光、目标来源、图件及初始画像独立冻结；评分、目标答案和反馈不进入作答输入。失败教学分支保留未运行，实际图件缺失则按文字范围解释结果。

学习评价先安排最多 4 次预定正反例校准，再运行 3 类×4 条件×作答／评价两次＝24 次，总上界 **28 次**，在原独立 36 次额度内；余下 8 次不安排复测。拟在 `scripts/internal-learning.ts` 增加校准、分批与完整单元准入：校准单独批次，实际四条件比较分两批，每批最多 12 次，45 分钟。全部批次共享 28 次总账本和同一学习协议，每个作答＋评价单元预约 2 次；保留原始作答，不重复已完成分支或自动重发取消分支。

发布三类产物与模拟应用结论分别报告。单次模型模拟只能说明这些固定目标中的表现，真人理解与稳定迁移仍需另外验证。

## 7. 交付与实施顺序

实施顺序固定为：P0 记录／恢复与零调用回归 → C 合同和冻结 → 校准 → D1 → D2／D3 → 留出与真实文件 → 学习 → 发布或保留。

每阶段保存协议、实际输入、前后稿、评价依据、调用和停止原因；结论只覆盖实际运行范围。最后交付实施记录、成功真实文件及诊断文件清单、未解决项、剩余预算和发布／保留决定。在 `main` 审查差异、运行相应验证、只提交本轮改动；不推送、不改写 A／B 历史。

本方案的首个实施任务是 P0。恢复入口、精简合同、独立校准和分批预算现已实现；旧取消请求的终态尚未确认。工程验收不代表候选已经改善，真实 C 比较与学习效果仍待满足准入条件后检验。
