# 整体方案 v2.2：批判性优化与实施收敛

日期：2026-10-06 · 复查起点：72a6649（main）· 产品代码基线：3381558 · 对照：[v2.1 归档](科研能力培养与三类Agent协作_整体落地方案_v2.1归档.md) · 修订：[整体方案 v2.2 归档](科研能力培养与三类Agent协作_整体落地方案_v2.2归档.md)。当前以[整体方案 v2.3](科研能力培养与三类Agent协作_整体落地方案.md)和[整体贯通复查](科研能力培养与三类Agent协作_整体复查与优化记录.md)为准，本记录保留 v2.2 的检查范围和结果。

本轮按“再次批判地优化”的要求复查。主体＋研究方案／PPT 双专区、助手／小白／校验三类角色、内部双闭环和用户轻量使用继续保留；优化重点转向证据、归因、用户收益与实施负担。只更改方案和记录，不实施产品或运行模型实验。

## 1. 核心判断

v2.1 已把功能融入整体，但完整流程仍有“流程跑通就以为能力形成”的风险。角色历史、论文数量、修好一次稿子和一次高分均不足以证明能力提升；小白模型已有知识、新增材料和教学解释也可能混在一起。继续堆角色规则会提高成本，未必提高结论可信度。

v2.2 因此按具体能力和缺陷优化，以范围清楚的用户功能先交付，内部比较逐批扩大。成熟能力仍须训练／磨合和核验，但产品首次可用不等待完整长期学习平台。保留原 40 项需求，按本轮追加讨论加入 R41；共 41 项需求、11 项任务、58 项验收。T48–T54 对应七项优化，T55–T58 对应用户建议与数据使用研究；新规格不表示新功能已经实现。

## 3. 实施顺序与结论的变化

| 阶段 | 先做什么                                                       | 能报告什么                     |
| ---- | -------------------------------------------------------------- | ------------------------------ |
| 0    | 选能力／研究类型，材料与评价依据，模型探针、账本和校验最小校准 | 输入和评价是否具备条件         |
| 1    | 研究方案起步、理由／依据、轻量核对、编辑／保存、Markdown 导出  | 指定范围的生成服务与用户可用性 |
| 2    | PPT 与可选稿件、版本同步、真实渲染、代表性试讲                 | 制作与稿件质量、对应模拟诊断   |

| 4    | 校准且固定的单层候选比较、留出、必要回归与回滚                 | 有证据支持的规则改进及适用范围 |

实际使用与真人体验从前期可用阶段即可开始，不统一拖到阶段 5；判断真人学习收益需另有独立行为与条件记录。一次模拟成功、比赛展示成功或阶段完成都不关闭长期科学验证。研究方案与 PPT 的两条内部闭环保留，顺序收敛没有把训练能力的目标删掉。

## 4. 调用与证据代价

原 41／53、49／55 次示例保留为联合冒烟成本说明，不当首批必跑配置。只给材料对照每个目标任务的小白＋校验另 2 次；若给 55 次示例的两个开发目标各做基线／候选对照，新增 2×2×2＝8，共 63，剩 1；仍没有覆盖留出对照、全部校准或必要重复。不得把增加第三分支写成零成本。

首批改为明确单一能力范围、实际阶段清单和预约额度。需要更多证据就减少本批结论或安排明确后续批次，自动继续不绕过 64 次上限。教学、材料、模型和评价完全相同的历史对照可绑定复用，但不冒充新独立样本。

三分支只能改善指定模拟条件的归因，无法抹掉预训练知识、随机性、共同模型错误或替代真人。是否有足够重复、任务覆盖、独立专业判断及真实用户证据仍分别报告，不预先写成效果已证实。

## 5. 用户建议、自适应与训练用途研究

本轮新增要求是能不能依据用户语言／建议灵活变通，并把反馈用于训练。检查了现有 LearningIntent、本轮／聊天设置、server/assistant.ts 的主动反馈上下文与 server/compatible-provider.ts 的实际出站输入；已有有限适配基础，尚无完整跨聊天记忆和通用改进授权管线。

正文 8.1／8.2 已融入四层机制：本轮建议立即适配、聊天／课题明确偏好、可选跨聊天记忆、另行选择的通用反馈改进。Skill 与程度作为方法／默认值，用户可改变表达、例子、顺序与范围；事实、依据、独立权限和预算保持约束。满意度不等于迁移，用户纠错不直接变成科学真值；通用反馈经过原有助手／校验／小白与留出闭环才发布。

按大陆场景查阅官方[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)和[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)，法条与产品边界见正文 8.2。本方案选择两个独立、默认关闭的可选设置，并配套目的／范围／接收方、查看／删除／撤回和入库前权限检查；这是产品方案，不是仅靠开关保证合规。正常推理可能把当前输入交给模型提供方，训练关闭不能当作离线或零留存。

初期只做偏好、规则与案例优化，不实施权重微调；嵌入、摘要等有模型调用仍计账。T55–T58 与 F01／F02／F05／F06／F07 一并承接，内部与用户使用不混成同一数据池。
