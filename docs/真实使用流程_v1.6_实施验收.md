# 真实使用流程 v1.6：实施与验收

2026-10-08；实现起点 `29fba8f`，main，起点工作区干净。本轮接续[执行细则 v1.6](真实使用流程与前后端磨合_落地方案_v1.6.md)及[v1.5 累计约束](用户使用质量与自主迭代_落地方案_v1.5.md)。细则保留实施前冻结快照，当前状态以本记录、README 和主方案为准。

用户要求前端简单、实用、核心完备。本轮保留原框架、17px 正文、明暗主题、三核心入口与原阅读器；没有增加前台课程树、角色工作台、模型管理或复杂配置。两个开发子代理分别补前端使用检查、后端回归及文件验证，由根代理整合与提交；开发代理不替代产品角色或独立用户评价。

## 实际实现与入口

| 路径 | 已实施 | 验收边界 |
| --- | --- | --- |
| 主动导入 → 中文带读 | 导入 receipt、会话、论文版本共同绑定；无问题时起读；已有问题、汇报和焦点优先；历史加载不生成 | 首次可读单元，不是假装全文已读；无正文保留文件并说明需补原文 |
| 继续／深化／专题／总结 | 服务端绑定源全文哈希、摘录哈希、真实字符范围和 expectedReadingRevision；主线／专题位置、旧版本及成功轮次持久保存 | 正文按约2600字符分片，一次多讲最多3片；总结提供已覆盖范围最近6片，并明确未覆盖，不是任意长论文全文总结 |
| 回答 → 保存进度 | 必要来源核对、材料包范围验证和答案保存后，再在串行会话更新内检查版本并提交覆盖 | 失败／取消／旧版本冲突不推进；保存失败保留任务答案；重复请求不重发；存储返回值复制避免提前改内存 |
| 普通汇报 → 完整稿 | 默认勾选完整稿；用户可关闭；讲稿自然语言修改要求送入 speech.question | 仍走既有页面／稿生成、来源核对与导出；不强制小白角色每次运行，不冒充试讲效果 |
| 页和稿同时修改 | 先保存并核对所有未保存页面；按版本保留两份草稿，AI新结果默认可见，旧修改可显式恢复比较 | 页面变化不让旧稿自动取得新核对；讲稿不匹配仍需比较和保存；历史草稿不删除 |
| 课题 → 文献 → 完整方案 | 默认 full-plan，英文检索式模型调用有账；后端 PubMed ESearch／EFetch、Crossref DOI／题名核验，最多12节；条件可后补 | 默认最多25候选、读前10条、Crossref前6条；读取摘要／元数据，非全文、非穷尽检索；相关性和关键方法仍须判断 |
| 保存版 → DOCX | 从同一核对成功保存版确定性生成中文正文、可编辑表格、条件、设计理由、警告与公开参考链接；Markdown保留 | 导出零新增模型调用；未核对／失败／阻断稿不可绕过资格；最终分页尚未全部视觉复验 |
| 桌面阅读 | 答案宽度900px，原文栏上限560px且保留聊天宽度预算；拖栏保存去抖200ms；按论文＋会话保存滚动，新回答不抢旧位置 | 浏览器固定视口与主题检查通过；原生125%缩放、系统缩放及真人长阅读未作为通过结论 |

旧 JSON 新字段可缺省；新增阅读、外部文献与任务字段进入记录结构校验，异常记录继续隔离。旧失败 Guide 不被覆盖，无 requestKey 不重发；显式新 key 追加尝试，同 key 幂等。章节重新检索保留未修改章节的必要引用；新检索记录优先于旧书目快照，撤稿来源不能经旧来源回填复活。

检索工具只有固定 HTTPS 主机，禁止重定向；每次12秒、响应2MB上限、串行约400ms间隔，没有网络自动重试。网络失败与零结果分别保存；失败检索不假装生成有依据终稿。24小时缓存保留原读取时间，新请求各有独立记录。外部 evidenceId／PMID 与本地 paperId 分开，不给模型 shell、任意网页或 MCP 权限。

## DOCX文件验收

使用 documents 技能要求检查真实文件；本机 bundled runtime定位工具返回无效请求，未找到render_docx.py，因此实际替代为Microsoft Word COM→PDF→pdfjs-dist／canvas PNG，明确不声称使用打包渲染器。

确定性12节夹具含1张可编辑中文表格、1个公开书目超链接、中文和 `A<B`／`B>C`／`A&B`。修复前DOCX确由Word打开并成功导出4页，全部标题／文本／PDF链接保留；逐页发现表格行跨页拆开及参考条目与链接分离。已加入cantSplit和keepNext，并将引用独立成行防止落入最后表格格子。最终唯一重渲染尝试Word可打开，但90秒PDF转换无返回，未取得最终分页证据；按owned PID／start time／path清理，无遗留Word进程。

`scripts/verify-plan-docx.ts`只从新生成DOCX调用Word，不能用旧PDF冒充新布局通过；失败保存JSON并退出。旧4页PNG与旧DOCX哈希 `d7c5695ef7d60802871647944705e0be79466883fceb30acaae57f6c92ba1f10`继续作修复前证据。`runs/workflow-v16/docx/word-failure-report.json`是最后状态；`verification-report.json`和page-1至4对应旧布局。结构测试不等于最终分页通过，真实方案DOCX尚未逐页Word渲染。
