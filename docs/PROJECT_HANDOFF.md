# 医研导师：开发接续与证据底稿

更新日期：2026-10-11。代码审阅基线：`38dd1e0`，分支 `main`。

这份文件用于把用户需求、另一段开发对话、当前实现和验证记录对齐，供后续接手使用。它不是新的产品需求，也不是参赛终稿。历史对话中的执行命令不自动成为本轮授权。

## 1. 审阅范围与可信度

- 当前源码、现有项目文档、提交历史、测试、若干真实运行 JSON 和导出图像。
- 用户提供的开发对话约 38,138 行、2.60 MB：已做全文结构检索，提取并阅读主要对话与决策，按主题回查工具记录。没有把每行工具日志都独立重演。
- 本地归档 `runs/private-release-archive/internal-documents.zip`：需求访谈基线、需求落实清单、历史参赛材料。归档不属于公开源码交付。
- 本次接续审阅期间，在正确的 Node 环境下运行过 `npm run check`：TypeScript、Vite 构建通过，322 项测试通过；构建有大 chunk 提示。这不是全部浏览器脚本、付费模型流程或医学正确性验证。

采用三种表述：**代码存在**说明路径已实现；**有样本证据**说明特定条件下跑过；**仍需验证**说明不能外推。历史助手说“完成”不单独作为验收证据。用户后续明确决定优先于早期需求；源码决定当前行为，真实记录决定已验证范围。

## 2. 产品目的与不能丢失的设计

服务刚进入实验室、需要学会读论文和理解实验的医学生。主任务是讲清研究问题、为什么做实验、方法测量什么、对照如何设置、结果支持什么以及如何迁移研究思路。

用户不希望反复教 AI 怎样当老师。默认应先交代背景和价值，再沿论文推进；重要实验展开，必要基础补齐，允许追问与适度延伸，再回到主线。不是默认整篇翻译、完整实验操作 SOP 或大型课程管理系统。

对外有三条主线：论文带读、独立生成汇报 PPT、独立生成研究方案。PPT 和方案不要求先完成带读，界面应简洁、少追问、生成后可用外部工具编辑。

对内，后两者也是检验教学的任务：导师讲解后，模拟新手复述证据、组织汇报或提出设计；来源核验找出断点；导师补教；新手修正；再用改变条件的新任务检查迁移。因此不能把项目介绍缩减成“读论文加两个导出按钮”，也不能把“三份产物说法一致”当成教会或事实正确。

三个角色是导师、模拟新手、来源核验；修订属于导师职责。用户历史上要求减少多智能体开销，主要针对开发时分派子代理，不能据此删掉产品内部角色。

模拟新手的表现是迭代代理指标，不是对真人学习效果的证明。“已经讲过”也不等于用户掌握。

普通完整带读链：导师 → 新手试读 → 来源核验 → 必要时一次有界修订 → 新手复读 → 最终核验。某些基础问答只需导师，某些聚焦任务会减少新手阶段；不能把主链描述为所有请求的固定调用数。

研究方案有独立生成、核验和有界修订路径；它不天然等同于完整的新手补教与迁移实验。PPT 使用 PptxGenJS 输出可编辑元素，图件必须绑定真实材料，选定图缺失时不能静默伪造。

## 5. 是否绑定原生 Codex

| 路径 | 是否需要 Codex CLI | 当前含义 |
| --- | --- | --- |
| `codex` | 是 | 默认路径，走 CLI 的 ChatGPT 登录模式。 |
| `codex-configured` | 是 | 使用 CLI 已配置的提供方、模型和 API Key 认证；不能暗中退回另一认证方式。 |
| `compatible` | 否 | 服务端直接调用兼容的 `/chat/completions` 接口；地址、模型、密钥和图像/JSON 能力需匹配。 |

开发此项目用的 Codex，与用户运行这个应用的模型入口，是两件事。应用并非必须嵌入原生 Codex 桌面；也不能自动借用任意网页会员、其他平台订阅或第三方桌面应用登录态。

CLI 角色调用会限制工具、Shell、MCP、记忆等能力，结构化返回由宿主接收。搜索、文件处理、导出和调度主要由本项目后端实现。因此复制 Skill 文本不等于复制了完整产品。

`scripts/replay.ts`、`learner-check.ts`、`second-round-check.ts`、`deck-check.ts` 等旧脚本仍直接构造 Codex 提供方；部分新流程虽用统一提供方，但准入检查仍涉及 CLI。`assistant-check.ts` 已使用统一创建入口，不能沿用“它也全部写死”的旧结论。

历史首次安装反馈曾出现 `Codex process closed`。当前默认仍为 CLI，相关底层诊断信息不足；不能仅凭兼容接口存在就宣称安装引导问题已解决。也没有证据表明各国产模型都已实测兼容。

## 7. 54 项之外：内部迭代也必须交接

原访谈编号主要描述用户功能，不能用它替代内部机制核对。

- **来源隔离**：区分论文原文、背景补充、解释与假设；引用绑定身份与版本；跨产物材料合并要拒绝冲突。
- **交叉核验**：[cross-function-review](../server/cross-function-review.ts) 至少接收两类真实产物；[三产品门禁](../server/closure-product-gate.ts) 要求全部三类及实际导出文件。复核绑定指纹，改动后不能沿用旧“通过”。
- **独立学习任务**：[internal-learner](../server/internal-learner.ts) 包括证据复述、设计草稿、汇报提纲；区分未学、材料、材料加教学等暴露条件。提前给答案或评审提示的结果应算 assisted。
- **六阶段闭环**：补教、核对补教、修正、核对修正、迁移、核对迁移。各阶段持久化；流程完成和迁移通过是不同字段。
- **候选与上线隔离**：Skill 快照冻结；规则发布覆盖 reading/ppt/proposal/transfer 与 development/holdout，记录基线和候选证据。已检查的数据位置未发现活动发布指针，不能声称已有完整晋级实绩。
- **费用与中断**：有调用账本、预算、未知用量及恢复状态；只对符合条件且确认失败的传输请求有界重试，不把超时/取消/未知结果全部自动重发。
- **并发准入**：默认任务并发为 2，同会话串行；训练准入默认检查本机 4317，可配置。历史“4317、4319 都空闲再跑”不等于代码默认检查两者，更不能探知远端共享账户全部并发。
- **可重复性限制**：部分历史活动配置依赖未公开的本地材料与记录。公开源码不含完整训练数据，不能宣传一键复现全部实验。

### 产品变化要连起来理解

最早的四个模块是 paper、method、figure、ppt；后来的三条用户主线是带读、PPT、研究方案。两组数量描述不同层次，不是删掉了方法与读图。方案使用独立服务和 Skill；方法与读图仍包含在带读、追问及组合任务里。

早期个人学习记录、课题目录、逐页编辑、完整演讲稿、候选比较入口都有实现或规划。后来的取舍是简化主界面，保留旧记录和有用底层能力。因此“代码中找得到”不代表“用户默认应看到”，旧方案中的每个未完功能也不是当前必须补齐的待办。

最初用户自述是刚进课题组的本科生，后期参赛描述扩大到医学本科各年级及研一科研初学者。这个范围表示目标用户，不是已经对这些年级开展真人试验。

### 教学偏好与三种学习状态

- `LearningIntent` 将**展开程度**（简洁/常规/深入）、**重点**（综合/基础/研究思路/方法图表/机制）、**目标**（理解/迁移/讨论课题/汇报）分开，并绑定论文、来源、选区和产物版本。它比旧 `depth` 字段更完整，旧字段保留兼容转换。
- 自然语言偏好识别有具体规则；“以后”与局部“这段”影响保存范围。不能把规则匹配描述成对任意表达都可靠的语义记忆。
- 用户主动反馈、已讲概念、模拟学习者作答是三类不同证据。收藏或“继续”不自动变成理解反馈；反馈也不自动训练模型。
- 早期 [learner](../server/learner.ts) 是带概念状态、可见讲解、选项作答和本地评分的模拟环境。未知概念即使蒙对，也不能升级为已掌握；有依据的正确表现记录为 `observed`。
- 后来的 [internal-learner](../server/internal-learner.ts) 承接开放复述、设计与汇报任务；[learning-loop](../server/learning-loop.ts) 明确辅助纠正与独立迁移。两代机制并存，不能把选择题成绩称为完整开放迁移。

### 材料、草稿与恢复

- PDF 导入独立限 30 MiB；聊天附件最多 4 个，单图 8 MiB、合计 40 MiB，支持 PNG/JPEG，并限制一次发送中的 PDF 数量。原始图片与模型缩小图分开保存。
- 浏览器文本/生成参数和待查询请求使用 localStorage，附件草稿使用 IndexedDB；后端 JSON 保存正式材料与任务。仅备份后端目录未必包含尚未提交的浏览器草稿。
- 图片检查区分可用、用途不明、无关、不可读和失败，可针对单图处理。上传截图来源标为 interpretation，不因上传而获得论文页码或核验身份。
- 导入请求身份、会话消息身份、方案 requestKey 用于避免重复提交；相同身份对应不同内容会被拒绝。刷新后查询旧任务，与重新发起一轮生成不同。
- 在线允许交付带少量外围问题的结果，但 [ResultCache](../server/cache.ts) 更严格：完成且有核验、无未解决核验问题、资料请求或新手断点才缓存。可交付不等于下次一定零调用命中缓存。

### 联网和模型运行细节

- “联网”由后端受控检索执行，当前主接口是 PubMed 与 Crossref，并非允许模型任意浏览网页。背景检索先经意图规则及一次计费模型决策；当前材料足够时可不搜索。
- 检索报告记录摘要/元数据层级、查询、请求、时间、排除项与复用。当前代码取 PubMed 前 25 条候选、读取前 10 条，并有撤稿与去重处理；带读补充最多取 3 项。题录核对不是逐篇科学审阅。
- `.env` 不由应用自动读取；独立接口启动要用 Node 的 `--env-file`。`model:check` 默认配置检查，显式生成探针才证明实际调用能力。
- 兼容接口当前使用非流式请求、纯 JSON 返回和本地 schema 校验，拒绝工具调用与不完整结果；图像能力必须明确配置。结构兼容还涉及 `response_format`、输出上限等参数，不能只改一个模型名就宣布迁移完成。
- 取消本地请求、收到 interrupt 确认、远端终态、实际用量是不同事件。早期曾尝试收到完整文本即收口，后续因丢失终态证据撤回；接手时不能重新引入这种“提速”。
- 期限按任务区分：普通讲解、局部诊断、长产物有不同总期限、单请求期限、首输出和停顿期限；只有实际输出增长算进展。历史“180 秒”不能套到当前所有任务。

### “迭代”和“发布”的精确含义

这里的训练主要是修改 Skill、提示词、材料组织与协作执行，不是底层模型权重微调。候选保存、候选实验通过、规则正式采用、源码中的规则直接更新也不同。

规则读取优先级由 [skills.ts](../server/skills.ts) 确定：当前内部实验快照 → 已采用的活动规则快照 → 仓库 Skill 文件。未发现正式发布指针，并不意味着在线仍使用项目第一天的提示词；直接提交过的 Skill 改动可通过文件读取生效。反过来，`decideRevision(keep)` 只保存 `reviewed-candidate`，不自动修改活动指针。

归档进一步说明了今天机制的来历：首周期 28 次尝试（27 返回、1 未知）未完成全部产物比较；第二周期 16 次返回，候选新增归一化错误，仍未发布。随后 A/B 合计新增 22 次（21 返回、1 取消），A 遗漏已提供的必要原理，B 比较因取消不完整。这些属于早期独立时间段，不能再与第 9 节后续活动数字直接相加冒充统一总量。

这些失败推动了来源原句与交付字段绑定、修订前后事实变化追踪、实际曝光隔离、预算继承、完整单元预留、渲染验收和取消恢复。它们解释了为何当前实现不只是几段角色提示词。上述早期数量本轮依据归档报告读取，未再次重放模型或逐个重算原始账本。

在线审核对少量透明资料缺口有特例，当前部分识别依赖类型和文字规则；正式内部验收还要求新手断点与事实/范围条件。应按各条实际代码路径判断，不能把“宽松”或“严格”当成全项目统一阈值。

### 原创设计、借鉴与当前接续方式

历史参考过 TinyTroupe、LangGraph、DSPy/GEPA、promptfoo 和若干写作/界面 Skill 的设计方法；参考记录不等于安装或集成这些框架。当前核心编排是本项目 TypeScript 实现。实际使用的依赖、字体、PDF 样式与许可证另有明确记录，不能把必要第三方归属删除，也不应把整个原创设计说成复制现成项目。

后续可以从用户目标、功能取舍、技术路径、真实案例、已知问题和最新阶段直接继续，正常实现选择由执行者承担。只有新需求改变方向或涉及材料中没有的信息时才补问；不要求用户重做需求访谈，也不因读到旧自动接续提示而启动历史训练或自动发送外部消息。
