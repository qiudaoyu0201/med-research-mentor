# UI 桌面质感精修方案（2026-10-28）

## 范围

- 工作区为 `D:/智能体-ui`，分支为 `codex/ui`。保留左侧列表、右侧任务区以及全部功能、任务流程和数据接口。
- 用户截图是审美基准：中性银灰、白色工作区、克制的蓝色、紧凑清楚的桌面控件。不迁移棋盘、木色、宣传图外部投影或无依据的玻璃效果。
- CodeEdit、妙言辅助研究桌面布局与阅读层级；React Aria、Radix 辅助核对键盘与焦点行为。不引入依赖、不复制其他产品的结构或品牌。

## 实施

1. **视觉基础**：偏冷蓝灰改为中性灰阶；明确工作区、分组背景、输入区与工具栏的层次。紧凑控件采用细边、近距离阴影与轻微明暗变化，避免所有元素都浮成卡片。
2. **比例与文字**：整理标题层级和重复文案；界面控件与长文阅读采用不同密度。统一按钮基线、图标视觉重量和同组控件间距，不机械缩小所有文字。
3. **方案与 PPT**：去掉包裹整个表单的大白卡片，改成有明确标题、局部分组和底部操作区的任务表面；论文导入与选择归为一组；补充要求不再撑起失衡的双栏；保留全部字段、页数选项与生成行为。
4. **导航与带读**：收紧品牌区、搜索、分组与列表的节奏；优化选中态、工具栏图标、空态、资料面板和输入区，区分内容与辅助工具，不为填满空白增加功能。
5. **设置与浮层**：逐项卡片改成有语义标题的连续设置组；明确即时生效项和需要保存的默认偏好，保持保存行为不变。统一菜单、管理弹窗、关闭按钮、焦点与禁用状态。
6. **状态适配**：同一套语义变量适配深色，检查悬停、按下、焦点、选中、错误、加载、禁用和减少动态效果偏好。

## 验收

- 桌面至少检查 1440×900、1280×800 和 1024×768；覆盖主要任务页、论文资料面板、菜单、设置与管理弹窗，窄桌面无横向溢出。
- 视觉验收关注模块重量、字段宽高、文字基线、按钮分组、边界和状态，不以测试通过代替观感验收。
- 使用隔离的临时预览数据；不读取或覆盖真实用户资料，不触发模型生成。
- 使用锁文件安装依赖，运行 `npm run check`、格式与差异检查；浏览器回归焦点、Escape、菜单方向键、表单启禁和浅深色。
- 审查并仅提交本任务文件到 `codex/ui`，报告提交哈希与预览入口；不推送、不合并、不动功能迭代工作区。
