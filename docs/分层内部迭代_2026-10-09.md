# 小样本与整篇论文配合的内部迭代

用户本轮授权开始内部迭代，并再次明确小样本与整篇论文配合以提高效率。沿用三角色教学、模拟新手、来源核对及一次修订后的复读与复核。开发阶段不用额外开发子代理代替智能体自身角色。

## 分层与准入

1. **局部诊断**：每例一个完整问题、方法或实验的证据链。按需要同时提供方法、对照、结果、图注与原图，来源可跨页；页数少不是唯一目标。材料不够时标明是取样缺陷还是原论文确实缺失，不能把前者当作模型能力不足。
2. **候选窄修**：只针对已观察的错误更新隔离候选。保留首稿、反馈、修订和复核，核查新增错误。局部成功后测一个相关但不同的开发片段，不把背熟失败案例当作泛化。
3. **整篇整合**：局部候选稳定后，验证连续阅读的背景、方法、结果、总结与原文位置，以及整篇汇报的证据组织。整篇输入实际会受材料包长度约束，必须记录模型实际可见范围；不能用导入全文等同模型已读全文。
4. **三功能交叉**：以当前真实带读、PPT、研究方案版本对照原文核查。修订使旧交叉验收失效，不能让三个产物彼此一致替代原始证据。PPTX和独立讲述提示、方案DOCX按实际文件验收。
5. **留出与采用**：使用没有参与本轮改规则的案例；开发失败样本不是留出。合格前保留线上规则。模拟新手通过不等同真人学习效果，不跳过现有发布准入。

局部检查每项最多一次自动修订，结果未知停止本批后续调用；有明确失败原因才开启新的冻结候选，不重复整篇碰运气。不为用完预算而跑满轮数。内部严格；在线可容忍少量非关键缺口，重大事实错误及大量缺口仍阻断。

## 本轮起步批次

入口：`scripts/development-regression.ts`。固定目录 `runs/internal-training/development-20261009`，独占训练锁与不可覆盖的启动声明；最多12次新调用，两项各预留6次。使用当前 klapi / gpt-5.6-sol 配置，无自动回退。

- 第1项：Hewitt论文第1–2页，背景到第一个实验的局部带读。此项用于诊断当前分页材料和解释边界，不代表完整实验图像验收。
- 第2项：同篇论文六页组会汇报，提供全篇可选来源，由现有材料包选择实际可见摘录；独立讲述提示不进幻灯片正文。用于检验整体压缩和修订是否混淆组织、组别、统计量。

运行前冻结规则、论文、历史报告文件哈希和去重的可见历史调用；只读核查旧未知请求。已不可读的临时线程仍保留未知，不改作零成本或成功，也不重发。可见历史调用数仅为已扫描账本的下界，不能当作整个项目完整账单。

本批是现有规则的真实开发诊断，不是候选优于基线的对比证明。即使TaskRun为completed，仍检查未解决来源问题及新手断点；不把部分内容保留算作整份验收通过。

### 不能机械采用的反馈

PPT初核曾把研究问题的疑问句当作确定结论，列为blocking。最终修订通过不代表该初核判定合理。审核优化应区分“提出问题”“转述作者主张”“基于数据下结论”，保留严格事实门槛，减少对未声称的结论提出反证要求。该观察先记录，未直接降低线上阈值。

下一候选优先验证三点：修订保持组织/组别/时间/指标/统计量绑定；测量读数与实际生物过程不混同；审核不把研究问题当事实断言。先用完整局部证据链检验，再进行整篇整合。此批没有改动或发布在线Skill，没有执行研究方案、三功能交叉复核、留出或真人验证，不能报为整体训练完成。

工程验证：TypeScript检查和内部训练/预算/在线交付相关10项测试通过；新增严格验收测试检查“completed但缺复读、未解决warning、新手仍困惑、PPT缺产物”均不能通过。
