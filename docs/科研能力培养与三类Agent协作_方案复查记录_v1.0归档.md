## 3. 成稿后发现并修订的细节

### 3.1 防止阶段名称被误算为额外 Agent

现有代码同时出现规划、教学、试读、学习模拟和核对名称。复查后补充这些阶段到三类角色的映射，避免实施时再次扩成“主助手＋导师＋若干小白＋校验”。对应方案第 6 节。

### 3.2 完整论文背景不能被局部示例代替

初稿强调可见内容与相关学习单元，但对“读完整篇论文背景下的汇报”覆盖还不够明确。已补充整篇研究路线学习历史、材料覆盖和关键衔接行为检查，并加强 T11；局部 Figure 案例继续保留，但不得当作完整论文汇报验收。对应第 7.2、9 节。

### 3.3 材料补充不能形成自动无界循环

教学流程图原先从材料缺口直接连回输入，可能被实现为无条件重试。已明确只有用户补充后以新轮继续，仍保留原任务关联和累计成本；自动修订保持一次上限。对应第 8、11.2 节。

### 3.4 PPT 新追问必须额外计账

完整 PPT 首轮四次／修订后八次的计算，依赖讲述与一个公开问题合并在同一次小白任务。已明确校验听完后另提问题、再让小白回答时增加调用；学习准备和独立评价也计入批次。对应第 9.1、11.2 节。

### 3.5 让共同能力目标有可理解示例

初稿的合同和表格较多，可能看不出教学、迁移和 PPT 怎样围绕一个能力配合。已增加“两种测量交叉支持”的教学设定，展示小白误解、专业校验、修订、迁移和汇报的连续关系，明确它不是论文实证。对应第 6.3 节。

## 4. 一致性与偏差检查

- **在线预算与完整 PPT：** 在线三阶段，首轮三次、修订最多六次，必要规划总上限七次；后台双条件首轮四次、完整修订最多八次，额外准备／追问／评价计入后台总上限。两种预算没有混用。
- **模拟与真实能力：** 小白表现用于系统诊断，用户能力依据实际行为；未教知识越界不能作为教学成功，真人试用仍待开展。
- **全面目标与截止前演示：** F01–F09 保留完整目标；时间安排为目标日期，演示范围取决于实际验证，未完成部分继续列待办。
- **后台自动化与评价可信度：** 可以自动提出和比较候选，不能改变事实答案、判定标准或直接自改生产版本；发布经过固定条件与版本程序。
- **前端简洁与后端专业：** 内部角色信息留在开发侧，用户仍看得到影响判断的材料不足和结论边界；两组设置不增加常驻复杂面板。
- **讲解程度与学习重点：** 五个旧值有兼容映射，三类角色共享新意图；研究思路是待新增的重点，机制不能代替研究设计。
- **历史失败与新样本：** Figure 1m 分母及引用缺口继续保留，简单 PPT 通过和高清原件不能覆盖旧内容／视觉问题。
- **模型与比赛路线：** 当前仍用 Codex；国内适配待实现并在目标模型重验。Skill 优化不称为模型权重训练，后端隐藏不代表豁免要求。

按现有讨论和本次核对范围，未发现需要从整体方案删除的核心需求；上述新增细节已回写正文。仍需实施与验证的部分列在方案第 3、14、15、17 节。
