## 用户可用路径

主导航并列显示论文研究、研究方案、PPT 汇报。方案可以只输入医学问题创建，不要求 PDF；逐步添加对象、资源、限制及最多 12 个已有来源片段。研究类型支持四类、暂定／确认／未知及复合设计，由用户确认，未宣称完成可靠的自动语义分类。首次创建带入当前聊天的讲解偏好；选段／问题可明确带入，之后方案设置单独保存。

起草按方向框架、设计草案或较完整方案取舍，保留设计理由、条件假设、最多三个关键问题及待核范围。当前建议进入独立请求区，来源仍作为资料。首轮助手＋一次轻量核对为两次调用；阻断问题允许一次修订与复核，整个根任务最多四次。用户主动只核对保存稿使用一次调用，不自动改写手稿。问题未解决时仍显示问题与范围，保存和 Markdown 导出不受内部评分阻断。

每节可编辑标题、正文、理由和事实类别。手动保存追加版本，保留未变章节的作者，改动章节记用户或共同修改；当前是受助制作路径，未提供独立迁移证明。历史恢复追加新版本，恢复历史条件但不复制旧核对。导出绑定选定保存版本，包含条件、来源原位置／实际片段、参与方式、假设与实际核对状态。当前只开放 Markdown，DOCX／PDF 未新增入口。

内容及条件草稿按方案保存在本机浏览器，刷新与切换专区可恢复。版本冲突保留本机手稿、最新保存稿及可查看的手稿副本；旧条件下的生成结果保留为候选，不覆盖新稿。归档阻止新生成；删除方案清除其保存版本、来源副本和任务记录，原论文／聊天仍保留。内部模式、候选清单或伪造核对状态不能通过请求字段注入。

## 合同、持久化与失败行为

`shared/research-plan.ts` 定义 SourceRef、TaskContextV2、ResearchTaskInput、Topic、PlanVersion、Job 和 Review。采用独立的 `schemaVersion=2 / module=research-plan` 判别合同，不将方案强转成旧 TaskInput，不虚构 paperId。来源正文／定位／版本由后端从真实论文解析，重复 sourceId 用完整身份区分；没有 PDF 时学习意图的单论文字段为空。方案与任务使用新的存储组，不重写旧聊天和 PPT 文件。

任务开始固定模型标识／配置指纹、规则正文及哈希，形成 `medical-plan-initial` 的不可变任务快照，范围为工程预览。未发布多论文案例包、自动规则升级或成熟教学能力。默认模型继续用已有 Codex 接入；国内接口沿用配置，未声称实测通过。

与主聊天／PPT 共用两个调度槽，按方案串行模型任务；提交与写入使用短锁和版本校验，模型运行期间允许保存及更新条件。调用发出前保存预占账本，草稿先保存，再核对；未知调用不自动重发。请求键绑定摘要，同键同请求返回原任务，同键不同输入为 409。条件及内容有预期版本，来源在任务前、阶段间和落库前重查。失败、停止和冲突不写通过，调用用量和根截止保持。

重启将未终结任务标中断、预占未确认标未知；已保存草稿仍可读。草稿提交与任务写入之间的崩溃窗口可从 jobId 重新定位。仅已保存、依赖有效、没有未知调用且原预算／期限足够的核对阶段可显式恢复；超额或过期时可对保存版本明确发起新核对。UI 显示本次及方案累计调用，自动修订不更换根账本。核对报告有独立 ID 并保留任务历史，新内容不继承旧通过。
