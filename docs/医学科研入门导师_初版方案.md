# 医学科研入门导师：初版实施方案

版本：v0.3 · 日期：2026-10-04 · 状态：讨论结果已整理为实施方案，程序尚未开始搭建

本版调整：模拟新手纳入初版；补全任务内修订与跨案例改进两层闭环、三个角色的提示词约定、skill 独立使用与组合方式；补充教学、科研核对、前端及评估工具的 GitHub 参考和来源记录办法。

本文件用于确定本地 demo 的制作范围与实施顺序。它不是已经完成的功能说明，也不是参赛申报书。论文资料包、模型接入、教学规则和界面均需在后续实施中验证。

## 1. 一页看懂我们要做什么

做一个可以在 Windows 笔记本上启动、通过浏览器使用的医学科研学习工具。学生上传论文或打开示例，选择带读、方法讲解、图表解读或汇报 PPT；导师补足基础知识，解释实验如何支持结论，学生可以随时追问。

核心价值是帮助医学科研新手理解科研过程，并产出自己能够解释的汇报材料。讲解要细，但通过分段、展开和追问控制阅读负担。

| 项目 | 初版决定 |
| --- | --- |
| 暂定名称 | 医学科研入门导师；名称可在试用后调整 |
| 面向人群 | 刚进入实验室的医学生、科研入门的医学研究生；长期兼顾基础医学与临床研究 |
| 首个演示场景 | 以一篇基础医学研究论文，展示术语、方法、图表与证据链教学 |
| 使用方式 | 本机网页，一名使用者，一次运行一个学习任务 |
| 模型优先项 | 用户现有账号可用的 GPT-6.1 Sol；接入方式先验证 |
| 前端风格 | Apple／iOS 的简洁视觉和清楚的交互层级，适配桌面阅读 |
| 核心功能 | 论文带读、方法讲解、图表解读、基础汇报 PPT |
| 协作方式 | 教学、模拟新手、核对三个 agent 分工，同一模型可承担三个角色 |
| 改进方式 | 保存基线→定位失败案例→修改一个 skill→回放与检查退步→保留或撤回；初版不做模型权重训练 |
| 当前交付 | 详细方案文档 |
| 后续初版交付 | 可运行程序、源码、示例资料、启动说明和已知问题说明 |

用户已经确定：先完成初版；由开发侧选择代表性论文；使用完整性由开发侧设计；上线部署、参赛视频与申报材料以后再安排。本次不实施模型连接、购买服务或部署。

### 1.1 后续制作时核对的需求基线

详细讲解与理解推理是产品核心；不能为了省事把产品改成快速生成科研成品的工具。基础医学与临床研究都在目标人群内，首个示例先从基础医学开始。学生可只学一个方法、只看图或只做 PPT，不强制按课程顺序使用。

模拟新手是初版协作角色，不能移到“以后再做”；反复改进包含跨案例的规则更新与检查，不能只保留一次回答的修改。多 agent 的组成服务于教学和核对，不预设固定课堂或苏格拉底教法。GitHub 参考用于减少从零试错，具体迁移由开发侧给出默认方案，真实新手与老师之后反馈调整。

交付先是本地参赛 demo，前端采用可修改的 Apple／iOS 简洁风格；优先核验用户现有模型账号，接入情况与额外付费如实说明。用户无需先学会智能体搭建，也无需事先设计完整教学评估。改变这些需求时须明确记录原因，不能在实现中悄悄删掉。

## 2. 定位与范围

### 2.1 解决用户已经遇到的五类困难

| 困难 | 初版对应行为 |
| --- | --- |
| 不理解术语 | 首次出现时给出中文解释，保留英文；解释它在当前研究中有什么用 |
| 只知道 PCR、流式等方法的名字 | 从研究问题、原理、测量对象讲到结果含义，区分基础原理和论文具体做法 |
| 看图很慢，不熟悉图形类型 | 先认坐标、分组、单位与图注，再比较结果，最后解释含义 |
| 实验与结论之间接不上 | 显式展开“改变了什么→测了什么→观察到了什么→能支持什么→还有什么解释” |
| 熟练者的讲解跳步 | 检查前置知识，补足理解当前段落所需的基础；不默认学生已懂缩写和方法 |

### 2.2 初版能力边界

初版优先验证“适合医学科研新手的讲解与汇报”。实验方法模块可以独立学习，不要求先读完论文；PPT 也可直接生成，不设置测验门槛。

暂不展开自动设计完整实验方案、自动发掘创新选题、自动写整篇论文、执行实验、分析真实患者数据库或修改仪器参数。以后可通过模块接入更专门的工具。

产品定位同时包含基础医学和临床研究；首篇基础医学示例不等于两个方向都已验证。临床论文需后续用第二篇材料检验研究设计、混杂因素、结局指标等教学模板。初版不要宣称覆盖所有医学学科。

## 3. 示例论文选择与资料准备

### 3.1 首选论文

**Xu M, et al. Senolytics improve physical function and increase lifespan in old age. Nature Medicine. 2018;24:1246–1256.**

- DOI：`10.1038/s41591-018-0092-9`
- PMID：`29988130`
- PMCID：`PMC6082705`
- [出版社题录、摘要与图标题](https://www.nature.com/articles/s41591-018-0092-9)
- [PMC 作者稿入口](https://pmc.ncbi.nlm.nih.gov/articles/PMC6082705/)

它围绕细胞衰老，通过移植和清除细胞等研究路径考察小鼠身体功能，包含人体组织离体研究。题材适合展示对照、干预、表型和结论边界之间的关系。这里的选择是教学适配判断，不代表该论文是所有医学新手的最佳教材。

第一条带读路线聚焦 Figure 1 的实验与功能结果，再联系 Figure 5 的干预验证；Figure 6 用于进一步练习图表与结论边界。图号与图标题已对照出版社页面。具体子图、分组、方法与数值，在获取全文和图注后核验再写入示例。

### 3.2 为什么选它，以及它覆盖不了什么

选择理由：医学问题容易用普通语言引入；实验推进有可解释的顺序；既有方法与结果，也能练习证据范围。先读局部，不要求学生第一次就理解整篇复杂研究。

它不是临床随机试验，也不能用于证明系统已覆盖流式、火山图、全部组学或全部统计方法。方法模块可另有基础课程，但必须标明“基础知识”，不能把不属于本篇的实验或图形说成本篇内容。

### 3.3 本次核验程度与后续资料门槛

本次已核对题录、出版社摘要和主图标题；PMC 入口存在，但本次直接访问遇到网页验证，尚未下载和整理完整资料。不能据此宣称已读完全文、已解析所有图件或已准备好教学样例。

实施时先准备一个小而可核验的资料包：

1. 合法获取的作者稿或用户可使用的 PDF，注明版本。
2. 正文段落、所选主图、完整图注与对应方法段落。
3. 书目信息、PDF 真实页码、图号／子图号与内容位置。
4. 对所选教学单元列出已核对事实和未核对事项。

如果全文仍不可取得，保留选题说明，但不进入“完整论文带读”验收；改用另一篇能取得可靠全文的基础医学论文，并更新本节。不要用摘要补造方法、子图或数据。资料取得不是要求用户先做教学评估，而是保证程序有内容可读。

## 4. 初版四个功能入口

### 4.1 论文带读

输入：示例论文或用户上传的文本型 PDF。学生可选择段落、图号或“从研究问题开始”。

一次输出一个学习单元：这段在回答什么、必要术语、方法为什么合适、结果是什么、结论推导与限制、原文位置。随后提供“从基础讲起”“换个例子”“为什么能推出这个结论”“下一步”以及自由输入。

默认详细讲解必要知识；进一步延伸内容可以展开。学生可跳过熟悉内容、直接看指定图、返回上一单元。首次使用不安排冗长知识测评。

### 4.2 实验方法讲解

可以从论文中的方法打开，也可以独立进入。首版基础条目优先 PCR／qPCR 和流式细胞术；论文特定方法随资料核验结果加入。

每个条目按同一顺序组织：

1. 用来回答什么问题。
2. 原理与理解原理所需的最低基础。
3. 实际测到的是什么，结果通常怎样呈现。
4. 需要什么对照，为什么。
5. 结果可以解释什么、不能单独证明什么。
6. 本文具体怎么用；未在当前论文出现时明确说明。

基础知识要有可信教材、标准方法或原始资料支撑。初版教学重点是理解与读论文；实验操作参数不从一般知识自动补成本文事实。

### 4.3 图表解读

输入：选中的论文图件／子图及图注；上传 PDF 无法自动正确识别图件时，允许选择页和手动圈定区域。

阅读顺序：图形类型→坐标与单位→分组与样本单位→误差线和统计标记→实际观察→结论与边界。先解释“怎么看”，再解释“本图说明什么”。

基础图库优先覆盖柱形／散点图、箱线图、生存曲线、火山图和流式图；其中没有可靠样例的类型不宣称已验证。独立教学示意图必须标注为示意，不能混入论文原图。

如图不清晰、图注缺失或模型看不出标记，说明具体缺什么，再让用户放大、圈定或补文本。不能凭印象猜分组名称和数值。

### 4.4 基础汇报 PPT

可直接使用，不要求完成带读。先显示可编辑大纲，用户可调整页数和顺序，再生成 PPTX。

默认 8 页：标题与来源、研究问题、必要基础、研究路径、关键结果一、关键结果二、结论与局限、汇报小结。按实际证据增减内容，不能为凑页数发明结果。

初版要求：中文文本可编辑、原图保留出处、术语前后一致、备注包含新手讲稿和必要解释。原始科研图作为图片嵌入，不承诺拆成可编辑曲线或图内文字。缺少图片时只生成有来源的文字与图件占位说明，不伪造论文图。

PPT 属于学习输出，内容仍沿用核对后的证据；布局采用稳定模板。生成后检查缺图、溢出、来源、备注及基本可打开性，不追求首版覆盖所有答辩与投稿格式。

## 5. 教学规则与质量基线

### 5.1 “讲得细”的具体含义

不是只增加字数，而是补足推理步骤和前置知识。第一层直接解释当前疑问；第二层展开必要原理；第三层提供可选延伸。层级用于组织阅读，不限制学生深度。

每个学习单元默认遵循：

> 研究问题 → 必要概念 → 方法与对照 → 观察结果 → 推理过程 → 结论范围。

术语采用“中文名（英文名／缩写）＋一句话解释＋在这里的作用”。类比只辅助理解，随后回到真实机制并说明类比的适用范围。

学生表示“还是不懂”时，不原样重复长答案：判断卡在术语、原理、读图还是推理；换例子或缩小到一个步骤，再继续。不能凭学生点了“下一步”就记录为已经掌握。

### 5.2 信息分清三种来源

| 内容类别 | 展示与处理 |
| --- | --- |
| 论文事实 | 指向段落、页码或图件；数字必须能定位 |
| 补充基础知识 | 标明教材／方法资料来源，或注明尚待核验 |
| 系统解释与推断 | 明确是帮助理解的解释或待验证假设，不写成原文事实 |

没有可靠 PDF 页码时使用段落或图号引用；不补假页码。输出里的依据按钮应能打开本机原文位置，而不只是给一串链接。

### 5.3 教学验收看什么

首先看是否真实解决用户的五类困难，再检查事实与出处。不把一次阅读后的自我感觉或 agent 评分直接作为“学习效果已证明”。老师的反馈可在 demo 出来以后补充；不作为开始制作的前提。

## 6. 多 agent 配合与改进闭环

### 6.1 初版配置

| 角色 | 职责 | 初版实现 |
| --- | --- | --- |
| 流程控制器 | 选 skill、取原文、保存状态、控制次数、处理取消 | 程序逻辑，默认不消耗一次额外模型请求 |
| 教学 agent | 按学生问题和教学规则生成讲解／汇报内容 | GPT-6.1 Sol 的独立角色会话 |
| 模拟新手 agent | 根据预设知识水平试读讲解，指出理解断点，修订后再试读 | 同一模型的独立角色会话；一次任务默认一个新手画像 |
| 核对 agent | 对照原文检查事实、证据范围，并判断模拟新手的反馈是否具体合理 | 同一模型的独立角色会话，以后可以更换模型 |

三个 agent 有各自的任务、输入与输出；由控制器传递结构化结果。模拟新手进入初版的教学协作流程，帮助发现熟练模型容易省略的步骤。角色配置不要求固定课堂结构；讲授、示范、提问都可采用，苏格拉底式问答和强制测验不设为默认。

### 6.2 一次回答的闭环

```text
用户选内容或提问
        ↓
控制器取出有关原文、图注、方法与 skill
        ↓
教学 agent 生成讲解草稿和引用
        ↓
模拟新手按知识画像试读，指出不懂的位置和原因
        ↓
核对 agent 对照原文，检查事实与反馈，给出具体问题
        ↓
通过 → 展示；有问题 → 教学 agent 修改一次
        ↓
修改后 → 同一模拟新手复读 → 核对 agent 最终检查
        ↓
本地检查引用位置与输出结构，保存最终版本
```

没有修改时为三次模型调用：讲解、试读、核对。有修改时再增加修改、复读、最终核对，默认一次任务最多六次生成调用、一次修订。输出格式纠正也占本任务的调用预算；预算耗尽时说明未完成事项，不能额外无限生成。网络失败或响应状态不明确时保留任务并提示，不能盲目重发可能已计费的请求。

论文带读、方法与图表讲解默认走这个流程；直接制作 PPT 时，对讲稿和基础解释进行一次整体试读与核对，不对每张幻灯片单独重复整条流程。读取 PDF、保存记录和将已确认内容导出文件不调用模拟新手。

核对 agent 必须拿到相关原始资料，不能只看教学 agent 的摘要。输出包括：问题位置、问题类型、原文依据、建议修改。核对范围是本次取得的材料，不宣称审查了所有文献。

页面状态用“正在讲解”“正在检查理解步骤”“正在对照论文”“正在修订”“正在复查”。试读与核对详情默认折叠，只展示可追溯的问题与修改记录；不展示模型隐藏思考过程。草稿若实时显示，标注尚在核对，正式笔记和导出使用最终内容。

### 6.3 两种闭环不要混淆

**运行闭环**：每次任务讲解、模拟新手试读、核对、必要修订与复查、交付，解决当次问题。

**开发闭环**：收集真实用户与模拟新手的理解断点及具体错例→归类→修改某个 skill／样例→回放固定案例→比较→保留或撤回版本。只有通过来源检查、且在回放中有用的反馈才纳入公共教学规则；一次模拟反馈不能自动改写全部 skill。用户追问不会自动触发整套开发回放。

模拟新手参与初版的教学环境。初版通过规则和案例反复优化 tutor，后续才研究是否需要模型参数训练。模拟反馈有偏差，不能替代真实新手和老师。

### 6.4 模拟新手如何配置

**画像围绕用户已经描述的困难制定。**准备三个可选画像，每次只运行其中一个，避免为了多个学生角色成倍增加调用：

| 画像 | 假定已有基础 | 主要理解困难 |
| --- | --- | --- |
| 默认：医学科研初学者 | 有基础医学背景，听过 PCR、流式等名称 | 术语、方法原理、陌生图形与实验到结论的衔接 |
| 方法入门者 | 知道基本操作名称和步骤 | 为什么这么做、测了什么、对照有什么用 |
| 推理入门者 | 能描述图上变化 | 观察如何支持结论、证据范围和其他解释 |

这些是模拟配置，不是对真实用户能力的诊断。开发回放可分别使用三个画像；正常学习默认用第一个，根据用户明确反馈调整，不默认同时运行三个。

**限定输入。**模拟新手只拿到画像、学生问题、学生实际能看到的讲解与图件／图注，以及本学习单元此前已教过的概念。完整原文方法、作者结论、标准答案、核对报告和教学 agent 的内部材料不作为它的额外提示。复读保持同一画像；重跑不同教学规则时恢复同一初始画像，避免因测试会话积累答案而出现假改善。

限制提示内容不能抹去大模型已有知识，因此这是一种行为模拟，不是真实的“零知识学生”。通过输入隔离和固定案例检查降低偏差，而不把角色提示当成完全可靠的认知模拟。

**要求具体反馈。**输出包括：能复述的部分、卡住的句子或步骤、缺少的前置概念、一个针对该断点的自然追问。允许报告“按该画像可以理解”；不强制每次找错，也不接受只有“太难了／很好懂”的空泛评分。

例如讲解直接使用“扩增”却没解释：模拟新手指出不理解为什么要增加目标片段、这与检测有何关系；教学 agent 补这一步；复读再检查原来的断点是否仍在。该示例用于说明协作，不冒充已进行的模型测试。

**复读与停止。**反馈逐项关联原来的断点，分别记录已补足、仍不清楚和材料不足。模拟新手说“懂了”不能作为事实正确性的判据，核对 agent 仍对照来源检查。一次修订后保留未解决项并交付，不持续争辩直到三个角色都说满意。真实用户仍可继续追问。

**回放记录。**保存画像版本、讲解前后版本、理解断点、修订记录、复查结果、来源、调用次数与耗时；页面可以展开查看。最终采用的规则修改与示例由开发侧审查，老师反馈以后补充。

### 6.5 反复改进如何真正闭合

初版先建一个小案例库：6 个可用于改规则的案例，覆盖术语、PCR、流式、真实图件、证据链、看不懂后的改写；另外准备 2 个未放进提示词或示例的留出案例，用不同段落／图件检查是否只是记住示例。这是起步规模，不能据此宣称教学效果得到统计学证明。

每个案例固定材料、用户问题、新手画像、必要前置概念和人工可检查的通过条件。参考解答与核验清单供评价使用，不传给模拟新手。不同 skill 版本比较时固定材料与模型设置，重新建立角色会话；模型变化另记一组结果。

| 步骤 | 开发侧动作 | 留下的结果 |
| --- | --- | --- |
| 1. 保存基线 | 使用当前正式 skill 跑案例，保存完整可见输出和问题 | 案例版本、skill 版本、已知失败、调用与耗时 |
| 2. 找到原因 | 区分事实错、材料不足、术语漏讲、原理跳步、图表误读、推理越界、格式或流程失败 | 具体句子／步骤和来源，避免只有总分 |
| 3. 制作候选版 | 一次优先改一个有关模块或公共规则，写出为什么改 | 候选版本、差异、预期解决的断点 |
| 4. 小范围试跑 | 先回放 1–2 个受影响案例；失败则继续修改，不急着跑全库 | 是否补足原断点、是否新增事实或解释问题 |
| 5. 检查退步 | 候选版有希望时检查其余案例及留出案例，与缓存基线比较 | 改善项、退步项、仍未知项 |
| 6. 决定与归档 | 满足条件才升级正式版；否则保留旧版并记录原因 | 正式版本号、可撤回旧版、下次待处理事项 |

默认保留条件：针对的具体断点得到补足；没有新增关键事实错误、虚假出处或越界结论；其余必需条件没有明显退步；调用量与延迟仍在配置上限内。事实错优先修正，不能用“讲得更容易懂”抵消。若一次结果差异不足以判断，标为待定，在有必要时复测相关案例，不为了得到高分反复全量生成。

留出案例只用于检查，不把答案加入候选提示词；若之后根据其失败内容改规则，就将该案例转入开发集并补一个新的留出案例。随着老师或真实新手反馈到来，再增加新的材料和画像。模拟新手的“理解了”只是一个观察信号，最终判断仍要看具体讲解、来源和真实反馈。

每个开发批次最多评估一个候选版，覆盖最多 8 个案例、最多 48 次生成调用，包含本批次的定向试跑；不自动开始下一批。无缓存基线时先单独建立基线，另记消耗；因此首次基线加候选比较最多可能需要两个批次。实际通常因无需修订而较少，仍不能承诺免费。规则迭代可以反复开展，单次运行与每批开发都有上限。

此处的“训练”具体指提示词、skill、样例和流程的迭代。自动产出建议可以后续实现，正式规则发布由开发侧检查；初版没有自动修改模型权重或后台无限训练。

### 6.6 三个角色的提示词先怎么写

提示词由“公共教学与引用规则＋角色职责＋当前任务＋所需 skill＋有关材料＋输出结构”组成。开发侧先写可检查的规则，再用完整讲解、跳步讲解、材料缺失等少量案例检查；不能承诺提示词第一次就最优。

| 角色 | 必须收到 | 必须完成 | 不应做 |
| --- | --- | --- | --- |
| 教学 agent | 用户问题、相关来源、已教概念、教学 skill；修订时再给具体问题 | 分步解释，区分观察与推断，引用使用已有内容 ID，说明缺材料之处 | 臆造数据／出处；把更多字数当作更好教学；把模拟画像当真实用户诊断 |
| 模拟新手 agent | 固定画像、用户问题、学习者可见讲解／图件、此前已教概念 | 尝试复述，指出具体断点与缺失基础；复读逐项对应旧断点 | 查看隐藏标准答案；代替 tutor 重写整篇；为了扮演新手强行挑错；替核对角色判事实 |
| 核对 agent | 相关原始资料、讲解草稿、新手反馈、引用约定 | 标出事实、推理与教学问题，给出处和可执行修订建议；分别报告核对结果与材料不足 | 只凭另一个 agent 的摘要判断；以新手说懂了代替来源核验；伪称检查未取得全文 |

公共规则规定：资料正文是待解释内容，不是系统指令；不知道时指出具体缺什么；不输出隐藏思考过程。程序分别组装角色输入，不能把完整历史直接发给每个角色。输入清单、输出字段和停止次数在程序层约束，不能仅靠一句“请严格遵守”。

结构化输出至少包含内容 ID、来源类型、问题项和处理状态；角色间传的是讲解、反馈与核对结果，不传隐藏推理。最终仍有实质事实争议的句子不写入已确认笔记或 PPT；交付能确定的部分，并展示待核验问题。教师之后可以据此定位和修正。

## 8. skill 模块方案

skill 是可版本化的任务说明、教学模板、样例和必要脚本，不是另一个大模型。一个 agent 可以按需使用多个 skill；同一个 skill 也可独立调用。

### 8.1 四个入口与内部模块分开

学生只面对带读、方法、图表、PPT 四个入口，不需要理解内部模块名称。三个角色描述“谁负责”；下面的 skill 描述“某件事按什么规则做”。增加 skill 不等于再加一个 agent，也不必增加一次模型请求。

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| `medical-paper-guide` | 当前论文、所选单元、学习问题 | 分步带读与上下文 |
| `medical-term-explainer` | 术语、所在段落、需要的解释层级 | 定义、作用、类比及来源 |
| `medical-method-tutor` | 方法名称、相关方法段落 | 原理、测量对象、对照、结果解读与边界 |
| `medical-figure-tutor` | 图件、图注、结果段落 | 阅读顺序、观察与解释 |
| `medical-evidence-chain` | 问题、实验、结果和主张 | 实验到结论的展开与缺口 |
| `medical-journal-club-ppt` | 论文资料、所选重点、大纲 | PPTX、讲稿与来源表 |
| `medical-novice-simulator` | 新手画像、学生可见材料与讲解 | 能复述的部分、理解断点、缺失概念、追问与复读结果 |
| `medical-grounding-check` | 原始材料与草稿 | 具体核对问题及修改建议 |

### 8.2 一个模块具体装什么

以方法模块为例，建议目录如下；这是拟定结构，本次不创建这些实现文件。

```text
skills/
  shared/                         引用规范、教学层级、输出结构
  medical-method-tutor/
    SKILL.md                      使用条件、输入、教学步骤、输出、失败处理
    manifest.json                 模块 ID、版本、依赖、支持任务
    examples/                     少量正反例：漏讲测量对象、混淆原理与本文方法等
    references/                   PCR／流式的已核验基础资料及来源位置
    templates/                    方法讲解的结构，不预写每篇论文答案
    scripts/                      有需要才放辅助代码，无需每个模块都有
```

每个模块包含：何时使用、最低输入、材料不足怎么办、输出约定、教学规则、少量正反例、版本和参考来源。通用规则只存一份，各模块继承；论文事实保存在资料包，不硬写入通用 skill。资料较长时只取当前需要的片段，避免把整个模块库塞入每次请求。

`SKILL.md` 是便于人和程序维护的约定文件；网页后台仍需实现读取、路由、模型调用与导出，并非文件放进去就自动运行。PPT skill 负责内容与版式规则，后台脚本真正生成 PPTX；页面负责显示与操作。

### 8.3 怎样独立使用与组合

| 使用方式 | 教学角色加载的模块 | 共享与补缺行为 |
| --- | --- | --- |
| 只读一个段落 | 带读；按内容加入术语、方法、图表、证据链 | 取有关来源与已教概念，不强制生成整篇科研卡 |
| 只学 PCR | 方法＋术语 | 没有论文也可从基础教材开始；不输出“本文采用了……” |
| 只看一张图 | 图表；需要时加入方法与证据链 | 缺图注先明确缺口，不要求先完成带读 |
| 直接做 PPT | 汇报；按需加入术语和证据链 | 从资料包准备必要内容，先大纲再导出，无学习进度门槛 |
| 先学再做 PPT | 带读与汇报分别执行 | 复用当前有效的已核验单元，避免无意义重新生成 |

以上教学生成再经过模拟新手与核对两个角色，各加载自己的模块。模块组合可以在同一次教学请求中执行，不为每个术语独立调用三个角色；角色共享的是明确约定的数据，不共用全部隐藏上下文。

共享数据包含论文资料、已核验术语、引用内容 ID、学生主动提供的理解情况、已教概念和最终学习单元。模拟画像与真实学习记录分开，不能把模拟新手的反馈写成用户的实际掌握情况。

技能更新时任务记录保存所用版本；旧答案保留自己的版本与核对状态。来源改变或有关 skill 更新后，使相关缓存失效，再按需核对。初版只提供项目内维护的模块，不直接允许运行任意网络 skill 脚本。

## 9. 前端设计：iOS 简洁风格的学习网页

### 9.1 页面组织

| 页面 | 主任务 | 初版内容 |
| --- | --- | --- |
| 首页／论文库 | 开始与继续学习 | 示例论文、上传入口、最近记录、四个功能入口 |
| 学习工作区 | 对照原文理解内容 | 左侧原文，右侧导师；顶部切换带读／方法／图表 |
| 汇报工作区 | 调整并导出 PPT | 页级大纲、基础知识选项、生成状态、下载 |
| 设置面板 | 查看运行状态 | 模型名称、连接状态、示例／实时模式、记录管理 |

桌面阅读布局：

```text
┌────────────────────────────────────────────────────────────┐
│ 医学科研入门导师   当前论文             保存状态   设置     │
├─────────────────────────┬──────────────────────────────────┤
│ 原文／图件              │ 带读   方法   图表               │
│ 页码、目录、缩放        │                                  │
│                         │ 这一段在回答什么                 │
│ 所选段落或图片          │ 术语 → 方法 → 结果 → 结论        │
│                         │ 原文依据   展开基础   收藏       │
│                         │                                  │
│                         │ 从基础讲起 / 换个例子 / 下一步   │
│                         │ 输入问题…                        │
└─────────────────────────┴──────────────────────────────────┘
```

这是布局草图，不是已完成的截图。桌面优先，两栏比例可拖动；窄屏切换原文与讲解，避免两栏被压缩到无法阅读。

### 9.2 初版视觉默认值

- 浅灰背景、白色阅读面板、深色正文、少量蓝色用于关键操作。
- 统一圆角与间距；轻阴影帮助区分层级。
- 系统字体与可靠的中文字体回退，正文以长时间阅读为目标。
- 导航可用轻微磨砂；正文区域保持稳定背景和足够对比。
- 动效简短，用于反馈状态；可减少动效，键盘操作可见。
- 图标配文字，重要入口不会只用陌生图标表示。
- 术语解释、补充原理和核对详情采用可展开内容。

所有视觉参数都可调整。正式页面更关注上传、阅读、追问和导出，不加入无关的产品宣传段落。

### 9.3 必须设计的界面状态

未上传、读取中、读取完成、读取失败；模型未连接、实时回答中、检查理解步骤中、核对中、修订中、复查中、完成、失败、已取消；PPT 生成中、下载可用、生成失败；保存成功、保存失败。

状态由后台真实事件驱动，不播放假进度百分比。较长等待显示正在做什么和取消入口；取消后不让旧回答覆盖新任务。

## 10. 模型接入：降低首次使用的不确定性

### 10.1 优先路线与当前未知

优先研究用用户现有 GPT-6.1 Sol 账号，在本地程序中接入 Codex。官方 app-server 提供自定义客户端、会话与账号接口，但不意味着当前账号已经在本项目验证可用。

官方说明区分本地／开源应用与托管服务，并建议新集成了解 Sign in with ChatGPT。不能把本地账号接入直接搬成公开网站共享个人额度；以后上线需重新选择官方支持的接入方式。依据：[OpenAI Docs：Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Sign in with ChatGPT](https://developers.openai.com/siwc)。

前面的“可以用你的模型”是技术方向，不是连接成功的承诺。账号资格、客户端注册要求、可用模型、当前认证方式与图像输入都要验证。

### 10.2 分步接入流程

| 步骤 | 开发侧动作 | 用户需要做什么 | 费用边界 |
| --- | --- | --- | --- |
| 1. 只读检查 | 检查运行环境与客户端版本、认证方式、模型可用性；不输出凭证 | 通常无需操作 | 不进行模型生成调用 |
| 2. 明确入口 | 选择适用于本地 demo 的官方路径，区分订阅与 API | 如果需要，按说明完成浏览器登录 | 登录不等于开通 API 付费 |
| 3. 小测试 | 发出一次短文本请求，再验证一张普通测试图 | 查看连接状态与结果 | 使用实际选中的账号额度；不能承诺零消耗 |
| 4. 接教学流程 | 再接论文和三个角色，记录调用次数与耗时 | 试用一个学习单元 | 默认有次数上限，不自动购买额度 |

不要求用户把密码、token 或 API Key 粘贴进聊天。不覆盖现有登录信息，不根据环境变量存在就默认使用付费 API。连接失败时说明是哪一步失败，不反复试探账号或连续发出大请求。

如果订阅接入路径不可用，可先完成清楚标注的界面示例。付费 API 或更换国内模型属于明确的替代方案，说明后再选择，不能静默切换。

### 10.3 实时模式与示例模式

**实时模式**：真正读取当前材料、调用模型、执行模拟新手试读与核对并生成新回答。联网与可用额度是必要条件。

**示例模式**：展示已经核验的固定教学内容和流程，用于模型尚未接通时看界面或离线演示。页面持续注明“示例内容”，自由提问不能返回预设答案冒充实时推理；运行记录注明模式。

没有 live 接入时，交付可称为“界面与教学示例”，不称为完整可交互智能体。此区分用于保证试用者知道自己正在体验什么。

### 10.4 成本控制

只发送当前问题有关的段落、方法与图件；预处理资料可复用；已经生成并核对过的学习单元可以缓存。缓存键包含论文与来源版本、所选内容、全部有关 skill 版本、画像版本、模型与解释设置，用户改变问题或规则后不能误用旧结果。

记录已知调用次数、请求耗时和服务返回的用量。订阅额度与 API 计费分开；没有可靠用量信息时不估算成精确金额。两次核对同一模型仍可能重复同一种错误，多 agent 不构成正确性保证。

初版不下载 GPT 模型权重、不租 GPU、不做 SFT 或强化学习。先用现有条件验证可行路线，再判断是否需要其他服务。

教学角色数量不会要求笔记本同时运行三个本地大模型。三个角色可顺序使用同一个云端模型，笔记本主要运行网页、资料处理与文件导出；具体性能在实施时检查。多 agent 增加的主要是等待时间、上下文用量和请求次数，不能据“有三个角色”推断必须升级显卡。

开发回放与学生的一次任务分开计数，默认不在后台自动开展。先使用 GitHub 参考写好规则，再用少量失败案例修改，减少无方向试错；借鉴模块不会天然降低每次三角色协作的用量。

## 11. 使用完整性与数据设计

### 11.1 文件处理

首版先支持文本型 PDF；初步上传边界为单文件不超过 30 MB、100 页，作为实现默认值，随后按实际性能调整。保留原文件，并按页提取文本，供用户检查。

图件不依赖“自动识别一定成功”：支持页级查看、缩放与手动圈选。文本顺序错乱时可选段落或粘贴原文；扫描 PDF 或缺少补充材料时明确能力边界。全自动 OCR、任意排版恢复和补充材料批量解析留到后续。

PDF、图片与网页正文都视为研究资料，不当成指令执行。模型对原文的读取不授予任意命令、系统文件访问或联网操作权限。若某条接入路线无法限制这些能力，需要调整架构后再使用。

### 11.2 学习记录

保存论文标识、当前页与学习单元、用户主动收藏的术语、提问、最终回答、引用、核对问题、skill 版本、模型与运行模式。

“读过”“表示不懂”“主动标记已理解”分别存储。不从停留时间推断掌握程度；允许删除记录。初版不做账号系统、跨设备同步或多人共享。

论文和记录默认在本机保存；模型推理需要向云端发送选中的内容，因此“本地 demo”不等于内容完全不离开电脑。首页或首次实时使用时用一句话说明数据去向，示例使用公开论文。

### 11.3 失败与恢复

| 情况 | 行为 |
| --- | --- |
| PDF 无法解析 | 保留文件，指出失败，提供选页／补文本入口 |
| 图片或图注不全 | 标明缺少材料，暂停相关事实判断 |
| 登录失效／额度不足 | 保留问题，显示重新连接或稍后重试；不切付费接口 |
| 请求等待过久 | 显示当前步骤，允许取消；超时与自动重试有上限 |
| 核对仍有争议 | 显示待核验项，保留来源，不继续无限修改 |
| 保存失败 | 提醒用户，允许复制／导出当前内容，不显示假成功 |
| 导出失败 | 保留大纲与文本，可重试导出，不重做全部模型生成 |
| 刷新或重启 | 恢复已完成记录；未完成任务标为中断，不擅自重发收费调用 |

## 12. 技术实施草案（供开发使用）

用户不需要先学习本节。选型优先考虑 Windows 上容易启动、依赖少、前端可调整、模型可替换。

| 部分 | 建议选型 | 原因／边界 |
| --- | --- | --- |
| 网页 | React＋TypeScript，Vite 开发构建，独立 CSS 设计变量 | 页面与教学逻辑分开，后续换风格不影响模型接口 |
| 本地后台 | Node.js＋TypeScript，HTTP 服务与任务事件 | 与前端共用一套运行时，负责模型、状态和导出 |
| PDF 查看与文本 | PDF.js | 页级预览、文本与圈选支持；复杂排版需实际检验 |
| PPT 输出 | PptxGenJS | 模板生成 PPTX，文本与形状可编辑，科研图用原图 |
| 初版保存 | 每篇论文一个目录，结构化 JSON＋原文件＋导出文件 | 适合单人 demo；原子写入，未来多人版再用数据库 |
| 模型层 | 统一 provider 接口，优先本地 Codex 适配器 | 接入失败不要求改写教学与前端模块 |
| 协作层 | 显式任务状态机 | 先落实角色、次数与恢复，暂不依赖多个大框架 |

上述是实施建议，不是已安装的软件清单。版本在实施时读取官方兼容要求并锁定，不在方案中承诺某个未经测试的版本组合。

技术依据：[React](https://react.dev/learn)、[Vite](https://vite.dev/guide/)、[Node.js](https://nodejs.org/learn/getting-started/introduction-to-nodejs)、[PDF.js](https://github.com/mozilla/pdf.js)、[PptxGenJS](https://github.com/gitbrent/PptxGenJS)。

### 12.1 建议项目结构

```text
项目根目录/
  docs/                   方案、启动说明、验收与已知问题
  app/                    页面、组件、阅读交互、设计变量
  server/                 文件、模型适配、任务流程、导出
  skills/                 教学模块与公共规则
  examples/               经核验的示例清单与教学单元
  evals/                  开发／留出案例定义、人工核验条件与回放入口
  data/                   用户论文与学习记录，不提交 Git
  exports/                生成结果，不提交 Git
  runs/                   原始运行与回放记录，不默认提交 Git
  checks/                 少量有价值的流程与证据检查
```

模型登录信息与 secret 不放在项目文件或 Git 中。开源样例若不能直接再分发全文或图件，只保留获取入口和来源说明；实施时按材料的实际授权安排，不把“可阅读”当成“可任意分发”。

### 12.2 内部数据约定

- `PaperBundle`：题录、版本、原文件、页面、文本块、图件与图注、来源状态。
- `LearningUnit`：当前问题、前置概念、方法、观察、推理、边界和引用。
- `ReviewResult`：具体问题、依据、建议、处理结果与仍未核验事项。
- `NoviceFeedback`：画像与版本、可理解部分、理解断点及对应句子、缺失概念、追问、复读结果。
- `TaskRun`：任务 ID、角色输入范围、模型设置、skill／画像／来源版本、运行模式、状态、次数、时间、取消与失败原因。
- `DeckOutline`：每页目的、内容、图件、出处、讲稿与生成状态。
- `EvalCase`：案例 ID、开发或留出划分、材料版本、问题、画像、必要解释项、核验条件与参考依据。
- `RevisionBatch`：基线与候选版本、修改理由、案例结果、改善／退步／未决问题、消耗、保留或撤回决定。

每个引用使用固定内容 ID，能返回原文；这些 ID 不依赖模型随意生成。输出不符合约定时返回可解释错误或有限修正，不能直接把坏结构渲染成完成结果。

回放原始记录默认本地保存，只有去除个人内容、适合公开且来源允许的案例才进入项目。角色输入隔离通过组装清单检查，不以复制完整聊天历史代替；数据约定是后续实现标准，不代表当前已有这些记录。

## 13. 制作顺序与阶段交付

不需要先完成正式教学效果研究。每个阶段都形成可看或可用的成果；阶段划分用于发现问题，不额外增加逐项审批。

| 阶段 | 工作 | 可检查成果 |
| --- | --- | --- |
| M0：确认关键条件 | 取得示例局部可靠资料；只读检查接入路线，再做最小模型测试 | 资料来源表、连接测试结果、可用路线与剩余问题 |
| M1：页面与基础资料 | iOS 风格首页、阅读器、教学区、PPT 大纲、保存状态 | 本地网页可操作；示例内容明确标注 |
| M2：实时教学 | 写公共规则与三个角色提示词；接术语、方法、图表、证据链和引用定位 | 中间开发版本可检查讲解；完成版还需 M3 协作 |
| M3：协作与记录 | 接模拟新手试读、核对、一次修订与复查；建立基线、候选回放、保存／撤回；补取消和恢复 | 可查看理解断点；至少完成一次可追溯的规则比较；刷新后记录仍在 |
| M4：输出与交付 | 可编辑 PPT、学习笔记、必要验证与启动整理 | 一次从材料到教学再到导出的完整操作 |

M0 如果接入受限，可推进 M1 与资料整理；不把受限情况埋到最后。M2 到 M4 的实时验收必须有实际可用模型。阶段顺序可按依赖调整，不能因此删除核心功能而不说明。

初版必做：四个入口、代表性单元带读、真实自由追问、证据定位、方法／图表基础解释、模拟新手画像与试读、三个 agent 的有限协作、模块版本与小案例回放、候选规则保留／撤回、基础 PPT 导出、学习记录、取消与错误处理、清楚的模式标识。

以后再做：任意论文的全自动完整精读、庞大医学课程库、完整扫描 OCR、真实学生测评体系、多个模拟新手同时参与的大规模教学环境、自动实验设计、模型训练、多账号与在线部署。暂不安排视频、申报书或上线日期承诺。

## 14. 初版验收清单

验收以真实操作为准。只检查与当前功能有关的事项，不先开展大型基准或重复模型测试。

| 场景 | 通过标准 |
| --- | --- |
| 打开与启动 | 用户按说明可启动网页；缺依赖时提示可理解 |
| 资料载入 | 示例真实可读；上传文本 PDF 可显示页面和提取文本；失败不假报成功 |
| 术语 | 陌生缩写有解释，并说明当前研究中的作用 |
| 方法 | 能讲清测量对象、对照与结果边界；一般原理和本文做法分开 |
| 图表 | 先解释图怎么读，再解释当前图；未知标记不猜；引用能定位 |
| 推理 | 能展开实验到结论的步骤，不直接跳到作者结论 |
| 追问 | 用户说看不懂后，讲解方式实际改变，而非原句重复 |
| 协作 | 用人工设置的错分组、无来源数字和跳步草稿验证核对；问题具体、有依据 |
| 模拟新手 | 对省略必要概念的草稿指出具体断点；完整讲解允许判为可理解；不每次强制挑错 |
| 输入隔离与复读 | 新手输入不带隐藏答案或完整核对报告；复读用同一画像，比较原断点是否被补足 |
| 模块独立使用 | 方法可无论文学习；PPT 可直接生成；切换模块可复用有效资料，不要求先完成测验或全篇阅读 |
| 跨案例闭环 | 有基线、明确规则差异与回放结果；记录退步及保留／撤回决定；留出案例未混入提示示例 |
| 来源与版本 | 输出能识别有关来源和模块版本；更新有关规则后不误用旧缓存；复用文件有来源记录 |
| 次数与取消 | 达到上限停止；取消后不继续新增模型任务或覆盖页面 |
| 保存 | 关闭／刷新后可恢复完成记录；不自动重发中断任务 |
| PPT | PPTX 能打开，中文文本可编辑，原图有来源，讲稿有内容，没有明显溢出 |
| 模式与认证 | 示例与实时持续可辨；模型未连接不显示假实时回答；凭证不进入前端或日志 |

固定回放先设 6 个开发案例：术语不懂、PCR 原理、流式原理、所选真实图件、实验到结论、看不懂后的改写；另设 2 个留出案例，采用不同的原文片段或图件。PCR 与流式的通用方法教学不必强绑同一论文；知识来源要独立核验。案例尚待取得材料后编写，不是已经完成的测试。

记录人工能检查的结果：有无跳步、有无新增未解释术语、关键事实是否有来源、追问是否改善。可用这些结果判断规则修改是否值得保留；不将相同模型的自评分当成独立教学评价。

闭环验收要求比较过程确实可运行，并能拒绝变差的候选版；不要求每次修改必然进步，也不要求所有模拟画像一致赞同。PPT 另做实际打开、页面渲染与内容检查，不能用讲稿试读替代文件验证。

## 15. 主要局限与应对

| 局限 | 对初版的影响 | 应对 |
| --- | --- | --- |
| 订阅接入未验证 | 可能影响实时功能 | 尽早试最小连接，保留适配器；不默认换付费 API |
| 三个角色使用同一模型 | 可能共享错误倾向 | 核对角色直接读材料，配合引用检查；承认剩余未知 |
| 模拟新手已有模型知识 | 可能比真实新手更容易理解，也可能为角色而故意挑错 | 限定可见输入、固定知识画像，检查具体断点并引入真实反馈 |
| 试读与复查增加调用 | 更慢、消耗更多额度 | 每次一个画像、一次修订、最多六次生成；整份讲稿整体试读 |
| 讲解详细可能造成负担 | 学生不一定愿意读长篇 | 一次一单元、必要基础展开、随时跳过与追问 |
| 首篇论文偏基础医学 | 尚未证明临床适配 | 后续补一篇临床材料，初版表述范围准确 |
| PDF 提取与图件定位 | 复杂文件可能失败 | 提供选页、圈定和文本补充；不承诺任意 PDF 全自动 |
| 仅有示例成功 | 不能代表对所有论文有效 | 区分示例验收和泛化测试，后续逐步加材料 |
| 固定案例容易被优化过度 | 分数上升可能只是记住了示例 | 留出材料不进入提示词；用于改规则后补新留出案例；未来加入真实用户错例 |
| 提示词迭代不是权重训练 | 不会因反馈自动获得所有能力 | 如实记录 skill 改进；确有需要和数据后再讨论模型训练 |
| GitHub 的任务或人群不同 | 成熟代码不等于适合医学新手 | 逐项迁移并用本项目案例核验；不同许可与署名分别记录 |
| 教学效果未正式评估 | 不能宣称显著提升学习成绩 | 先由真实用户试用，再请老师看重点单元 |
| 本地运行依赖设备和网络 | 关机或断网后实时任务停止 | 保存完成记录、明确运行状态，部署以后再处理持续服务 |
