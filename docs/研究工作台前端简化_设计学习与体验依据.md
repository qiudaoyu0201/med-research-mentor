# 研究工作台前端简化：设计学习与体验依据

日期：2026-10-06。代码基线：`e451f38`。

后续实施安排已整合为[第三轮前端简化落地方案](研究工作台第三轮前端简化_落地方案.md)（v1.1，待实施）；本文件保留设计来源、学习过程与体验假设。v1.1 根据用户补充反馈加强材料可读性，并逐项审查现有功能，明确保留、优化、删减和暂缓项。

本轮先研究设计规范和用户体验方法，形成后续改版依据。本文记录已查阅来源、现有界面观察及待验证的设计建议；尚未修改前端，也未开展新的目标用户试用。尺寸、菜单数量和验收目标属于本项目的试验值。

## 已确认的问题与设计目标

用户明确反馈：界面太乱，希望简洁、导向清晰；可利用右键等方式按需展开；聊天区域被其他区域挤占。后续设计以连续阅读和提问为主要任务，兼顾查原文、记录想法及制作汇报。

后续补充反馈：提取原文有乱码或乱序，讲图时图片细节无法辨认；不应为功能完整堆砌劣质能力，但已经做得好的功能应保留，需要批判审查已有功能。由此将“围绕当前论文提问、获得有依据讲解、核对原页并看清图”作为本轮核心；选区引用、草稿恢复、笔记收藏和已有 PPT 流程保留并检验，重复入口和劣质展示删减，新辅助能力暂缓。

已从当前代码和界面确认：

- 导航默认 260px；右侧阅读面板默认占剩余区域的 45%，且至少 330px。按 CSS 近似计算，1440px 窗口同时打开两侧区域时，聊天栏约 640px；1024px 窗口约 410px，尚未扣除聊天内部留白。此处为规则推算，实际值需在原型中测量。
- 输入区默认 210px、最低 175px；顶部还包含大标题、管理工具栏及重复的论文／讨论信息。聊天高度也被固定区域压缩。
- 每段回答重复展示来源按钮和追问入口；收藏、反馈、笔记动作进一步增加了操作密度。
- PPT 同时展示版本记录、页面列表、预览和完整编辑表单，阅读和编辑状态混在一起。
- 原文默认显示提取文本；PDF 页面需要切换，且按面板宽度渲染，没有主动缩放工具。图件登记和示例缓存的是固定 `scale: 1.3` 的整页图，上传附件缩到最长边 1800px 并保存 JPEG，未独立保留原始字节。这些做法不足以保证讲解时能读清标签，不能据此断言原始 PDF 本身低清。

依据：[布局参数](../app/research-layout.tsx)、[布局样式](../app/research-workspace.css)、[回答视图](../app/research-discussion.tsx)、[PPT 工作区](../app/research-ppt.tsx)。

材料依据：[原文视图](../app/research-reading.tsx)、[PDF 渲染](../app/research-pdf.tsx)、[图件登记](../server/paper-assets.ts)、[示例图件](../server/sample.ts)、[附件处理](../server/attachments.ts)。

目标是让用户容易回答三个问题：我现在在读哪篇论文／哪段内容？此刻能做什么？下一步怎样继续？

## 查阅来源与学习结论

| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |

材料改版另核对 [Mozilla PDF.js 渲染示例](https://mozilla.github.io/pdf.js/examples/)：页面可以按 viewport 的目标比例渲染，并处理屏幕像素比。项目据此安排缩放重绘，清晰度仍以真实论文目标标签能否辨认为准；固定渲染比例和 CSS 放大不能代替任务验收。

## 从用户任务重新安排界面

下表是基于产品定位与用户反馈的任务假设，后续需要观察真实使用频率。

| 用户此刻的目标     | 应看见的主要内容／动作                     | 按需出现的内容               | 需要保留的上下文             |
| ------------------ | ------------------------------------------ | ---------------------------- | ---------------------------- |
| 开始读一篇论文     | 当前论文、一个具体起始问题、输入区         | 主动整理概述、更多问题、题录 | 论文身份与材料状态           |
| 理解回答中的一句话 | 回答正文、选区浮条、待发送引用             | 解释程度选择、收藏和记录     | 实际选区、完整问题、阅读位置 |
| 核实一项结论       | 轻量来源入口、原 PDF 对应页和返回位置      | 短摘录、来源详情             | 回答与支持它的来源关系       |
| 理解一张科研图     | 目标图／原页、大图入口、完整图注与相关讲解 | 缩放和平移                   | 图号、轴单位、图例与来源     |
| 中断后继续阅读     | 上次论文、讨论、草稿及阅读位置             | 全部历史、课题管理           | 原文定位、附件及未完成编辑   |
| 准备汇报           | 当前汇报、页面列表、预览、导出             | 版本历史、单页编辑、核对详情 | 论文、保存版本和未保存草稿   |

原“研究问题 → 实验 → 结果 → 汇报”路线缩减为按需问题建议；不扩建独立路线面板，不要求用户完成上一阶段才能继续，也不自动声称用户已经理解。

## 本轮学习后修正的设计判断

1. **右键与渐进披露承担不同作用。** 右键提供当前对象最相关的快捷操作；低频全局设置留在设置页。不能把所有隐藏功能塞入一份大菜单。
2. **更少按钮需要配合可发现的入口。** 鼠标右键、更多按钮和键盘入口使用同一套对象动作。手机文字区域先保留系统选词／复制，再提供选区浮条，避免长按手势冲突。
3. **更多聊天空间需要兼顾原文对照。** 默认收起支持区域；用户持续对照原文时允许固定并排。抽屉适用于临时查看，但频繁开关也可能增加切换负担，需与并排方案比较。
4. **正文简洁仍保留证据关系。** 来源改成轻量编号或“原文 · 第 N 页”，展开后看到具体支持片段。必要的结论边界仍贴近结论；核对详情可以按需查看。
5. **导向清楚不等于强制流程。** 一次突出一个相关下一步，同时保留自由提问、返回、跳转及继续阅读的方式。
6. **材料要能支持核对与理解。** 默认对照原始 PDF；短摘录用于定位，图件可展开辨认轴、图例和分图。原件、阅读显示图、缩略图与模型输入分工，低清原件明确补充要求。
7. **已有功能也要经过取舍。** 不按功能数量判断完成度，也不一律删除辅助能力。逐项检查任务价值、现有质量与视觉成本；保留有效流程和数据，修复劣质展示，合并重复入口，暂缓独立系统扩建。具体决定见落地方案第 1.2 节。

## 可用于原型的布局与交互试验值

以下数值属于本项目的初始候选值，不是任何设计系统规定的标准。

- 桌面导航尝试 200–220px，并有明显的折叠／恢复入口。折叠后仍能辨认当前论文和切换方式。
- 默认关闭原文／笔记支持面板，聊天获得剩余空间。需要对照时，支持面板尝试 350–380px；若聊天将小于约 720px，优先采用临时查看或折叠导航。窄窗口直接使用单主区域与明确返回。
- 以可用容器尺寸计算并排条件，随窗口大小、浏览器缩放、导航宽度及人工调整重新判断。720px 不是对手机聊天的硬性下限，也不制造横向溢出。
- 聊天容器可以占满可用区域；长文本正文再用独立的行宽上限约束。两者分别调整，避免“正文不宜太宽”导致聊天容器也被缩窄。
- 顶部尝试一行 48–56px，呈现论文名、资料入口及更多操作；已有汇报入口次级保留。完整用户问题保留在消息中。
- 输入区默认尝试 90–120px，随文字和附件增高；长草稿可主动展开。引用和附件存在时保证可看见、可移除。
- 普通按钮减少强边框与填充；强调色集中到当前选择和主动作。视觉分界变细，拖动命中区域仍保留，并支持键盘调整。
- 每个上下文菜单先尝试 3–5 个相关动作，最多一个子菜单层级。以任务可发现性和点击负担决定增减。
- PPT 默认显示页面列表和预览，编辑当前页时才展开编辑区；版本记录使用选择器，导出保持明确入口。

上述 PPT 布局属于候选方向，v1.1 保留已有按页编辑、版本恢复与导出，仅安排必要的编辑区折叠和入口收敛，暂缓全面重做。原文窄面板承担短查与定位，整页和科研图支持主动展开阅读，防止为保留聊天宽度而牺牲材料可读性。

## 待验证的体验假设

| 假设                         | 原型比较                   | 观察指标                                               |
| ---------------------------- | -------------------------- | ------------------------------------------------------ |
| 聊天优先能减少阅读中断       | 当前布局与聊天优先布局     | 聊天可用宽高、可见正文量、为继续阅读而关闭面板的次数   |
| 上下文操作能降低视觉负担     | 固定按钮与右键／更多／浮条 | 首次发现入口、无提示完成情况、误点与来回查找           |
| 原文面板应该区分短查与长对照 | 临时查看与固定并排         | 查来源后回到原位置的操作数、遮挡情况、是否丢失阅读位置 |
| 一条相关建议更容易开始       | 多个并列建议与一个主建议   | 首次有效提问、停顿／求助、是否能自由改变问题           |
| 按需编辑让 PPT 更容易理解    | 编辑表单常开与按页展开     | 选对页面、恢复草稿、辨认保存状态、导出正确版本         |

先为相同论文和相同任务制作候选原型，使用相同内容比较，以免模型答案变化干扰界面判断。可先用固定内容完成工程验证；真实试用再观察完整流程。

增加材料假设：原 PDF 与可展开的清晰图件有助于核对。比较提取长文／整页缩图和原页／大图，观察能否读出指定标签、轴单位，核对图注并返回原回答。PPT 全面原型比较暂缓，已有能力继续回归。

## 体验验证安排

采用 Design Council 的“发现—定义—探索—验证”组织下一轮。现阶段完成公开资料学习和现有界面诊断；访谈、原型任务观察和目标用户验证尚未开展。

首轮建议邀请少量符合产品定位的用户，覆盖科研入门者、熟悉论文者及不同窗口／输入方式。人数和轮次依据发现的问题调整，小样本用于找问题，不能声称统计上已经证明学习效果。

任务说明只给目标，例如：

1. 导入你准备阅读的论文，开始理解它的研究问题。
2. 找一句还没理解的话，针对它继续提问。
3. 查明回答中某个结论的来源，然后继续读刚才的回答。
4. 切换另一篇论文，再回来继续未发送的问题。
5. 调整汇报中的一页，确认保存并导出需要的版本。

记录是否独立完成、何处求助、误操作、任务耗时、返回／切换次数，以及任务后的简短困难评价。测试中不提前告诉用户“右键”或“点击更多”，除非正在研究已教授后的效率。

工程验收检查窗口适配、键盘／触屏入口、菜单边界与焦点、草稿恢复、引用归属、保存／导出状态；用户观察检查是否找得到入口和能否连贯完成任务。理解程度需要另做内容评价，不以界面测试通过或模型核对通过代替。

核心观察增加“找到讲解所指分图，读出目标轴单位并对照图注”，使用真实密集多面板图、公式页、扫描页及低清反例。现有理解反馈保留为可选记录，不能拿来证明掌握程度。

## 后续改版优先级

1. 聊天空间与材料可读性：合并顶部、输入区随内容变化；原 PDF 默认、必要缩放与清晰看图，资料按任务出现。
2. 操作层级：统一对象动作，接入右键／更多／选区浮条，减少逐段固定按钮。
3. 上下文连续性：来源定位和返回、论文切换恢复、少量按需问题建议。
4. 核心视觉与保留：统一核心间距、字体、按钮与状态；审查辅助能力，保留有效流程并做必要优化，全面汇报改版暂缓。

本记录供下一轮原型与实施方案使用。应先验证聊天空间和常见任务，再据观察调整其余部分。
