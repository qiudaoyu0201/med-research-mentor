# 内部训练第一轮落地方案

版本：v1.0 · 日期：2026-10-07 · 工程基线：`cc29845`。

本文是[主方案 v2.8](科研能力培养与三类Agent协作_整体落地方案.md)的内部实施细则。**本次交付方案，尚未执行新训练、生成新候选或发布能力提升。** 已有完成度与失败证据见[整体复核](整体完成度复核_2026-10-07.md)和[产品收尾验收](产品收尾_配图裁剪与日常错误验收.md)。

第一轮的结果应是：有依据地改善讲解、PPT／演讲稿、研究方案中的具体缺口；建立可重复运行的内部比较；分别报告产物改善与模拟学习表现。用户仍从现有三个入口使用，不增加训练界面、考试门槛或后台管理步骤。

## 1. 第一轮做什么

这里的训练是改进规则、材料组织和协作，并用固定案例验证；本轮不安排模型权重训练。每个候选只改一个明确层面，保留其他比较条件。第一周期只比较一个候选；M1 确定后冻结哈希，M2 的全部比较使用同一候选。若继续修改，建立下一周期并重新验证，不能拼接不同候选的通过记录。

| 能力         | 第一轮目标                                                       | 通过时应看到的结果                                                                           |
| ------------ | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 论文讲解     | 讲清问题、方法测到了什么、对照作用和证据边界；内部反馈不混进正文 | 回答先解决用户问题，必要原理衔接完整；未知明确；正文没有内部编号和重复核对说明               |
| PPT 与稿件   | 主线清楚，原图与讲述对应，页面简洁，完整稿与保存页面一致         | 实际 PPTX 图文能读，裁剪保留相关标签；讲稿能解释图，而非重复标题；完整稿可选且版本匹配       |
| 研究方案     | 根据问题和资源做设计，解释理由，识别条件不足                     | 条件变化后调整相应设计；不凭空补样本量、结果或设备；类型选项保持通用，不写成某篇论文专用模板 |
| 小白独立应用 | 从选择题扩展到复述、设计草案、汇报提纲                           | 保留原始作答和真实曝光；能区分独立完成、受助完成与仍有缺口                                   |

首个候选聚焦两份真实失败共有的“内部反馈进入交付正文”问题，检查生成与修订时的反馈处理。不能通过直接删掉编号、放宽校验或把必要解释改成未知获得通过。随后根据独立审阅定位的具体缺口决定下一候选；没有观察到的问题不先扩功能。

| 有效规则       | `decideRevision` 保留 reviewed-candidate；`loadSkills` 不自动读取它                            | 首轮用 Git 管理有效规则：验收后更新对应规则及版本，验证实际新请求装载的哈希；候选留存不算发布            |
| 账本与保存     | 有预算预约、取消、状态、持久化和隔离                                                           | 全批统计算例、角色、评价、失败和结果未知的调用；内部记录使用独立目录，个人论文库不加入训练记录           |

## 3. 固定案例，再开始修改

第一轮产物比较用六个案例，分开发与留出。具体 PDF、问题、条件和评价依据在实施阶段 M0 冻结；冻结前不发起比较。历史输出用于定位问题，首轮正式比较默认重新运行基线与候选。

| 案例 | 分组 | 任务与来源                                               | 用途                                         |
| ---- | ---- | -------------------------------------------------------- | -------------------------------------------- |
| D1   | 开发 | Xu 2018 普通论文 PPT，复用真实失败请求与原材料范围       | 检查反馈编号泄漏、页面主线、原图与讲稿       |
| D2   | 开发 | 队列论文讲解，复用真实失败请求与原材料范围               | 检查内部说明泄漏、研究设计、关联与因果边界   |
| D3   | 开发 | 一项研究方案任务，固定问题、资源、来源及资源变化后的条件 | 检查设计依据、可行性、条件变化和未知处理     |
| H1   | 留出 | 未参与本轮规则修改的论文 A，讲解一个方法到证据的连接     | 检查通用解释能力，不复述开发论文答案         |
| H2   | 留出 | 未参与本轮规则修改的论文 B，生成带原图 PPT 和可选完整稿  | 检查页面／稿件质量及实际文件，不能只看网页   |
| H3   | 留出 | 新研究问题与资源约束，用 A／B 中合适的来源支持设计       | 检查独立课题适配，不照搬原论文实验或观察结果 |

材料要求：两篇开发论文加至少两篇留出论文，覆盖基础／转化与临床观察场景；资料来自可核对的公共全文或既有明确可用材料。同一研究的预印本、正式版和补充材料归到同一组。现有 Hewitt 等已用于开发的材料不再声称为全新留出。

每个案例记录请求、研究类型、来源版本／文件哈希、可见片段、图件范围和评价版本。默认先手选核对材料，不为启动训练新增采集平台；个人笔记和其他用户资料不自动并入训练集。

留出原文可作为目标任务的必要输入；参考结论、评分依据和校验备注只在评价侧。留出结果不能反馈给本轮候选生成。若据留出缺陷继续修改，该案例转为开发，并重新选择留出，不能继续称原案例为未见题。

## 4. 三类 Agent 怎么合作

| 角色 | 可以看到                                                     | 应交付什么                                                             |
| ---- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 助手 | 用户问题、已陈述条件、实际装载材料、当前规则、开发侧反馈     | 讲解／方案／PPT 与稿件、具体依据和必要未知；修订保留原目标             |
| 小白 | 固定背景、实际可见的教学与允许材料、任务要求、自己的历史作答 | 独立复述／方案草案／汇报提纲，以及具体理解断点；不能只说“我懂了”       |
| 校验 | 固定评价条件、必要原文、确切产物版本、小白原始作答和曝光记录 | 具体位置、依据、缺口、影响及未评价项；事实、产物质量和学习表现分别判断 |

在线生成沿用现有按需协作，不把全部训练角色机械加到每次用户请求。训练侧可以运行完整诊断；独立迁移时小白看不到目标助手产物、参考答案或评分备注。试读一份成品只证明试读表现，不能计为独立设计或独立制作 PPT。

小白的模型自带知识无法仅靠提示消除。比较保留相同模型、背景和输入，记录未经可见材料支持的知识；不把模型自报理解或一次正确回答归因于本次教学。

## 5. 按四个阶段实施

| 阶段                  | 工作与交付                                                                               | 完成条件                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| M0 固定运行条件       | 案例清单、材料与规则快照、独立数据目录、固定比较配置；先做零调用输入走查                 | 六例可用且分组明确；三个真实服务能被同一内部脚本驱动；候选／答案隔离、预算、取消、重启和记录兼容检查通过 |
| M1 校准并修首个缺口   | 六份预先核对的正反例校准评价；对 D1 运行基线／候选小批，优先处理内部反馈泄漏             | 评价能识别规定的错误，结果均有位置与依据；基线、候选、调用与失败记录完整；只形成候选，不发布             |
| M2 产物比较与发布判断 | 完成 D1–D3 的定位与比较，冻结一个候选后运行 H1–H3；导出、实际渲染 PPTX，查看方案及完整稿 | 三类产物都检查；已确认缺口有改善，成功路径不退步，来源和文件门槛全部满足；不满足则保留基线并报告         |
| M3 开放式学习试验     | 完成复述、设计、汇报三类任务；比较未学习／只给材料／材料加教学的独立作答                 | 有可核对的作答、曝光与判断；只报告指定任务的模拟表现，真实学习迁移继续未验                               |

M0 先新增内部脚本与必要合同／适配，复用 `BudgetLedger`、来源、存储和实际生成服务；不建新的前端工作台。拟新增 `scripts/internal-training.ts`、内部案例清单及比较协议；文件名在实施时按现有结构确定，不能把示意名称写成已交付命令。

M1 评价校准使用三份明确可通过的局部产物和三份有确切错误的局部产物，例如无依据的结论、图文不符、内部编号进入正文。程序先检查可机械判定的部分，模型审阅语义；若评价识别错误，先修评价再重新冻结，不靠调整候选迎合漂移的评分。

M2 从普通上传／提问／生成路径取结果。PPT 要检查原图区域、图例和标尺、原文对应、实际 PPTX 和备注；方案要检查条件、设计理由、假设与结果语气；完整稿要与保存页面版本一致。没有生成成功就记录失败，不用固定正文文件替代模型效果。

M3 的三类任务分别为：解释一条新证据链、在新资源条件下写设计草案、根据新论文组织三页汇报提纲。两套规则各用同一初始画像的独立克隆状态，分别运行三种学习分支；目标题目与必要目标材料相同，只改变之前的学习曝光。未学习分支不给此前学习材料；材料分支获得同一学习材料；教学分支再增加实际教学。题目不同于已练题，之前直接改写的目标答案不能计为独立迁移。首轮每种条件一次，记录波动限制；有迹象后再做重复，不能据此宣称稳定教学收益。

## 6. 调用边界、比较与停止

使用当前已配置模型，基线与候选固定实际型号、推理配置、材料、背景、评价和工具版本；记录影响比较的实际返回配置，不保存服务端凭据。产物比较先顺序执行；协作扩展先在内部验证，不扩大在线默认调用。国内模型与真人核验继续暂缓。

| 范围            | 首轮默认上限                        | 计数方式                                                                                            |
| --------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------- |
| 第一小批 M1     | 24 次尝试，或 45 分钟，先到即停     | 六次校准审阅，加 D1 基线／候选各最多七次生成链调用及一次独立审阅，最多 22 次；尚不满足发布条件      |
| M1＋M2 产物周期 | 合计 108 次尝试，分批每批最多 24 次 | 六例 × 两套规则 × 最多八次调用，加六次校准，共最多 102 次；余量用于显式记录的复测，不是自动耗尽目标 |
| M3 学习试验     | 单独最多 36 次尝试                  | 三任务 × 三分支 × 两套规则 × 一次作答和一次独立评价；教学复用确切版本，不能隐藏额外补教调用         |

七次生成链包含规划、生成、核对、必要模拟及修订；沿用现有任务更低的额度，不为用足上限增加角色。单任务期限沿用现有账本，独立审阅保留自己的期限。所有模型准备、评价、失败、取消和结果未知的已发调用都计入批次；调用数、token 与耗时分别记录，不把调用上限称为费用金额。

每次启动一个完整比较单元前检查剩余额度与时长；不够就标未运行。额度不足、取消、结果未知或输入版本变化即停止相应后续阶段。继续使用原批记录和剩余额度，不自动重置或重发未知调用；超过首轮范围的下一周期另立范围。每批输出一份短报告，持续执行时仍向用户说明实际进展。

历史基线可作诊断，正式比较首轮默认禁用答案缓存。之后只在问题、完整协议、材料、规则、模型配置、状态与评价哈希完全一致且记录可核对时复用，报告复用与实发调用；旧验收的六成功／两失败不直接当本轮对照结果。

## 7. 验收与启用规则

先逐项判断，不把分数平均后掩盖严重失败。

| 层面     | 必须满足                                                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 硬条件   | 来源与版本有效；关键事实有依据；假设与观察分开；正文无内部问题编号；失败不导出；已要求且可用的配图不缺失，保留理解所需标签，文字不溢出                                                 |
| 三类产物 | 问题被回应，必要原理／设计理由完整，PPT 主线与稿件相符；每个判断有具体位置，不能靠关键词出现或模型自评通过                                                                             |
| 候选收益 | 至少一个预先指定缺口被解决；其他必需维度无可确认退步；三类留出无阻断失败；不通过则保留基线，不声称改进已发布                                                                           |
| 效率     | 按相同任务分别列实发调用、累计 provider 时间及端到端时间；缓存等待单列；失败基线不作成功提效参照；减少核对或删必要内容不能算提效；新增无收益调用不默认启用，单次耗时变化不宣称稳定提速 |
| 学习试验 | 保存未经助手改写的作答；可见信息与评分材料隔离；分别报告独立、受助、失败／未评价及模型先验限制                                                                                         |
| 工程回归 | 相应测试与浏览器路径通过；本次基线为 148 项测试、十一组浏览器检查，实施后记录实际范围和数量；未定位超时记录继续保留                                                                    |

M2 可以形成范围明确的产物规则改进，M3 的学习结论单独发布。M3 未通过或未完成时，只能说明产物质量的指定改进，不能称已证明学习迁移。

通过门槛后，更新对应有效规则／内部指令与版本并以 Git 提交结束；保存基线、候选、案例／材料／模型／评价版本、实际产物、用量、失败和发布范围。新请求应可核对装载的新哈希；在途任务与历史稿保留原版本。需要回退时新增回退提交，验证未来请求恢复基线，保留原比较记录和 Git 历史。

第一轮交付为：可重复的内部运行入口、一份案例清单、明确的候选比较报告、三类实际产物检查、独立作答试验报告，以及“启用／保留基线”的具体结论。若效果不足，也应交付证据完整的失败报告，避免留下一个被误称为完成的训练循环。

本轮不扩展用户端方案转 PPT、自动阅读截图识别、素材管理、账号后台或复杂跨产物同步；研究能力和教学效果的训练在内部进行。更大材料库、自动采集和长期自动磨合在这一小轮有依据后再安排。
