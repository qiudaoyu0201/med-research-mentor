# 整体方案实施验收

依据：`Skill与工作流驱动的科研学习助手_落地方案.md` v1.0。2026-10-05 本机 07:00 启动；定时任务已停止，避免重复启动。以下分别记录已实施能力、工程检查和实际行为。

## A：标准 Skill 与学习模拟

十个入口均含标准 YAML 名称与触发说明，保留原 ID 与 manifest 兼容旧入口。发现目录只提供名称和描述；后台按任务加载正文，引用限定在对应包内，正文及入口变化进入版本哈希。仍由后台加载，没有声称已启用模型原生自主读取或联网。格式依据 [Agent Skills 规范](https://agentskills.io/specification)。

新增独立学习模拟，保存画像版本、概念状态、真正可见的讲解、实际作答和证据编号。讲过、自述理解及表现为能应用分开记录。评分规则与答案留在验证端；学习者视图只含自己的状态、所见讲解、历史题目与回答。保存后可以恢复同一学生，更换学生不共享状态。失败、未见引用、取消和保存失败不会产生掌握证据。

工程：构建及 54 项测试通过；skill-creator `quick_validate.py` 对全部十个入口通过。验证器的 PyYAML 仅装入忽略的 `runs/skill-validator-lib`，未修改系统 Python。

真实回放：`npm run learner:check -- --live`，GPT-6.1 Sol，与旧试读基线使用同模型和同一缺前提讲解。报告 `0295c457-2d84-4c20-98c3-0d6119767ef2` 保存于 `data/simulation-reports/`，独立学习者输入输出在 `data/simulation-attempts/`，状态在 `data/learners/`；这些运行数据不提交。

| 观察 | 实际结果 |
| --- | --- |
| 已知基础题 | 正确指出接受目标处理的甲组是实验组 |
| 未教虚构规则 | 回答不知道，并询问读数与颜色的对应关系 |

总计 7 次调用：旧试读 1、导师 1、学习者 5；预先上限 7、总截止 480 秒，实际生成耗时合计约 66 秒。输入、输出和可取得用量随报告保存。未教与缺前提阶段的实际文字经人工阅读未出现隐藏规则。

这是一份明确标记的测试用虚构规则和一个固定画像。选择题评分是该任务的行为检查，不能推断医学教学有效性、模拟所有专业知识边界或真人学习效果。旧试读与新模拟的职责不同，不把其输出当作可直接比较的掌握率。历史三页汇报验收失败及 Figure 1m 分母缺依据继续保留。

## B：主助手与按需协作

简短普通背景问题和已交付背景句子的追问由主助手直接解释，输出明确标记“未核验背景”，允许无引用。请求论文事实、数值、正式出处或汇报仍进入资料流程；局部论文追问保留来源核对，默认省去模拟试读，用户可主动要求试读。原完整任务仍保留一次具体修订、每组 6 次／含规划 7 次及 480 秒截止。来源核对指引检查混合段落，不能用 background 标记掩盖论文事实。

追问绑定会话、原讲解段落、真实句子与当前资料版本；伪造句子、跨会话或过期资料在调用前拒绝。规划阶段只提供 skill 触发目录，正文按实际职责加载。普通直接解释不会加载核对和试读指引。

工程：构建及 57 项测试通过，其中新增直接解释／跨轮承接、局部论文核对、伪造来源阻断；其余包括具体修订、取消、版本、来源、预算和历史分母缺口检查。初次新增局部测试误将整篇固定输出套入单段资料包，被引用白名单拒绝；改为单段响应后通过，未扩大白名单。

实际行为：`npx tsx scripts/workflow-check.ts` 报告 `0ecf1e27-ca9f-428b-914d-13e854a9e316`，两轮共 2 次真实调用，每轮 1 次。第一轮解释对照组提供比较基准；第二轮收到真实原句后用植物施肥／不施肥解释，并说明其他条件须相近、有对照不自动证明原因。没有生成假引用或声称完成论文核验。完整输入、输出和账本保存在 `data/runs/`、`data/turns/`、`data/workflow-reports/`，概要在 `runs/workflow-check.json`。人工阅读核查这一背景例子；局部论文路径本阶段采用确定性工程测试，没有再次运行历史三页失败场景，也没有声称真人效果通过。

## C：统一对话与核心体验

页面的功能入口和自由提问现在提交到同一会话，读图、补基础与汇报可以承接；可选择已有对话，刷新恢复已交付讲解。每段支持选中文字或以该段开头发起局部追问，发送简短／例子／深入机制的深度选择。论文与基础引用继续定位实际材料和原页；未核验背景另行标明。

进度来自真实轮次和任务状态；停止调用会话取消接口。失败或停止后已保存草稿可以查看，但标明尚未核对、不可导出。已交付解释与待补材料／影响问题分别可见。历史失败没有因为改善页面而变成通过。

验证：构建和原 57 项工程测试通过；原浏览器套件通过示例、出处、保存、方法、PPTX、PDF 圈选、手机宽度及会话 API。新增 `npx tsx checks/browser-workflow.ts` 在本机 Edge 验证“读图→刷新继续→查看原文→选择句子及深度→停止→保存草稿”。示例走真实本机接口且零模型调用；进度／取消页面采用明确的接口固定响应，验证 UI 传递及展示，不冒充真实生成或真人学习。后端实际取消和停止预算另有工程测试。结果保存在 `runs/browser-workflow.json`；桌面和手机截图分别为 `runs/screenshots/conversation.png`、`conversation-mobile.png`，已经视觉检查，无水平溢出。

## D：逐页修改、版本恢复与导出

汇报保留初始版本，每次改写或保存手动编辑都生成带父版本的新记录。只给改写角色和复核角色目标页及相应真实资料，程序只替换指定页，保留其他页及原图绑定。修改事实内容后复核，阻断问题最多一次具体修订，仍失败则草稿不可导出、旧版保留。用户可比较标题、要点和讲稿，恢复生成新版本，按选定版本导出。普通对话说“修改第二页”承接当前汇报；无汇报时具体请求材料并停止。直接绕过版本接口导出未保存编辑会被拒绝。来源改变也会拒绝过期导出。

工程：构建及 61 项测试通过，新增单页保留、恢复、指定版导出、会话隔离、过期资料、失败、取消、一次修订和自然语言承接。首次负例暴露手动伪造引用未在调用前拦截，已按真实资料列表修复，保留对应测试。所有模型尝试、输入输出、候选页和失败保存；页面修改不运行模拟学生，独立修改上限 4 次、一次修订、480 秒，主助手中的修改共用原轮次账本。

真实行为：`npx tsx scripts/deck-check.ts` 报告 `6170a4bb-98e0-46f0-9585-76a262931387`。2 次调用将第二页改为“衰老细胞会让身体功能变差吗”，保留一起出现不等于导致、干预不证明唯一原因及自动提取未逐段校对的限制。其余七页逐字段一致；八页 PPTX／八页讲稿和恢复快照验证通过。报告在 `data/deck-reports/`，版本及完整调用记录在 `data/deck-versions/`，概要 `runs/deck-check.json`。

浏览器实际手动修改和复核另用 1 次调用，导出文件 1,040,543 字节，恢复后刷新仍为旧版。手机初次检查因选择框撑宽失败，已保存 `runs/browser-deck-first-failure.json`；限制宽度后 `checks/browser-deck.ts --resume-mobile` 零新增调用通过。桌面及手机版本截图已查看。该验证使用八页固定示例为起点，只核对修改页；历史三页内容失败和 Figure 1m 分母缺依据继续保留，不把两个模型角色的同意当作独立事实证明。
