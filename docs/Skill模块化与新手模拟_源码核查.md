# Skill 模块化与新手模拟：源码核查和方案纠正

日期：2026-10-05 · 本地代码基线：`c59565e` · 本轮：源码核查与文档修正，未实现模拟环境

本记录的结论已汇入[科研学习助手整体落地方案](Skill与工作流驱动的科研学习助手_落地方案.md)。后续实施以总方案为准，本文件保留源码依据与纠正记录。

**之前没有接入 TinyTroupe、CAMEL 或 Generative Agents。现有程序有讲解、试读、核对三个角色的调用流程；“新手”主要检查讲解是否容易理解，尚未实现并验证一个持续学习的新手模拟器。此前没有明确这个区别，容易使人误以为后者已完成。**

## 1. 哪些做对了，哪里做偏了

现有 PDF／图件读取、来源定位、会话保存、调用预算、修订和 PPTX 导出都可以继续使用。按不同职责调用同一个强模型，也是可行的角色协作方式，不必为每个角色重新训练模型或从零建设资料库。

偏差在于：把“模拟试读意见”当成了新手模拟的主要实现，却没有先定义它的知识状态、学习行为和验证办法。已有工程与内容检查不能证明模拟新手符合真实学生的行为，也不能证明使用者学会了。

| 核查对象 | 当前源码实际行为 | 判断 |
| --- | --- | --- |
| `server/skills.ts` | 按功能选指引，读取 `SKILL.md` 与 `manifest.json`，记录版本哈希 | 已有提示词模块加载；不是模型自主发现、分层读取的标准 skill 运行方式 |
| `skills/medical-novice-simulator/SKILL.md` | 要求只按画像和可见讲解试读，不把模型已有知识当成学生基础 | 已有软性知识约束；尚未验证约束是否可靠 |
| `examples/bundle.ts`、`shared/types.ts` | 画像是背景和困难描述；试读输出 `understood` 与 `breakpoints` | 是试读反馈，缺少概念级知识状态与作答记录 |
| `server/orchestrator.ts` 的 `visibleInput` | 只提供画像、问题、可见讲解／图注、已教概念和先前断点等 | 输入隔离可复用；隔离材料不能删除模型的预训练知识 |
| `server/assistant.ts` | 从讲解中的术语列表保存 `taughtConcepts` | 记录“讲过什么”，不能据此标成“模拟学生已掌握” |
| `server/provider.ts` | 每次创建临时会话，关闭搜索、文件和动态工具；后台传入材料与指引 | 模型能力仍在，但历史必须实际传入；新增指引不会自动获得工具能力 |

以上是对当前代码的核查。历史工程测试和四场景验收记录仍按[原验收文档](基础资料迁移与四场景验证_验收.md)保存；三页汇报的失败没有因本次核查变为通过。

这里的区别不是“用了框架才算多 agent”。我们已有轻量角色协作；但要声称模拟学习过程，就需要明确维护和观察这个过程。是否采用现成框架，是实现选择，不能代替效果验证。

## 3. Skill 模块化应该怎样做

skill 是可复用的工作说明；角色是带职责、输入和状态的模型调用；环境负责决定各角色看到什么、怎样传递消息、保存状态及何时结束。三者配合使用。skill 文件可以规定模拟规则，实际输入隔离和状态保存仍需运行程序执行。

按官方说明和开放规范，标准 skill 目录以带 `name`、`description` 的 `SKILL.md` 为入口。运行时先提供名称和触发说明，匹配任务后加载正文，再按需读取参考资料、脚本或模板。无需为简单工作流强行增加脚本。[OpenAI skill 编写说明](https://developers.openai.com/plugins/build/skills)、[Agent Skills 规范](https://agentskills.io/specification)

本项目现有文件缺少标准 YAML 入口元数据，元信息放在外部 `manifest.json`。它们是有效的内部提示词模块，但要作为标准 skill 包移植，需补入口元数据、校验相对引用，并接入支持这种加载方式的运行时。格式符合规范与实际执行有效，应分别验证。

后续模块组织保持简洁：

| 模块 | 核心职责 | 需要的输入 |
| --- | --- | --- |
| 主助手 | 持有目标、选择工作流、整合结果、决定停止 | 当前材料、任务进度、相关历史和未解决问题 |
| 讲解／读图／汇报 | 用强模型正常组织教学和产物 | 当前目标、来源、已确认解释和所需专业指引 |
| 新手试读 | 检查表达是否容易理解 | 用户可见内容与明确背景；结果标作模拟意见 |
| 新手学习模拟 | 在指定知识状态下复述、应用、提问 | 测试画像、实际可见讲解、相关交互历史；不含评分答案 |
| 来源核对 | 判断具体事实、引用和推理是否有依据 | 候选内容和原始来源；不从学生自述判断事实 |

试读与学习模拟的目标、输入和验收不同，后续应分开。主助手和讲解角色继续发挥模型已有知识；模拟学生的知识边界只用于相应测试角色。资料库用于复用已取得材料和核验记录，不是模型通用知识的上限。

## 4. 本项目最小的新手模拟环境

先做“一个导师＋一个指定画像的新手＋按需来源核对”的文本交互。不需要先搭小镇、十几个角色或新的庞大知识库。开发测试可换几个固定画像；实际使用者不必每轮参加测验。

下面是待实现设计，不是当前运行能力：

1. **定义起点。** 记录本任务相关的已知概念、未知概念、明确指定的误解。没有依据的误解不自行编造；测试画像与真实使用者记录分开。
2. **控制所见。** 导师能看原文，模拟新手只看呈现给学生的讲解、图件、图注及相关历史。环境不把隐藏评分答案或核对报告传给新手。
3. **观察行为。** 新手给出简短复述、对一个新例子的回答或具体疑问，允许答对、答错或说明不知道。不要求每轮必须找错，也不索取隐藏思考过程。
4. **按证据更新。** 保存讲过的内容、实际回答与评分结果。只有观察到相应表现，才更新“在本次任务中表现为掌握”；自述“懂了”和出现术语不自动升级知识状态。
5. **承接下一轮。** 传入更新后的相关状态和历史，观察同类新问题的表现。先保留现有一次修订与预算上限；未改善就记录具体问题并停止。

持久化只需先覆盖：画像版本、概念状态及其依据、实际见过的内容、交互／作答记录。已有会话与任务存储可复用，不先建设完整认知架构。

通俗例子：测试学生知道“实验组和对照组”，却没学过 Ct。导师只说“Ct 下降说明表达增加”。模拟学生是否追问 Ct 的含义，是一个观察点。补讲后，让它解释另一个新例子，才有新的行为证据。如果补讲前就能熟练说出所有未提供的专业细节，应检查模型是否越过了指定知识边界，而不是直接宣布讲解成功。

**限制知识是模拟行为约束，不能真正删除预训练知识。** TinyTroupe 的人格提示也采用这种约束；将它用于本项目仍需测量越界情况。概念状态和评分都应按当前任务解释，不冒充真人学习测量。

## 5. 怎样验证，而不是让几个角色互相宣布通过

先用固定材料做小规模对照：相同模型、相同画像与任务，比较现有试读和候选模拟。若要采用 TinyTroupe，再单独跑适配原型，以相同条件比较；本轮没有这项实测。评分参考与测试答案只给验证端，完整输入、输出、状态变化及用量留档。

| 检查 | 可观察结果 |
| --- | --- |
| 信息隔离 | 新手输入不含原文隐藏段落、评分答案和核对报告；做输入审计 |
| 知识越界 | 未教／未指定掌握的任务细节是否被直接使用；记录具体输出和越界比例 |
| 讲解是否起作用 | 完整讲解与刻意缺关键前提的讲解是否出现合理差异，允许无差异并记失败 |
| 状态是否真实更新 | 仅记录“讲过”或自称“懂了”不能升级；更新须能回到实际作答依据 |
| 是否承接学习 | 下一轮能使用已观察到的内容；更换测试学生时不能串入另一个人的状态 |
| 是否装傻／乱找错 | 明确已知且材料充分的基础题可答对；不为了像新手而固定出错 |
| 是否接近目标使用者 | 请目标使用者判断少量代表性回答，逐步与真实反馈比较 |

程序测试可以验证隔离、保存和状态更新规则；模型行为需要实际回放。模型自评可辅助定位问题，但同一模型的互相赞同不是独立验证。没有真实使用者对照时，只称“用于教学检查的模拟”，不声称准确复现真人学习。

## 6. 使用者真正需要做什么

你负责决定要帮助谁、希望完成什么，以及试用后指出哪里不自然。提示词、skill 包装、环境实现、记录和测试由开发方负责，不需要你学框架或替开发方设计角色系统。

先沿用已有讨论作为工作假设：有医学基础、科研方法刚入门；希望读懂论文图和推理，能解释给别人并整理汇报。这是可调整的测试起点，不是对你个人知识的诊断。先使用已有材料，不要求重新整理一整套资料库。

当有可运行样例时，你只需看几条有代表性的学生回答，指出“像我会问的”“这里明明会”“这里仍没懂”。若以后要宣传对某类真实学生有效，再需要相应使用者的反馈和验证数据。

## 7. 修正后的实施顺序

先把目标定义和验收补清楚，再实施一个可见的纵向样例：标准 skill 入口及加载 → 明确的新手状态 → 导师讲解 → 新手实际作答 → 有依据的状态更新 → 下一轮复用。先证明这条链能工作，再扩大到不同画像和其他页面功能。

采用 TinyTroupe 可以作为候选适配路线，不能仅因它有“simulation”字样就立即替换现有系统。当前建议先复用已有模型接入和存储，借鉴其状态与验证设计；若最小原型显示需要现成环境功能，再比较接入成本与行为效果。这是本项目的工程判断，尚未实测选型。
