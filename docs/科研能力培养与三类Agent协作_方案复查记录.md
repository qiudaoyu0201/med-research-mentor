## 1. 本版判断与复查方法

最终架构是主体科研学习助手加并列的 PPT／研究方案专区，仍为助手、小白、校验三类角色。内部利用大模型已有能力、经核查的成熟 Skill 和长期积累的多论文案例，分别改善助手产物能力与检查教学后的学习迁移；用户端使用有效能力，进行轻量核验。

复查对照了完整讨论和最后三次澄清、v1 原方案、首轮实施验收与实际代码的类型／状态边界。逐项核对 R01–R39、F01–F11、T01–T39，再检查输入隔离、质量与学习证据、在线与内部政策、版本、调度、缓存、导出与调用总账。最后检查文档链接、格式、编号、交叉引用与 Git 差异。

## 3. 成稿复查发现并回写的关键遗漏

1. **不能把“小白学会”当作助手生成能力的唯一指标。** 增加内部闭环 A、B 和 evaluationTarget，方案与 PPT 都分别测产物、教学和独立行为；明确助手产物失败不能被学生表现覆盖。
2. **看完目标示范再作答不能叫独立迁移。** 分开先前案例教学与目标课题答案，保留作答前快照和独立原稿；反馈后同题答对归纠错，再迁移另题。
3. **单篇论文到任意新课题的假设过强。** 加入长期多论文／方法案例库和能力单元，局部例子标范围；开发／留出按研究系列及来源簇分开，不拿同论文不同 panel 当独立留出。
4. **用户端不应复制内部严格训练。** 默认方案／PPT 为助手＋轻量校验 2 次，修订后 4 次；小白理解检查按需用 3／6，不默认考试、留出或高分门槛。
5. **原默认正式导出门槛会妨碍实际使用。** 普通保存与草稿导出不受内部评分限制，核对范围和待确认项准确呈现，不能把未知或事实错误标已通过。
6. **PPT 讲述与独立组织能力有区别。** 新增独立结构／讲稿任务，目标助手 PPT 隔离；已见讲稿的复读不算独立制作迁移。
7. **现有单论文和选择题合同不能直接承载新功能。** 明确 Topic、多来源 TaskContext、开放任务判别 schema 与迁移位置；前后端同批扩展，不强转类型或伪造论文。
8. **共享机制也可能混用线上与内部报告。** 报告／缓存加入 reviewPolicy 与 evaluationTarget，内部权限服务端控制，用户不能提交已掌握／已核对状态自证。
9. **追加模式可能漏计学习、候选与评价开销。** 按实际节点核算，并给 41 次基础、最多 53 次含指定补教的首批预占例；剩余审阅和双条件还计入 64，未运行不算完成。
10. **方案改完后 PPT 不能自动覆盖。** 明确上游版本引用、影响提示、显式同步产生新版本，反向回写也需选择内容。
11. **已有功能状态必须更新到实际基线。** 将 v1 的待实现意图／兼容接口改为首轮基础已交付；开放小白、专区、完整磨合、真实国内与真人验收仍列待办，保留历史失败。
12. **新方案不能让历史依据失真。** 归档 v1 方案／复查，首轮验收改指归档，README 最新入口清楚说明只是文档更新。

## 4. 四条闭环交叉核算

| 内部路径               | 最小生成链                     | 含一次纠错／修订                   | 不能据此推出                         |
| ---------------------- | ------------------------------ | ---------------------------------- | ------------------------------------ |
| 助手研究方案能力       | 助手生成＋校验 = 2             | 助手修订＋校验，共 4               | 学生独立设计已会                     |
| 助手 PPT 能力          | 助手生成＋校验 = 2，程序另渲染 | 修订＋校验，共 4；模型视觉审阅另计 | 小白可以独立组织 PPT                 |
| 小白方案／PPT 独立迁移 | 小白独立输出＋校验 = 2         | 助手补教＋小白修订＋校验，共 5     | 同题纠错证明再次迁移或真人学习效果   |
| PPT 汇报／首次听众诊断 | 助手＋汇报者＋听众＋校验 = 4   | 同条件完整修订，共 8               | 每位用户都必须跑此链或独立制作已通过 |

未学习分支另 2，实际学习、候选、准备、新问题、独立审阅另计。在线默认 2／4 或按需 3／6，含一次规划的总上限 7；内部组与总批次 64 分开。原有 480 秒在线截止与两槽资源继续，新增模式需真实实现验收。

内部产物能力提升和学习迁移收益分别报告。可以先发布已验证的生成能力，同时准确保留教学迁移未验证，不能为了“闭环”把未证实能力写成完成。
