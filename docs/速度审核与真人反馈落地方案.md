# 速度、审核与真人反馈落地方案

## 1. 目标

当前版本的核心流程已经具备：导师 Agent 组织讲解或产物，新手模拟 Agent 检查是否容易理解，来源核验 Agent 检查事实和证据，调度器负责顺序、预算、取消、恢复和记录。本方案不删除这条闭环，而是把它改成适合日常使用的分级流程：常见任务更快交付，重大错误仍然阻断，失败后可以继续修订。

目标是让用户在大多数普通任务中一次得到可用结果，同时让医学事实、实验对照、图表含义、研究结论和方案可行性保持可靠。

## 2. 用户流程分级

### 2.1 普通交付模式

普通带读、一般的 PPT 和初步研究方案采用轻量流程：

1. 调度器读取已确认的论文文本、图表索引、来源指纹和用户要求。
2. 可并行的工作同时进行，例如图表清单、术语清单和证据定位。
3. 导师 Agent 生成初稿。
4. 新手 Agent 和来源核验 Agent 只检查与本次任务有关的关键部分。
5. 没有重大问题就交付，并把次要问题作为结果旁的简短提示。

普通模式不要求每个段落都完整执行三 Agent 串行闭环，也不重复检查已经确认且未变化的来源。

### 2.2 严格模式

以下情况进入严格模式：用户明确要求精读、准备向老师汇报、要求逐图逐表核对、生成正式研究方案，或系统发现核心证据不稳定。严格模式保留完整的导师→新手→核验→导师局部修订→复核流程，并记录每个阻断问题。

### 2.3 审核结果分级

审核结果不再只有“通过”或“打回”：

1. 阻断错误：来源不存在、数字或方向错误、把假设说成结果、虚构图表、缺少决定性对照、研究方案遗漏关键可行性或安全条件。必须修订后才能交付。
2. 警告问题：创新表述略强、术语缺少直接引用、局部解释不够完整但不改变结论。允许交付，在对应位置给出一句提示。
3. 编辑建议：版式、措辞、段落长短、讲稿节奏。直接交付，作为后续可编辑建议。

审核 Agent 应返回具体位置、问题类型、证据和建议动作。只涉及一个页面或一段文字时，调度器只重做局部，不重生成整份成果。

## 3. 速度优化

1. 证据缓存：论文版本、图表索引、已核对术语和来源摘录按来源指纹缓存。论文未变化时不重复解析。
2. 并行准备：文本分段、图表识别、来源索引和用户要求整理并行运行；只有依赖前一步结果的生成阶段保持顺序。
3. 有界核验：普通任务只核验影响当前结论的来源；严格任务才扩展到全篇和全图表。
4. 局部修订：审核返回页面、段落或结论编号，修订只覆盖相关单元，并重新检查受影响证据。
5. 有限续接：网络或上游模型中断时，在同一任务记录上进行有限次数续接；不重复扣除已完成阶段，不把未知结果自动当作失败重发。
6. 可见进度：界面明确显示提取、生成、核验、修订和导出阶段，并保留“取消后重试”和“编辑要求”入口。

速度优化的原则是减少重复工作，而不是删掉决定可靠性的步骤。

## 4. 失败与恢复

系统将失败分为四类：

1. 网络或模型连接失败：保留输入、已完成的 Agent 结果和调用记录，提供有限重试。
2. 内容核验失败：保留初稿和审核意见，进入局部修订，不丢失用户要求。
3. 材料不足：直接说明缺少哪一页、哪张图、哪段方法或哪个约束，允许用户补充后继续。
4. 程序错误：保存草稿和错误上下文，允许恢复或重新开始，不生成伪造的成功结果。

用户看到的提示应说明“发生了什么、已有内容在哪里、下一步能做什么”，而不是只显示“生成失败”。

## 5. Skill 训练与内部迭代

Skill 训练继续采用“小样本定位问题、完整论文检查连贯性、跨功能验证迁移”的组合：

1. 小样本测试术语解释、图表读取、对照识别、来源绑定和失败恢复。
2. 完整论文测试带读主线、PPT 页面与讲稿、研究方案的完整性。
3. 三类产物交叉检查背景、实验设计、对照、结果、局限和来源是否一致，但不能用产物互相一致替代原文核验。
4. 模拟新手使用 PPT 或研究方案完成任务，暴露理解断点；导师补教后，再换条件验证迁移。
5. 只有在候选相对基线没有退步、阻断错误下降且迁移条件通过时，才发布新的 Skill 版本。

内部迭代始终严格执行完整审核标准。并行、缓存、局部修订和阶段复用只减少等待，不减少导师、新手、来源核验、交叉验证或迁移验证的必要检查；内部候选不能因为“用户模式可交付警告”就算通过。在线交付才按上面的分级审核执行。训练记录必须保留模型、材料、版本、预算、失败类型和最终决定，不能把一次成功样本直接当成 Skill 已经普遍变好。

## 6. 真人反馈回流

用户在其他 Agent 上阅读论文、调整讲解、修改 PPT 或打磨研究方案后形成的记录非常有价值。它们不是“随口意见”，而是能帮助训练 Skill 的真实使用信号，但需要结构化整理后才能安全使用。

建议每条反馈尽量包含：

1. 任务类型：带读、图表解释、PPT、研究方案或术语。
2. 原始要求和原回答片段。
3. 用户做了什么修改，为什么修改。
4. 修改后的理想表达或页面效果。
5. 问题类型：事实错误、证据不足、讲解难懂、顺序不佳、过于冗长、排版问题或审核过严。
6. 论文页码、图表或来源位置；没有来源时标记为个人偏好。
7. 这条反馈适用于所有论文，还是只适用于某一篇论文。

可以直接提供聊天记录、前后版本、截图、PPT 页面或研究方案草稿。我会先把它们整理成“偏好”“可复用规则”“案例测试”“待验证假设”四类，再进入小样本回放；不会把单次个人偏好直接改成全局规则，也不会把未经核对的内容写进 Skill。

## 7. 第一阶段实施顺序

1. 先实现审核分级和普通模式的局部交付。
2. 再实现来源、图表和术语缓存，以及断线续接。
3. 然后补齐 PPT 与研究方案的局部修订和失败恢复。
4. 最后建立真人反馈导入格式，并用真实反馈跑小样本回放和迁移验证。

每阶段都要通过工程测试、隔离环境真实运行和一次人工抽查后再进入下一阶段。主线保持稳定，所有改动先在开发分支验证。
