# 医学科研导师：需求访谈基线

日期：2026-10-09。状态：访谈阶段基线，尚非最终实施方案；本次仅整理需求，未改变产品代码、有效 Skill、模型配置或运行账本，未启动付费迭代。

本文记录本轮用户明确表达的目标和修正，供后续优化方案追溯。新访谈要求与旧方案冲突时，不再把旧方案当作用户不可改变的偏好；实际运行仍是原版本，只有实施和验证后才可更新完成状态。

## 1. 记录规则与核心判断

- “已确认”表示用户明确要求或认可；“自主设计”表示用户把常规技术、体验和迭代判断交给执行者；“待验证”不能写成已完成。
- 用户希望全面访谈，但不希望被迫决定页数、裁图、模型评价公式等实现细节。追问应聚焦真实目标、关键取舍和尚不明确的偏好。
- 用户本科刚进课题组，老师要求读论文，学习研究思路与方法；面对论文往往无从下手。
- 用户主要依据当前示例展示感到不满，尚未完整实际使用本智能体。不能把示例印象写成系统性真人试用结论。
- 用户使用过通用 Agent 的较好讲解，但尚未做同论文、同目标的严格对照。独立应用必须证明相对“直接在 Agent 中使用 Skill”的实际收益。
- 全产品服务医学及医学相关科研入门者。非医学不作为本阶段优化重点；覆盖医学不同研究类型，不等于所有类型已经验证。
- 主要价值：不用反复教 AI 如何教学，小白能理解，讲解连贯，可对照原文，逐步培养实验设计思维和科研能力。
- 产品轻重：导师式论文带读是核心；PPT 与研究方案是省事、稳定的辅助生成专区。学习与交付都重要，不要求每个功能都承担教学职责。

## 2. 已确认需求清单

### 2.1 论文导师与教学方式

| ID | 已确认需求 |
| --- | --- |
| T01 | 初次导入先讲背景、目的、价值和整体关键内容，再直接开始第一部分，不强制再确认一次。 |
| T02 | 大体沿论文顺序带读，在重要问题、方法、实验、图表和推理处展开。 |
| T03 | 讲清研究背景、问题、实验目的、方法原理、分组对照、实际结果、图表读法、证据如何支持结论及研究启发。 |
| T04 | 关键专业术语提供中英对应，帮助熟悉科研英文，不把带读变成逐句翻译课。 |
| T05 | 一次可讲完整问题或实验，过长时合理分段；应支持希望一次读更多的人，不固定切成碎片或强迫频繁“继续”。 |
| T06 | 讲解有清楚排版、小标题、短段落和必要强调、表格；优先连贯可读，不机械堆卡片和模板。 |
| T07 | 基础讲到理解当前研究所需的程度，主动补必要前提，适度收敛。 |
| T08 | 方法默认侧重原理、用途、测量对象、对照和结果解释，适度涉及关键操作；不默认提供完整实验室操作培训。 |
| T09 | 对方法选择及替代方法适当比较，帮助理解研究设计，不无限扩展方法百科。 |
| T10 | 首次遇到一种图详细解释，后续同类图减少重复、聚焦数据与结果意义。具体坐标、单位、分组等变化仍需说明。 |
| T11 | 多面板图先讲整体研究问题，再解释相关小图，最后连接证据。是否全部涉及次要小图尚未逐项确定，由内容目标判断。 |
| T12 | 在关键处总结问题—方法—对照—结果—结论，并适度点出可迁移的设计思路，不每段套相同总结。 |
| T13 | 练习可选，不成为继续阅读的门槛；不要求用户参加考试证明掌握。 |
| T14 | 发现误解时直接、具体地纠正并解释原因，不迎合、不说教。 |
| T15 | 适度批判论文，服务科研思维；缺口在相关位置说明，不为免责反复提无关紧要的小问题。证据不足时明确不能支持的结论，其他可讲内容继续。 |
| T16 | 允许相关延伸讨论，及时收住，不因追问长时间偏离学习目标。 |
| T17 | 允许导师自主按需联网查补充资料，围绕当前疑问收敛，不每轮机械检索。论文事实与外部背景材料保持区别和可追溯性。 |
| T18 | 追问后可提醒原来的主线位置，并询问是否接回；避免每次固定重复同一句提示。 |
| T19 | 对话中要求“详细一点／简单一点”影响后续讲解，用户可继续调整；设置提供新论文的先行默认程度。显式限定本句的请求应保留其局部意图。 |
| T20 | 只需适当说明现在讲什么、下一步讲什么，不建设复杂课程路线。 |

### 2.2 原文联动、引用追问与保存

| ID | 已确认需求 |
| --- | --- |
| R01 | 中文讲解为主，原文按需联动，不要求持续分屏。 |
| R02 | 讲到具体图或段落时提供明确入口，打开后能定位和看清对应内容，同时方便保留／回到讲解。 |
| R03 | 提供当前相关原文或图注的中英对照，不默认整篇双语翻译。 |
| R04 | 不给每段强制配图；优先做好正文排版，按实际帮助采用图文结合。 |
| R05 | 用户不承担反复截图裁图的常规工作；实现优先复用 PDF 文本和位置，复杂定位的准确性需实测。 |
| R06 | 类似 Codex：选中回答中的句子／段落，引用到输入框，自由加问；保留回答与论文上下文，发送前可取消引用，回答优先围绕选中内容。 |
| R07 | 回答引用追问与 PDF 原文选字翻译／解释分别设计和验收，不只做其中一个。 |
| R08 | 关闭、重新打开后保留对话和位置，用户说继续就继续；不自动插入复习或重新收费起读。 |
| R09 | 跨论文适度记住讲过的基础、降低重复程度；不把讲过当作掌握，不建设沉重学习档案。 |
| R10 | 不建设专门笔记系统；支持方便复制回答。用户提到可稍作编辑，具体编辑位置仍待设计，不据此扩展笔记专区。 |
| R11 | 全文结束时总结留在对话末尾，方便回看，不建设独立总结管理专区。 |

## 3. 内部三 Agent 与自主迭代

### 已确认的授权与方向

- 沿用助手、模拟小白、校验三角色，继承已有开放式作答、材料快照、候选比较和迁移验证基础，不另起一套概念。
- 导师能力改善为中心，三个功能可交叉闭环验证与优化。产品端保持独立入口，内部交叉不意味着增加用户端方案转 PPT 等流程。
- 模拟小白采用多种基础与误解方式，具体画像由执行者设计。
- 执行者自主选择案例、定位问题、提出 Skill 候选、比较、决定启用和回退，不逐轮把技术判断交回用户。
- 用户希望充分内部迭代后再参与真人体验，不把真人先验收当成每轮执行前提；未做真人验证时不得宣称证明真人教学效果。
- 用户愿意投入调用，重点控制单次成本、无效材料和冗余往返，不要求刻意压低总调用来省事。执行者分批设计预算与收益检查，不解释为无限调用或无限购买授权。
- 当前只是需求与方案整理；上述授权尚未触发实际付费实验或运行账本变更。

### 后续方案应实现的验证链

1. 固定医学案例、模型和实际材料范围，保留旧版基线。
2. 助手实际教学；模拟小白依据可见教学追问、复述、解释实验、组织汇报或提出设计。
3. 校验回到原文与实际产物检查事实、推理、理解缺口和文件质量，不能只看模型自报理解。
4. 根据具体、重复的缺口修改 Skill 或材料组织策略，冻结候选。
5. 同条件比较，并用未参与修改的新论文／新问题检查迁移与退步。
6. 合格候选更新有效规则、版本并验证实际新请求加载结果；保存候选不算发布。
7. 记录真实消耗、耗时、失败、未知状态与采用理由；持续无收益、严重退步或服务异常时诊断，而非无限续跑。

跨功能一致不自动构成独立证据：PPT、讲解、方案可能重复同一错误。分别核查产物能力、模拟学习表现和真人效果。模拟小白本身有模型先验知识，应使用同条件控制，避免将其原有能力归因于教学。

这是教学 Skill／材料组织／协作流程优化，当前不是模型权重训练。参赛时可展示已实际运行的机制和有证据的效果，不把计划功能写成既成能力。

## 5. 对旧版本的改动方向与待核实问题

| 现状／旧偏好 | 新方向 | 尚需实施判断 |
| --- | --- | --- |
| 专门笔记、学习记录和管理入口较多 | 简化为复制和必要资料管理 | 旧数据保留与历史可访问方式 |
| 应用内 PPT 编辑、裁剪、版本交互 | 用户侧收束成生成／下载专区 | 后台质量检查可复用哪些能力 |
| 普通 PPT 默认完整演讲稿，备注写稿 | 独立简洁讲述提示，不进入 PPT | 导出合同和历史文件兼容 |
| 研究方案多轮修改、恢复、核对编辑器 | 输入后一次生成完整草案 | 保留失败恢复，减少前台状态负担 |
| 按字符片段组织带读 | 优先完整研究问题和实验叙事 | 新组织策略与论文顺序、范围记录怎样结合 |
| 有 PDF 跳页／选字基础 | 对应位置可读、当前中英对照、引用追问自然 | 定位准确率、长文排版和复杂图表需实际验证 |
| 教学主要依赖预置／上传材料 | 允许按需联网补充基础理解 | 检索适配、全文获取、缓存与证据区分 |
| 部分迭代／验收脚本直接依赖 Codex | 逐步统一提供方接入 | 历史请求恢复与新模型不能混用 |
| 保存已评审候选 | 验证有效规则启用与回退 | 完整比较、加载版本和发布流程 |

这些是待落实方向，不是代码已改的声明。旧实现中的保护机制应判断后简化，不能为了界面简洁直接删除来源、保存、取消、有效版本或真实失败记录。
