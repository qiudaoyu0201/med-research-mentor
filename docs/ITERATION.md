# 内部迭代运行约定

公开版本以本文件作为新实验的方案哈希依据。旧版本记录绑定旧方案和执行器，不更改其哈希、费用或未知状态；迁移后建立新实验，不能将旧记录伪装成当前实验继续执行。

1. 明确本轮学习目标、论文来源、角色可见材料、模型配置、调用预算和停止条件，冻结 Skill 基线与候选。
2. 用小样本定位解释、证据、图表和实验设计问题，再用完整论文检查带读连贯性、PPT 排版与研究方案完整性。
3. 使用实际生成的至少两类产物和原始来源交叉核验；变更产物后重新核对，不接受旧版本通过结论。
4. 模拟新手独立作答，核验断点；需要时导师补教，新手修正，然后在改变条件的新任务验证迁移。
5. 区分有效失败、无效评估和传输未知。未知请求不自动重发，恢复必须有绑定当前记录的证据。
6. 候选只有经过比较、复验和规则发布流程才用于在线服务；保存调用与费用记录，不把模拟学习表现宣称为真人效果。

运行入口是 scripts 中的内部实验命令。仓库保留 evals 中的用例定义，但带日期的 campaign JSON 是历史配置样板，引用的 runs 文件不随仓库分发。必须提供自己的论文与新实验记录，不能直接把这些配置当成可重放的真实实验包。模型实验会产生服务费用；工程测试不等于模型内容质量验证。

## 耗时与阈值校准

运行时间分成两层：测试目标是软标准，超出后记录偏慢并继续等待；保护上限是硬标准，只有它、明确服务失败或用户取消才终止。两者都是可调整参数，不是 Skill 质量真理。新模型、提供方、材料规模或流程变化后，先用有预算的小批真实调用检查首段等待、正文最长停顿、单次耗时及整轮耗时，再分别校准目标与保护上限；不要把测试目标直接当中断门槛。

按模型、通道、任务规模和角色区分样本，按调用 ID 去重。成功请求提供完整耗时；被截断的请求只有观察下限，不能作为“正常耗时”或 Skill 内容失败混入统计。样本不足时保留临时值与不确定性，不声称已经找到最佳阈值。新日志的 `firstMeaningfulOutputAt`、`lastMeaningfulOutputAt` 和 `maxOutputGapMs` 可帮助识别真实输出间隔；历史缺项代表未记录。

内部通过 `TUTOR_INTERNAL_*` 或实验显式 `budget.timing` 调整，保存本轮实际时限与总期限。内部多层计数继承上游计时与取消，不另开相冲突的短计时器。每轮只调整有证据支持的参数，继续保留调用预算、人工取消和有限总期限；传输未知不自动重发，未完成核验不算通过。

候选迁移到在线使用时，重新观察真实用户任务，在线通过 `TUTOR_ONLINE_*` 单独校准。内部追求的速度目标不能直接变成在线中断门槛，延长等待也不能替代 Skill 优化、放宽审核或证明模型服务稳定。
