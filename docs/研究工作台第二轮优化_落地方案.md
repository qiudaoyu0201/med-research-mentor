# 研究工作台第二轮优化：落地方案

版本：v1.3 · 日期：2026-10-05 · 代码基线：`574b10d`

状态：用户已授权实施。A 阶段聊天与调度已通过工程验收；B、C、D 核心能力已实现并完成工程与实际模型样本检查，详见[第二轮 BCD 实施验收](研究工作台第二轮BCD阶段_实施验收.md)及[第二轮 A 阶段验收](研究工作台第二轮A阶段_实施验收.md)。E 的目标用户试用尚未完成，实际模型样本不代替真人观察。

本方案更新[论文研究工作台与 PPT 专区落地方案](论文研究工作台与PPT专区_落地方案.md) v1.2。两份方案冲突时以本方案为准；[首轮实施验收](研究工作台首轮实施验收.md)继续记录已经交付的能力。本轮重点是单论文聊天、材料连续补充、工作台内 PPT、句子引用、讲解深度和可调整布局。

## 1. 已确认的产品安排

| 事项 | 本轮约定 |
| --- | --- |
| 论文与聊天 | 一篇论文对应一个主聊天；上传 PDF 自动创建并进入新论文聊天 |
| 并行 | 最多两个聊天同时生成回答；同一聊天顺序执行，其他发送进入可取消队列 |
| 工作不中断 | 生成时仍可切换论文、阅读、编辑笔记、输入草稿和准备附件 |
| 附件入口 | 输入框内有文件、图片按钮，支持拖入和粘贴图片，发送前可查看和移除 |
| 检查时机 | 内容解析和用途检查在发送后进行；空文件、明显超限等廉价检查即时提示 |
| 引用 | 鼠标选择一句、几句或部分文字后引用提问，以实际选区为准 |
| 讲解程度 | 按“简单点、详细点、从基础讲、重点解释机制”等自然要求调整 |
| 来源与引导 | 起点围绕真实研究问题、方法和结果；回答能回到对应句子、图和图注 |
| PPT | 当前前端里的专区，沿用视觉和材料上下文，承接生成、预览、修改和导出 |
| 页面入口 | 移除布局示例入口；PPT、设置和个人记录等主要操作留在当前前端 |
| 布局 | 拖动区域分界调整大小，记住结果，可恢复默认布局 |
| 文案 | 减少重复限制、能力声明和无用提醒；必要证据边界在相关位置说明一次 |

课题归组、显示名称、原始题录、笔记依据、版本核对和导出能力沿用现有安排。

## 2. 一篇论文一个聊天

### 2.1 PDF 导入

PDF 上传成功后，创建论文记录和主聊天，自动进入这个聊天。解析过程与结果显示在该聊天中；解析期间可以浏览其他论文或输入问题。问题需要正文时等待材料就绪，解析失败时显示对应材料的处理入口。

输入框中的 PDF 附件随发送上传，上传成功后进入新论文聊天，并把本次问题带入。从导航导入 PDF 则直接上传并创建聊天，无需先发送一句话。拖入遵循所在入口的行为，放下后明确显示待发送附件或新论文导入状态。

当前论文聊天里上传另一篇 PDF，开启另一篇论文聊天。原聊天的输入草稿、引用、记录和阅读位置分别保存。补充图片及其他已支持的材料仍归属当前聊天，不清空讨论。

### 2.2 恢复与历史

- 点击论文恢复其主聊天、草稿、阅读位置、笔记和关联汇报。
- 新交互取消“一篇论文中新建多个讨论”的入口。
- 旧论文已有多段讨论时，先以最近使用的讨论作为主聊天；其余历史记录保留并可回看，不自动拼接成新上下文。
- 课题归组与重命名保留记录 ID、原始题录及来源关系。
- 上传重试使用同一提交标识，避免因网络重发重复创建论文和聊天。再次主动导入同一 PDF 如何合并，留待重复导入能力实施时确定。

## 3. 并行与操作可用性

并行上限按本机服务实例计算：**两个聊天生成任务**。一个任务包含该问题的作答、核对及必要修订，不按内部模型调用次数占多个名额。PPT 生成或模型修改也占一个名额；同一论文聊天及关联 PPT 的模型任务依次执行。

| 情况 | 行为 |
| --- | --- |
| 有空闲名额 | 就绪任务按入队顺序开始 |
| 两个名额已占用 | 新任务显示“等待中”，允许取消 |
| 当前聊天正在回答 | 下一条问题进入该聊天队列，不交错生成 |
| 附件仍在处理 | 依赖附件的任务等待材料，不占生成名额；其他聊天可先执行 |
| 切换论文或页面 | 已提交任务继续，状态归属于原聊天 |
| 取消等待任务 | 移出队列，保留可编辑的问题和附件 |
| 取消执行任务 | 取消该任务及其后续步骤，释放名额，保留已产生记录 |

队列保存本次问题、选区、附件 ID、论文及来源版本。执行时承接同一聊天此前已完成的回答；切换页面不改变任务归属。若等待期间所引用材料发生变化，显示需要更新的具体材料。

刷新页面后恢复服务端任务状态。后台重启后，未完成任务标记为中断，由用户决定重试，不自动重复模型请求。

文件上传、解码、解析和本地编辑不占回答名额；需要模型的用途检查纳入同一调度。解析任务使用单独的资源限制，避免大量文件同时处理拖慢服务。已有单任务预算、取消和修订上限继续有效，并行不增加单次任务预算。

页面把状态绑定到任务和操作。回答期间保留导航、原文、笔记、草稿、附件操作和布局调整；对同一份 PPT 的保存、模型修改等冲突操作显示具体状态。

## 4. 附件发送与检查

### 4.1 输入框交互

输入框提供文件和图片导入按钮、拖入、图片粘贴。发送前展示文件名或缩略图，可逐项移除；附件与问题一起发送。导航中的 PDF 导入入口继续保留。

用户可以连续添加附件，每项分别显示处理结果。首轮上传接口按单文件处理的限制需要随附件队列调整，数量和总大小限制在实现时根据资源验证确定。首批覆盖 PDF、PNG、JPEG；其他格式在解析能力验证后开放，并沿用本节交互。

### 4.2 检查流程

1. 选取时即时检查空文件、大小和已支持格式。
2. 发送后上传，由后端检查真实类型、解码或解析。
3. 结合本次问题和当前论文判断图片等补充材料的用途；可以直接从用户问题中取得说明。
4. 回答使用可读且相关的材料。一次处理结果按附件和版本复用，避免每轮重复检查。

普通检查结果显示在消息附件附近。需要补充用途时，就地补一句说明；模型检查超时或失败可以单独重试该附件。无关材料给出简短理由，不连续弹窗，也不把检查扩展成额外问答轮次。

某项附件失败时，保留用户问题和其他可用附件。已有材料足以回答则继续；只有问题确实依赖缺失材料时才等待补充。独立截图保留上传来源，不自动赋予论文页码或 DOI。

## 5. 句子引用与讲解深度

### 5.1 选择具体文字

原文文字视图及助手回答支持鼠标选择一句、几句或部分文字。选中后出现“引用提问”，点击后把实际选区放入输入框附近的引用条，可以修改问题或移除引用；选择本身不发送请求。

原文引用保存论文、来源版本、来源位置、页码及选中文字；助手回答引用保存回复 ID 与选区。后台可读取必要邻近内容帮助理解，但用户看到的引用仍是实际选区，不强制扩展成段落。

来源核对沿用当前归属校验。点击引用能回到原位置；切换论文恢复各自草稿和引用，不把另一篇论文的选区带进当前请求。手机保留文字选择能力，并提供便捷的引用入口。

先完成现有提取正文视图的精确选区；内嵌 PDF 文字层选句作为同阶段增强。没有精确坐标时回到已知页或来源片段，定位层级与实际数据一致。

### 5.2 按需求调整输出

| 用户要求 | 输出调整 |
| --- | --- |
| 简单点 | 先讲核心意思，减少术语和分支，保留理解所需的关键关系 |
| 详细点 | 补充原理、推导、实验设计及证据联系 |
| 从基础讲 | 先补前置概念，再回到当前论文或问题 |
| 重点解释机制 | 聚焦相关过程、作用关系及论文支持程度 |

当前选区优先成为讲解对象；没有选区时，承接明确的上一轮问题或回答。“再简单一点”继续调整这个对象，不默认抽取回复最后一段。指代确实不明时才简短确认。

讲解程度在同一聊天中延续，用户下一次要求可覆盖；切换论文使用该聊天自己的偏好。简化不改写事实或删掉决定结论的条件，详细也不增加没有来源支持的细节。

## 6. 阅读引导与来源联动

导入后的概述和最多三个起始问题围绕实际研究对象、关键方法、比较关系和结果生成。优先复用当前来源版本已有内容，需要模型时可取消并缓存；用户主动问题优先于后台概述。

回答中的来源入口直接打开相关原句、图及图注，支持继续查看所在页面。长文来源按页、章节或图号组织，当前问题关联的材料优先显示。来源提取列表仍可查看，但不承担唯一定位入口。

缺正文或图件时给出相应补充动作，起始问题与实际材料一致。论文来源版本变化时更新缓存和引用定位。

## 7. 当前前端中的 PPT 专区及其他页面

论文研究与 PPT 是当前工作台的两个主入口，使用同一套导航、配色、字体、按钮、间距和状态表达。进入 PPT 时带上当前论文及其讨论、笔记和材料；也能从汇报记录恢复。

PPT 专区包含：

- 当前论文与可用材料、汇报记录和名称。
- 可跳过的时长、重点等设置，以及生成入口。
- 幻灯片预览、讲稿和引用。
- 自然语言修改、指定页编辑、保存版本、核对及导出。

复用已有后端和版本能力，在当前前端制作页面。修改结果按实际保存版本预览与导出，素材和来源关系贯通。

设置、个人记录和笔记相关操作也在当前工作台打开。逐项盘点导航、按钮、空状态和记录回看链接，清理跳回旧白色界面的入口。移除“布局示例”产品入口；历史原型可作为开发参考保留，旧地址是否继续兼容按迁移需要处理。

## 8. 可调整区域与阅读体验

| 分界 | 调整内容 |
| --- | --- |
| 左侧导航右边界 | 导航宽度 |
| 聊天与阅读区域分界 | 两个区域的宽度比例 |
| 输入区上边界 | 输入区与聊天记录的高度分配 |
| PPT 内部区域分界 | 汇报列表、预览与讲稿／编辑区的空间分配 |

分界在悬停和拖动时有明确反馈，设置合理最小尺寸；支持键盘调整、恢复默认布局。布局按工作区保存，在不同屏宽下限制到可用范围。拖动期间不触发内容点击或文字误选。

默认布局同时改善正文字号、行距、辅助信息可读性、按钮尺寸和阅读宽度。桌面支持并排；窄屏和手机采用折叠或切换，保留明确返回入口。通过截图和实际阅读检查默认尺寸，区域可调整不替代默认布局质量。

## 9. 文案与输出规则

产品提示直接说明状态和下一步。删除重复能力介绍、同一限制的反复提醒及用户无需知道的执行细节。模型回答先回应问题，必要证据边界放在相关结论处说明一次。

参考本轮已核对的 GitHub skill：

| 参考 | 应用位置 |
| --- | --- |
| [anti-defensive-writing](https://github.com/Kiterlin/anti-defensive-writing/blob/main/skill/anti-defensive-writing/SKILL.md) | 界面与回答中的过度声明、反复否定和重复限定 |
| [UX Writing](https://github.com/content-designer/ux-writing-skill/blob/main/SKILL.md) | 按钮、输入提示、加载、错误和空状态文案 |
| [Humanizer](https://github.com/blader/humanizer/blob/main/SKILL.md) | 长回答中的套话、机械结构和过度格式化 |

实施时把适用原则接入产品实际调用的共享规则和教学提示词，同时审查与之冲突的重复要求。仅安装 Codex skill 不会自动改变产品输出。使用或引入源文件时保留相应来源和许可证；英文词数等标准不直接套用到中文。

文案调整保留事实、出处和必要条件。核查问题在对应结论中呈现，减少重复而不把未知写成已证实。

## 10. 实施顺序与交付

| 阶段 | 主要内容 | 完成标准 |
| --- | --- | --- |
| A：聊天与调度 | 单论文主聊天、历史恢复、两个任务并行、队列与局部状态 | 切换论文不丢内容；两个聊天可生成，第三个可等待／取消；同聊天顺序执行 |
| B：输入与阅读 | 附件按钮／拖入／粘贴、发送后检查、精确句子引用、讲解程度、来源与真实引导 | 补图延续讨论；附件失败只影响依赖项；选区和输出程度符合本次要求 |
| C：工作台统一 | 当前前端的 PPT、设置和个人记录，清理旧页面跳转与示例入口 | 主要操作在当前界面完成；论文、笔记和汇报关联正确 |
| D：布局与文案 | 可调整分界、默认阅读尺寸、共享输出规则和界面文案 | 多屏宽可用、调整可恢复；代表性回答和状态提示符合文案要求 |
| E：完整验收 | 连续使用流程、真实材料行为检查及目标用户试用 | 工程结果、实际模型结果和用户观察分别记录，问题修正后复测 |

各阶段只对已实现和验证的部分标记完成。每次文件改动按仓库约定检查状态、审查差异、运行对应验证，在 `main` 提交并报告哈希。

## 11. 验收标准

1. 从导航上传 PDF 自动进入新论文聊天；输入框发送 PDF 与问题后，新聊天保留该问题。补图不清空当前讨论。
2. 旧多讨论数据可回看，主聊天选择明确；草稿、阅读位置、笔记和来源在刷新及后台重启后恢复。
3. 两个不同聊天可同时执行，第三个显示等待且可取消；同一聊天问题及关联 PPT 任务顺序执行，任务完成或取消后释放名额。
4. 回答时可以切换论文、查看原文、编辑笔记、准备附件和下一条问题。任务结果始终写回所属聊天。
5. 文件／图片按钮、拖入、图片粘贴均可用，附件发送前可移除；格式伪造、超限、解析失败、用途待确认和单项重试均有对应行为。
6. 用相关图片、用途不明图片、无关图片和模糊图片检查流程。问题已有足够材料时继续回答，确实依赖失败附件时才等待补充。
7. 原文和回复分别选取一个短句、部分文字及跨句内容，显示和提交范围与选区一致；引用可移除、可回看，切换论文无串用。
8. 同一问题连续要求“简单点、详细点、从基础讲”，比较对象、事实和来源保持一致，术语量、解释层次和展开程度有实际变化。
9. 两篇不同论文的概述和问题体现各自对象与方法；来源可回到相关句子、图和图注，缺材料时不生成不存在的建议。
10. 从当前论文进入 PPT，使用关联材料生成、预览、修改指定页并导出；汇报恢复及版本核对正确。设置、个人记录和回看入口保持当前前端样式。
11. 检查主要导航及上下文链接，无布局示例入口或跳到旧白色界面的操作；直接访问历史地址的兼容行为单独记录。
12. 检查 1440、1024、768、390 像素宽度及键盘操作；区域可调整、尺寸有下限、刷新恢复、重置可用，正文和按钮便于阅读与操作。
13. 对概述、解释、附件提示、等待、失败和 PPT 修改取代表性样本，审查重复限制、套话和不必要执行说明；证据边界与事实仍准确。

完整使用流程：**上传论文 A → 选择句子提问 → 补充图片 → 调整讲解程度 → 上传并切换论文 B → 两篇论文并行讨论 → 返回 A 整理笔记 → 生成并修改 PPT → 刷新后继续。**

模拟请求用于检查队列和界面状态，真实模型行为另外记录材料、调用和输出；两者分别报告。构建、类型及相关回归按实际改动运行。目标用户试用记录独立完成、需提示和未完成的步骤，优先修正中断、误跳转、错引用和材料归属问题。
