# 医研导师：这个项目在做什么，以及我为什么这样设计

我最近做的项目叫 **医研导师（Med Research Mentor）**，面向医学科研初学者。现在已经有完整的本地网页、后端、论文处理和生成流程，也开源到了 GitHub：

https://github.com/qiudaoyu0201/med-research-mentor

先说最核心的想法：**用模块化 Skill 组织能力，用导师、新手模拟、来源核验三个 Agent 协作，让论文带读、PPT 汇报、研究方案在内部迭代中互相检验。** 我想优化的不只是某一次回答，而是“怎样把人教懂、教到能讲出来、能换个问题继续思考”。

## 1. 出发点：科研小白需要的是有人带着建立思路

我自己刚进课题组，老师让读论文、学方法，但新手经常卡在“不知道怎么读”。英文术语不熟，图表不知道怎么分析，实验为什么这样做、对照为什么这样设，也很难一下看出来。和普通 AI 聊当然也可以，但每次都要重新告诉它怎么教，讲解深浅、连续性和原文对照也不稳定。

所以我希望它从背景、目的和价值开始，顺着论文读，遇到关键实验、图表和方法再展开。读完以后，不只是知道论文说了什么，还能解释“为什么做这个实验、结果支持什么、换成我的课题应该怎么设计”。

这种教学要有节奏：第一次遇到一类图，可以解释坐标和比较组；后面熟悉了，就更多关注结果和研究逻辑。专业词给中英文对照，回答有小标题和短段落，用户随时能追问、加深或继续。科研思维融入讲解，不把每一轮都弄成考试。

## 2. 三条核心功能，各自解决一个实际需求

| 功能 | 用户怎么用 | 希望得到什么 |
| --- | --- | --- |
| 论文带读 | 导入 PDF，跟着读，随时选句追问、查看原文和图表 | 逐步理解背景、方法、实验、证据和结论 |
| 论文汇报 PPT | 选择或导入论文，补充页数和重点 | 能向老师讲清研究思路、方法、主要结果、创新与不足的 PPTX |
| 研究方案 | 提供初步问题、方向、资源限制，可补参考论文 | 带设计理由、对照、测量、分析和待确认条件的讨论草案 |

带读是主要入口，另外两项也能独立使用，不必先读完整篇论文。

带读中可以对照 PDF、原图和原文片段，也能引用回答里的一句话继续问。PPT 重视页面排版、图文关系和汇报主线，讲述提示单独导出，文字可以在 PowerPoint 里继续改。研究方案支持 DOCX 和 Markdown，既写打算做什么，也解释为什么这样设计。

日常使用还有几个我比较在意的细节：

- **节奏可以调整。** 可以先设新论文的默认讲解偏好，也可以在对话里临时要求展开或简略。追问可以偏离主线，再接回原来的阅读位置。
- **按需补资料。** 带读和方案流程可以利用后端文献检索辅助理解；检索来的题录、摘要与已读全文分别使用，不把搜到文献等同于读完文献。
- **方案从实际条件出发。** 用户主要提供问题、思路、资源限制和自由建议，参考论文可选。医学范围覆盖基础、临床、影像、组学等，设计依据当前问题取舍。
- **生成专区保持简单。** PPT 和方案重点做好生成与导出，拿出去继续编辑；不把产品做成复杂的在线办公软件，也不额外堆一个重型笔记系统。

## 3. 为什么用三个 Agent：从三个角度检查同一件事

这里的 Agent 是不同职责的模型调用角色，不要求分别使用三家模型。调度器负责组织它们，Skill 提供各项任务的规则。

**导师 Agent**负责讲解和生成，也负责根据反馈修订。它要把背景、实验、结果和推理串起来，并根据用户的理解程度调整深浅。

**新手模拟 Agent**站在学习者的位置试读、复述、组织汇报或尝试设计。它暴露的是教学问题：这里为什么突然出现一个术语？这个对照到底有什么用？我能背出结论，但能解释依据吗？

**来源核验 Agent**回到原始材料检查事实与证据，也评价新手的回答和生成产物。它检查图件、引文、实验条件、比较关系，以及是否把相关性说成因果、把新方案假设当成已有结果。

基本配合是：

```text
导师生成 → 新手试读/作答 → 来源核验
    ↑                         ↓
    └── 针对断点修订或补教 ← 汇总问题
                  ↓
             复读与复核
```

这样可以把“讲得顺”“新手能理解”“证据站得住”放在一起考虑。普通局部追问按需调用，内部质量迭代则运行更完整的协作链路。

## 4. 最想强调的亮点：三功能交叉迭代

**带读、PPT、研究方案既是用户功能，也是内部检验教学效果的不同任务。** 各自生成成功只是第一步，还要看它们能不能一起讲通同一项研究，以及能不能帮助新手完成下一步。

三个功能的关系可以这样理解：

- **带读负责把研究讲明白。** 研究问题是什么，方法为什么适用，证据怎样形成结论。
- **PPT 负责把理解变成表达。** 压缩成几页后，能否保留关键比较和限制？新手能不能沿着页面讲清楚？
- **研究方案负责把理解变成设计。** 换个研究问题或资源条件，还能否提出合理对照、测量和分析思路？

### 比如：让小白拿 PPT 组织一次汇报

这就是我很重视的一种验证思路：导师讲过论文，系统生成汇报材料，再让模拟新手组织讲述或回答相关任务，核验者检查他的表达。

如果小白只会念结论，解释不出图中的比较组，问题可能在前面的带读没讲透，也可能在 PPT 只放了结果、没有交代实验设计。如果小白把观察性结果说成因果，核验者就回查：是讲解本身误导了，还是 PPT 压缩时删掉了关键限制？随后对相应讲解或页面修订，再验证小白能否说清楚。

**这会同时检验两件事：PPT 能不能支持有效汇报，新手能不能把学到的内容表达出来。** 反馈还可以回流到带读方法和 Skill，而不只停留在给 PPT 打分。

代码里已经有围绕这类目标的教学产物曝光、证据复述、汇报提纲、设计草案和独立评价任务。其中汇报提纲任务还要求新手重新组织表达，不直接复制现成 PPT，从而观察是否真正抓住主线。这里的汇报验证以文字任务与产物评价进行。

### 再把研究方案拉进来

新手理解一篇论文后，进一步尝试设计新研究。原研究是住院患者随访，新任务只有一次体检记录，就要重新考虑可回答的问题、时间顺序和结局，而不能照抄原论文。

方案中的困难会反过来暴露教学缺口：为什么必须有随访？为什么需要这个对照？原方法需要什么资源？这些问题可以成为下一轮补教和规则改进的依据。

### 三类产物一起核对

已有跨功能复核流程将带读、PPT、方案及其原始来源放在一起，检查关键事实、条件、图件和结论是否一致：

```text
同一组论文来源
   ├─ 带读：讲清研究
   ├─ PPT：组织汇报
   └─ 方案：尝试设计
           ↓
    跨产物证据与条件核验
           ↓
    新手复述 / 汇报 / 设计
           ↓
    定位问题 → 补教或修订 → 复验
           ↓
    改变条件的新任务 → 检查迁移
           ↓
    用于下一轮 Skill 候选比较
```

三份产物一致还不够，最终仍要回到论文来源。内部流程保存实际产物和来源版本，修改内容后重新复核。用户使用时可以只做一项任务，完整交叉链路主要用于内部质量迭代。

## 5. 为什么把能力拆成 Skill

教学规则全部堆在一个长提示词里，会很难定位问题：是读图没讲好、方案设计不合理，还是新手模拟得太像专家？拆成模块后，可以围绕问题修改对应能力，再检验是否改善了整体效果。

当前有 **11 个 Skill + 一份共享规则**：

| Skill | 中文名称 | 主要作用 |
| --- | --- | --- |
| `medical-research-assistant` | 科研学习主助手 | 理解用户目标，组织带读、方法、读图和汇报任务，处理直接解释与后续追问。 |
| `medical-paper-guide` | 论文带读 | 按研究逻辑组织论文讲解，串起背景、问题、方法、结果和讨论。 |
| `medical-evidence-chain` | 证据链 | 连接研究问题、实验、结果与结论，明确每个主张的依据和适用边界。 |
| `medical-method-tutor` | 方法教学 | 解释方法原理、实验目的、对照设置及设计理由。 |
| `medical-figure-tutor` | 图表教学 | 讲清坐标、分组、比较关系、统计和数据含义，并联系论文结论。 |
| `medical-term-explainer` | 术语解释 | 提供专业词的中英文对应、概念解释和当前语境中的含义。 |
| `medical-journal-club-ppt` | 论文汇报 PPT | 组织汇报主线、页面内容、图表证据和讲述提示。 |
| `medical-research-plan` | 医学研究方案 | 根据问题、参考材料与资源限制起草方案，写出设计理由和待确认条件。 |
| `medical-grounding-check` | 来源核验 | 对照原始材料检查事实、引用、证据支持与结论边界。 |
| `medical-novice-simulator` | 新手试读模拟 | 从初学者视角阅读讲解，指出术语不清、推理跳步和理解断点。 |
| `medical-learner-simulation` | 学习者任务模拟 | 支持内部学习者模拟，围绕任务作答与理解表现提供评估输入，配合学习闭环。 |

Skill 和 Agent 不一一对应。例如导师讲图时可以组合图表教学与证据链，制作汇报时再使用 PPT 模块；新手模拟和核验模块则从各自角度提供反馈。

模块化还有两个直接好处：一是便于替换模型和增加医学方向，二是能比较同一批材料上旧规则与新规则的效果。研究方案的生成规则也已经从后端拆成独立 Skill，接入了实际生成和候选快照。

## 6. 内部迭代具体怎么运行

这里说的“训练导师”，主要是优化 Skill、提示词、角色协作和调度，不是训练底层模型参数。

一次迭代围绕一个明确问题展开，例如：小白能否说清对照的作用，PPT 是否丢失重要条件，方案是否保留新任务的资源限制。

1. **固定材料和规则版本。** 准备论文或局部样本，保留基线和候选，记录模型配置及预算。
2. **运行教学和产物生成。** 根据本轮目标运行带读、PPT、方案及必要角色。
3. **检查产物，再观察学习表现。** 对照来源核验，也让模拟新手复述、汇报或设计。
4. **补教和复验。** 针对具体断点修订，看问题是否得到改善。
5. **换条件检查迁移。** 改变人群、设备、时间、可用数据等，看是否仍机械套用原论文。
6. **比较后采用规则。** 通过候选比较和规则发布流程，让改进进入实际使用。

学习评估还设计了“未学习”“只看材料”“材料加教学”三种分支。这样能比较教学额外带来的帮助，而不只看模型本来会多少。新手收到的是允许看到的材料和教学产物，评价记录与答案提示分开。

我的取舍是：**小样本快速定位问题，完整论文检查连贯性，三功能交叉检查应用效果。** 内部评价严格一些，用户交付抓住事实、证据和关键设计问题，不因零碎措辞反复阻断。优先把常见使用场景做好，再处理少见边界情况。

## 7. 前后端各自做什么

前端使用 **React + Vite**，负责工作区、对话、论文导航、PDF/原图对照、选句追问、设置，以及 PPT 和研究方案专区。它把学习过程做成一个能持续使用的界面。

后端使用 **Express + TypeScript**，负责论文导入与解析、图件和来源管理、模型调用、Agent 调度、Skill 加载、本地保存、阅读进度、生成版本，以及 PPTX、DOCX、Markdown 导出。

调度器处理任务顺序、按需调用、预算、取消和恢复。证据与版本记录让生成、核验和后续修改能够对得上，也为内部迭代提供可比较的输入。

整体关系是：**前端承载使用体验，后端组织数据和执行，Skill 定义能力，三个 Agent 分工完成教学与反馈。**

## 8. 目前已经做过哪些优化和测试

最近的工作集中在把这个设计落实到可用流程，主要包括：

- **带读体验：** 连续阅读、当前与下一步、讲解深度、术语解释、选句追问及原文对照。
- **图表证据：** 原图显示、来源绑定、图表比较关系，以及跨功能使用图件时的一致性。
- **PPT 和方案：** 幻灯片布局、独立讲述提示、可编辑导出，方案的条件保留、来源核对和文件生成。
- **内部协作：** 新手与核验角色的可见信息、跨产物复核、补教与迁移、候选规则隔离。
- **运行稳定性：** 数据保存、取消、并发、缓存、连接失败与有限恢复。

测试分三层：

| 层次 | 怎么测 |
| --- | --- |
| 工程回归 | 自动测试数据、合同、导出、调度、规则隔离与异常处理；最近一次 **322 项全部通过**，类型检查和构建也通过 |
| 真实使用走查 | 从导入论文开始，连续带读、追问、查看图表，再生成 PPT/方案并检查导出 |
| 内部模型迭代 | 多种论文和小样本、基线与候选、三功能交叉复核，以及新手补教后的新情境任务 |

322 是当前工程测试项数，不是模型迭代轮数。模型实测做过多批次，旧记录按实验分开保存，介绍里不把它们拼成一个没有统一口径的总次数。更值得传达的是，已经把“输出内容、检查证据、观察学习表现、修改规则、再次验证”串起来了。

## 9. 怎么用，以及现在是什么状态

项目已经开源，按 README 安装 Node.js 22.13+ 和项目依赖，配置自己的模型后启动本地网页。可以使用已配置的 Codex CLI，也可以使用独立兼容 API；兼容 API 路径不要求原生 Codex 订阅额度。

进去后导入论文就能开始带读，也可以直接去 PPT 或研究方案专区。阅读和生成记录保存在本机，调用模型时发送当前任务所需材料。源码和 Skill 都能继续修改，项目使用 MIT 许可证。

我现在最想让你理解的，是这套设计的连接方式：**读懂论文 → 用 PPT 讲清楚 → 用方案尝试设计 → 三角色检查哪里没讲明白、哪里证据不够、哪里迁移错了 → 反馈到下一轮教学和 Skill。** 这是三条功能放在同一个智能体里的意义，也是后面继续迭代的主线。

## 10. 简单使用教程

如果你现在只有一个能操作本地文件、执行终端命令的 Agent，也可以从这里开始，不需要先自己学会配环境。

### 准备：让 Agent 帮你装好并启动

在电脑上新建一个项目文件夹，用你的 Agent 打开它，把下面这段话发给它：

> 请帮我在本机安装并运行医研导师，仓库是 https://github.com/qiudaoyu0201/med-research-mentor 。我没有配置过开发环境，请先阅读仓库的 README.md 和 docs/SETUP.md，检查并帮助安装所需环境（Node.js 22.13 或更新版本），下载项目、安装依赖，并按运行说明配置模型。先问清楚我有哪些可用的模型服务，再选择配置方式；需要我登录或填写密钥时，告诉我具体在哪里操作，不要把密钥打印出来或提交到 Git。完成后检查模型能否正常调用、网页能否打开，把访问地址和以后重新启动的方法告诉我。先使用现有功能，不需要修改产品代码或运行内部训练。

这里需要你配合的主要是两件事：允许安装必要软件，以及提供可用的模型调用方式。项目可以使用已安装并登录的 Codex CLI，也可以配置兼容 API 服务；选择后者时，需要服务地址、模型名称和 API Key。**用来帮你安装的 Agent，与智能体运行时调用的模型，是两件事**：前者帮你把程序装好，后者负责实际讲论文、生成内容。让 Agent 根据你的现有条件配置即可。

启动后，通常在浏览器打开 <http://127.0.0.1:4317/>。这是你自己电脑上的入口，需要程序保持运行；以后关闭再打开，也可以直接让 Agent“启动之前安装的医研导师”。如果安装或启动报错，把报错交给它继续处理即可。

看到界面后，准备一篇医学论文 PDF，按下面的顺序试一遍。

### 第一步：导入一篇论文

在界面中导入自己的医学论文 PDF，选择这篇论文开始讨论。第一次使用可以直接说：

> 我是刚进课题组的本科生。先讲这篇论文的背景、研究问题和价值，然后按论文顺序带我读，重要图表和实验展开讲。

### 第二步：边读边问，对照原文

跟着讲解往下读，想推进就说“继续”，没明白的地方直接问。不需要每次重新交代自己的需求，例如：

- “这个实验为什么要设这组对照？”
- “这张图的横纵坐标是什么？两组差异说明什么？”
- “这段太细了，先讲主要思路。”
- “这里没懂，换个简单一点的说法。”

可以选中回答中的一句话追问，也可以打开来源、PDF 页面或图件，对照着看。需要英文帮助时，让它解释相关术语或翻译对应段落。临时问完其他问题，再说“回到刚才的位置继续读”。

### 第三步：生成一份汇报 PPT

进入 PPT 生成专区，选择或导入论文，按需填写页数和汇报重点。例如：

> 做一份用于向导师汇报的 8 页 PPT，重点讲研究问题、实验设计、主要图表、结论和不足，附简洁讲述提示。

生成后先看预览，再分别下载 PPTX 和讲述提示。PPT 可以放到 PowerPoint 里继续修改；讲述提示用来帮助自己组织口头表达。

### 第四步：有想法时生成研究方案

进入研究方案专区，填写想研究的问题、手头条件和限制，需要时选入参考论文。例如：

> 我想研究某项指标与疾病严重程度的关系。目前只有本院既往病历，不能新增随访，参考这篇论文帮我形成一份和导师讨论的方案草案。

生成后重点看研究对象、对照或混杂因素、测量指标、分析思路和待确认条件。需要分享给导师或合作者时，可以导出 Word 或 Markdown。

### 平时怎么选功能

**想学懂就用带读，准备汇报就用 PPT，有研究问题就用方案。** 三项可以独立使用，不必每次全部做一遍。刚开始最推荐的体验路线是：导入一篇论文 → 读懂一个关键实验 → 对照一张图追问 → 生成一份简短汇报。
