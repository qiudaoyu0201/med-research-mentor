# 使用当前中转运行与迭代

2026-10-09 已在本机真实验证：`codex-configured:klapi` / `gpt-5.6-sol` 可完成文本结构化生成、图片理解和主动停止。之前失败的直接原因是仓库默认锁定 ChatGPT 登录、`openai` 提供方及另一个模型，与本机实际 `klapi` / `apiKey` 配置不一致。

## 启动

在项目目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-configured.ps1
```

默认参数显式选用本机已验证的 `klapi`、`gpt-5.6-sol`、`apiKey`。脚本优先使用 `C:\Program Files\nodejs` 的新版 Node，启动前只读检查当前 Codex 配置、登录类型；不发送模型生成请求，不修改配置，不复制密钥。若提供方或登录方式不一致则停止，不切换接口。

`codex-configured` 只接入显式 `apiKey` 账费通道；原生订阅仍使用 `TUTOR_PROVIDER=codex`。自定义提供方不能仅凭本机 ChatGPT 登录就被标记为订阅计费。

启动后保持窗口运行，默认访问 `http://127.0.0.1:4317/`；若设置了 `PORT`，使用实际端口。按 Ctrl+C 结束。普通 `npm run dev` 仍遵循原默认配置，未设环境变量时使用 ChatGPT 登录通道，当前本机应优先用上述脚本。

只做预检：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-configured.ps1 -InspectOnly
```

已有生产构建时加 `-Production`；更换型号需明确加 `-Model '目标型号'`，然后重新做型号验收。脚本不会因为模型目录里列出了型号就声称实际生成已通过。

## 迭代脚本使用同一通道

在执行已有测试或内部迭代脚本的终端中设置：

```powershell
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
$env:TUTOR_PROVIDER = 'codex-configured'
$env:TUTOR_MODEL = 'gpt-5.6-sol'
$env:TUTOR_CODEX_PROVIDER = 'klapi'
$env:TUTOR_CODEX_AUTH = 'apiKey'
npm.cmd run model:check
```

`model:check` 不生成；加 `-- --generate` 才会发送一次真实文本探针并消费当前 API 通道额度。任务按实际调用记录账本，失败和未知用量不能当作零成本。不要为了排障反复执行全套昂贵迭代脚本。

## 与原生 Codex 的关系

- 这条已验证路径复用本机 Codex CLI 的 `app-server` 和现有中转鉴权，依赖 CLI 安装与配置。它使用中转 API 额度，**不要求 ChatGPT/Codex 原生订阅还有额度**。
- 业务代码也有独立 `TUTOR_PROVIDER=compatible` 的 HTTPS Chat Completions 适配器，可直接接服务端配置的接口，运行时不依赖 Codex CLI。目标服务是否支持图片、JSON、取消等，仍需单独实测。
- 修改前后端、Skill 与文档不绑定原生额度；真实生成、模拟导师/新手/核对员迭代，需要所选模型通道本身可用且有额度。
- 本次验证模型是 `gpt-5.6-sol`，不能把“通过中转运行”写成“已完成国内模型适配”。国内模型保留明确适配入口和后续验证工作。
