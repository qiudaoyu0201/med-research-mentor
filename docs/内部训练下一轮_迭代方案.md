# 内部训练下一轮迭代方案

版本：v1.1 · 日期：2026-10-07 · 起点：`36ad359`。

依据[主方案 v2.8](科研能力培养与三类Agent协作_整体落地方案.md)、[第一轮实施方案](内部训练第一轮_落地方案.md)和[周期 2 实测记录](内部训练第一轮_周期2记录.md)。**本文交付后续迭代方案，不代表已执行以下实现、模型比较或能力发布。** 用户已明确允许多迭代几次，成本重点控制单次消耗与无收益负荷；因此不再把原第一轮剩余 64 次作为后续工作的总上限。默认安排最多三个候选周期，每周期独立冻结、诊断、比较与结论；学习试验仍单独最多 36 次。历史 44 次保留累计记录，新额度与原协议分开记录，不续改周期 2 的冻结内容。

本轮要解决的问题是：重要原理明明已在实际材料中，助手却没讲到；修订虽然补了说明，也可能引入新的事实错误；评价有时把“讲过部分设计理由”误判为“必要解释已完整”。成功应同时满足科学准确、必要深度、初学者可理解和当前任务范围，再判断调用成本是否值得。

## 1. 目标、边界与结果分级

| 目标 | 本轮应看到的变化 | 不能当作成功的替代指标 |
| --- | --- | --- |
| 必要原理进入解释 | 当前结论依赖的重要概念、测量和干预理由有准确解释与实际依据 | 出现关键词、写了药名或笼统说“设对照” |
| 修订可靠 | 补缺口时不改变已核实的参照、单位、方向、比较对象和证据边界 | 改完读起来更顺，但公式、读图或结论发生错误 |
| 新手能跟上推理 | 术语首次出现时说明含义，连接对象、读数和结论，保留决定结论的条件 | 小白角色说听懂、删掉关键概念、堆积专业细节 |
| 按需完成任务 | 只生成和核对用户实际请求的讲解、PPT／稿件、方案 | 为验证讲解额外生成 PPT，或强迫用户做题 |
| 成本有依据 | 相同请求下记录成功率、尝试、用量、等待与耗时，控制无收益调用 | 失败稿更短、更快，或靠少核对取得“节省” |

结果分别报告，不能互相替代：

1. **工程可用**：隔离、账本、输入和验证合同可靠；不等于教学质量提升。
2. **开发案例改善**：预先指定缺口被解决；尚不启用规则，不代表能推广。
3. **三类产物有限发布**：固定候选通过全部开发与留出门槛、实际文件检查和回归，可以说明指定范围的产物改进。
4. **模拟应用表现**：开放式作答与真实曝光可核对；单独报告，不能升级为真人理解、稳定学习收益或研究能力已提高。

本轮继续改规则、资料组织和协作合同，不安排权重训练。用户仍使用现有三个入口；真人试讲、国内模型、用户端方案转 PPT、自动阅读截图识别、额外后台和复杂同步不纳入本轮。

## 2. 先诊断根因，避免再追加一大段泛泛提示

从周期 2 首稿、修订输入、修订稿、两次在线核对和独立评价建立逐项追踪表。对每个缺口记录“请求需要什么—实际看到了什么—在哪一步遗漏／改变—影响什么”，先用现有记录走查，零模型调用。

| 已知问题 | 已有证据 | 前置诊断及处理方向 |
| --- | --- | --- |
| 来源有原理，稿件未解释 | `train-xu-p4` 有抗凋亡通路说明，基线和候选未充分连接到干预理由 | 区分来源未选中、选中但截断、已提供却未使用；本例不能笼统归为材料不足 |
| 修订引入新错 | 初稿的对照参照解释较接近原图，修订加入减 1 和 0% 相同的公式 | 对照原图、图注和前后稿，记录改动来源；禁止凭词义推导并填造完整计算流程 |
| 评价遗漏重要设计理由 | 候选的总体设计理由被判通过，但重要干预原理仍未讲清 | 拆开研究对象、测量原理、干预选择、对照作用等适用检查，不由某一项覆盖其他项 |
| 反馈污染正文 | 基线有内部编号；候选反复写“未核验背景” | 检查角色建议怎样进入修订输入及正文；保留工作记录和真实边界，避免复述核验过程 |
| 提效依据不充分 | 两侧任务均失败，候选用量和耗时也未减少 | 把失败率、修订增错及重复解释列为成本原因，暂不宣称提高效率 |

追踪表区分四种情况：来源确实不足、来源装载不完整、助手未解释、评价漏判。它们的解决办法不同；不通过给每份请求塞入额外来源或答案掩盖问题。

## 3. 三类功能的必要解释标准

“必要”按当前问题判断，不要求每篇论文解释所有技术、每份方案写完整操作手册。相同科学边界适用于简短和详细回答；展开程度改变篇幅，不改变事实与关键条件。

| 功能 | 必须覆盖的内容 | 深度和范围判断 |
| --- | --- | --- |
| 论文讲解 | 回应研究问题；说明关键测量对象、比较／对照、观察、推理与局限 | 当前结论依赖某个原理，就讲清“测到／改变什么、为什么能支持判断”；不要求无关复现参数 |
| PPT／稿件 | 清楚的问题与证据主线；原图对应、轴／单位／参照与观察；讲稿解释为何能得出结论 | 页面短不等于解释少：必要理由可放在逐页讲稿；完整演讲稿仅在请求时生成并与页面一致 |
| 研究方案 | 问题、资源、测量／设计选择、必要对照、替代解释、未知条件 | 资源变化后调整对应设计，保留未变目标；设备、效应量、样本量和结果不得编造 |

写法以“先回答—解释必要术语—承接设计与读数—说明推理与限制”为一般原则，不固定成所有产物都必须出现的标题。比喻可帮助理解，不能替代准确对象；专业概念有必要时保留，并解释它的作用。

小白反馈指出具体理解断点；校验指出具体事实、遗漏或范围问题。助手审计这些意见：确实影响当前任务才补，过度扩展的建议留在工作记录，不服从角色权威而偏离用户目标。真实材料缺口可以向用户说明缺什么、为什么需要；内部编号、核验进度和修订清单不进入讲稿。

## 4. 候选设计与公平比较

每个正式周期只选择一个候选，默认最多三个周期。首个周期优先测试**教学端的来源到解释合同**，不沿用周期 2 未通过的共享规则作为新基线。其具体实施在根因走查后冻结，必须符合以下约束：

- 让必要解释绑定实际可见证据，区分“解释研究对象”“解释测量／干预原理”“解释对照为何必要”；不再把它们合成一项笼统要求。
- 优先利用现有正文、引用和角色输入输出形成可追踪记录。若需要新增内部字段，在同一次生成中返回，限制体积，不新增一个模型规划调用。
- 内部记录包括目标、相关段落／页面、真实来源 ID 和解释缺口；不是提供给助手的标准答案，不是用户交付的新清单。
- 普通请求保持真实自动材料选择，不加入隐藏 sourceIds、不手塞开发案例的结论。若诊断发现问题主要在选片段，本周期改选“材料选择／组织”这一候选，教学规则保持基线；不同时修改两层。
- 若问题主要发生在修订输入，另立“修订输入合同”候选，记录它和基线的具体输入差异。不能把换规则、换资料、换评价、换模型一并称为一个小改动。

评价侧补齐遗漏和结构检查是比较工具修复，先完成校准，然后对两侧使用同一版本。必要工程修复也先同时应用于两侧，明确这属于新的工程基线，收益不能归到教学候选。

案例的预定标准、具体判定依据和校准正确判断只在评价侧。助手可以看到普通请求、实际材料与正常在线反馈，不接收留出的标准答案或离线评分备注。

模型配置、问题、资源、可用原始资料、用户深度、图件、角色路由和比较工具保持一致。候选若改变材料选择或修订输入，那一项差异是实验变量，必须明确记录，不能声称两侧模型输入完全相同。首个周期的正式基线和候选重新生成；周期 2 旧输出只用于诊断和回归夹具。后续周期的基线仅按第 8 节严格条件复用，不将旧评价替换成新版结论。

不在同一周期反复改候选直至评分通过。开发失败后先输出原因与消耗，再据具体证据选择下一候选周期并继承全量账本。最多三个周期是有边界的实施安排，不是要求花满三轮：一旦达到发布门槛，进入必要学习试验和交付；连续两轮仍有同一阻断问题，先回到零调用诊断，未找到可验证的新原因或改法就不启动第三轮盲试。

| 候选周期 | 优先工作 | 如何决定下一步 |
| --- | --- | --- |
| A | 解决已提供来源未进入必要解释的问题；按根因选择单一改动 | 看首稿、修订及独立评价，定位剩余阻断，不只看总分 |
| B | 针对 A 的真实失败，例如修订输入或事实变更核对；不预先叠加所有改动 | 先验证新改动能解释旧失败，再冻结比较；未启用候选不自动成为基线 |
| C | 处理尚未解决且有具体新证据的缺口；或者验证已合格候选的必要稳定性 | 没有新假设、没有有效留出或已有充分验收时，不继续消耗 |

零调用工程修复不算一个模型候选。每周期明确当前在线基线、待测差异和所有继承变化；某个修复若必须成为共同工程基线，先验证再同时应用，不能把多个改动的效果都算在最后一条提示上。

## 5. 修订防回退：补解释时检查是否改错事实

实施通用的首稿／修订稿走查，而不是硬编码这篇论文的“100%”。对结论依赖的内容记录：测量对象、比较组、参照／分母、单位、方向、图件位置和科学边界。先按实际来源核实，错误首稿不能被锁成“不得修改”的正确答案。

修订请求指出需修什么、所在位置、依据、预期解决的理解缺口，以及哪些已核实内容应保留。内部问题 ID 保留在审计与核对记录；交付解释直接融入相应段落。最终核对既检查原问题是否解决，也检查修订新增或改变的内容。

数字、单位、来源 ID、页面及公式差异可程序定位；“为什么这一修改成立”仍需对照证据。图注、坐标、图例与正文有歧义时，合并查看实际原图；未能消解就说明确切限制，不自行补出完整公式。需要改掉首稿的事实时必须给依据，不能为了“保持一致”保留错误。

每个正常任务仍最多一次自动修订。一次未解决不继续自动套娃；保留草稿与原因，阻断内容不作为完成稿导出。已有可靠部分可按现有合同交付，但不能让未核实部分借此获得“全部通过”标签。

内部记录至少分别保存首稿、修订稿、改动位置、来源锚点、前后核对和独立评价，以便看清改进来自首稿还是修订，也能定位修订增错。

## 6. 先校准评价，再运行正式比较

将评价拆为六组：来源／事实、必要解释覆盖、可理解推理、任务范围、反馈污染、产物一致性；每项按案例说明适用范围。论文没有的步骤不强加，观察研究不照搬干预实验检查。

必要解释按具体作用分别判断。例如当前任务需要解释某干预时，不能仅凭对照解释正确就判干预理由完整。缺少解释的失败定位最相关的真实段落／标题，并说明少了什么；不让“找不到一句错误句子”导致遗漏被放过。

在零调用阶段准备正反例及来源锚点，覆盖：

1. 事实相符但只列结果，省略必要原理；与准确、足够解释的正例配对。
2. 专业术语密集但缺少术语含义、读数与推理连接；与简洁但完整的正例配对。
3. 首稿有正确参照，修订变为错误参照／公式；以及依据来源正确纠错的情形。
4. 真正材料缺失、已有材料但未使用，二者不混为一谈。
5. 内部工作状态重复进入正文，以及必要科学边界保留在对应结论旁。
6. 缺项、假位置、无效来源、事实判断不给来源，均算评价无效，不算反例识别成功。

本周期语义校准最多 6 次调用；一例可检查多个明确维度，必须逐项给预定判断，不能只看总体拒绝。结构无效类优先用零调用测试。评价规则本次已变化，不能拿周期 2 的六次通过替代新校准；只有评价指令、合同、例子、来源与输入哈希全部相同时，才允许复用原校准记录，并明确标记复用。

位置和来源 ID 合法只是最低合同，不等于引用能支持主张。新增“证据是否真正支持该解释”的语义检查；关键参照／单位／读图争议需原图与文本走查。模型分歧保留各自理由，不投票掩盖问题，也不无限增加模型裁判。无法核实的关键项记为未确认，不通过。

## 7. 案例、留出与日常路径

沿用四篇原始论文、D1–D3 与 H1–H3，先核实文件与哈希。既有留出尚未产生结果，可以继续作为本候选的留出；同一研究的不同版本和 SI 仍归到同组。默认不新增下载，不纳入个人笔记或其他用户资料。

| 案例 | 请求与验证重点 | 关键记录 |
| --- | --- | --- |
| D1 | Xu 六页 PPT＋已请求的完整稿；干预原理、原图参照、修订回退、工作状态 | 页面／逐页稿／完整稿、前后版本与实际源图 |
| D2 | 队列论文讲解；比较理由、关联与因果、必要定义和简洁程度 | 实际回答及自动装载的片段，不额外做 PPT |
| D3 | 固定细胞测量问题及资源变更；区分信号、细胞数与表达变化 | 两个条件的可行方案、对应设计变化与未变目标 |
| H1 | Passos 新方法到证据连接；检查一般解释能力 | 实际原文／图件覆盖；提取不完整时如实记限制 |
| H2 | Bell 新论文六页汇报及已请求完整稿 | 观察研究的主线、轴／参照、图稿一致与实际文件 |
| H3 | 新临床观察问题与资源限制 | 不照搬原论文资源、结果或估算出的样本量 |

D3 当前脚本对两个条件分别生成新方案，只能检验“条件不同，输出是否适配”。下一轮增加一个**零模型调用的版本／条件继承回归**；若要证明真实用户修改同一方案后的表现，需要预先将正式案例改为同一课题的更新流程，冻结两侧相同路径、版本和调用上限。不能在结果出来后临时补跑并计为旧案例通过。

先冻结候选并完成开发，再运行留出。留出结果不反馈给本周期候选；一旦据其缺陷修改，相应研究转开发，后续周期另找留出。三个周期不代表可以反复用同一留出调到通过：此前未运行且未用于设计的留出可继续使用，已暴露结果的研究连同不同版本和 SI 均不能重新标为未见。必要时按真实缺口补齐可合法获取的新来源，先冻结选题、分组、适用评价与调用上界，再运行；没有有效留出时只能报告开发改善。

零调用回归覆盖：仅讲解、仅方案、仅 PPT、带完整稿的 PPT、局部追问、资源变化、用户手改后核对、取消和失败保留。日常请求按原有路由核对实际产物，内部跨功能验证由案例入口安排。主流程不增加考试、标准答案、训练日志或新的用户操作。

## 8. 调用预算：允许多轮，重点限制每轮和每次无收益消耗

原第一轮的 108 次额度、已消耗 44 次及原协议保持原样，包括前序未知调用；不回写成更大的旧预算。用户本次授权的后续工作另立额度版本，默认最多三个候选周期，每周期产物尝试最多 70 次，后续产物合计最多 210 次。历史与新增分别报告，历史加后续产物最多 254 次；学习另列最多 36 次。这些是防失控的实施上界，不是预计必须花完，也不是要求用户再次批准已有授权。

恢复和派发前核实新报告的前序消耗、额度版本与冻结 lineage 一致，新目录关联 `cycle-2` 原报告哈希；后续周期缺少前序关联时拒绝启动，不能默认为零。新增额度不会抹掉旧消耗，不把旧剩余 64 次和新 210 次再叠加。日志按调用 ID 去重；无法确认是否派发仍保守占额度，取消后迟到结果不写入完成稿。多入口锁与运行中状态也要检查，避免并行绕过单周期和后续合计上限。现有运行器仍遵守旧协议，实施时须先新增兼容的额度版本与验证，不能仅换目录名就获得新额度。

目前脚本对任意比较统一预约 16 次，连只需少量调用的方案也如此。下一轮在零调用阶段根据冻结路由、条件数和最多一次修订计算每个案例的真实上界，预约完整“基线＋候选＋独立评价”单元；保守上界未验证前继续用原值，不能凭期望成功次数压低预约。

以下是**保持现有普通路由、没有额外规划／试读调用时的预算草案**，实施时要由零调用合同测试确认：

| 比较单元 | 两侧都无需修订时 | 现有路由修订上界 |
| --- | ---: | ---: |
| 新评价校准 | 6 | 6 |
| D1：PPT＋完整稿，两侧生成／核对＋独立评价 | 6 | 10 |
| D2：讲解，两侧生成／试读／核对＋独立评价 | 8 | 14 |
| D3：每侧两个条件，各最多 2 次＋一份比较评价 | 10 | 10 |
| H1：新论文讲解 | 8 | 14 |
| H2：新论文 PPT＋完整稿 | 6 | 10 |
| H3：每侧一个方案，各最多 2 次＋独立评价 | 6 | 6 |
| 合计 | **50** | **70** |

每周期按这组路由为完整最坏情况预留 70 次，不再因为旧剩余 64 次而放弃必要比较。开发阶段先最多 40 次（校准 6＋D1 10＋D2 14＋D3 10），达到阶段门槛才支出留出的最多 30 次；失败就提前停止该候选，余量不自动转换成额外重试。默认不增加额外模型微试，也不重跑完整稿和失败题来耗尽余量。路由变化或新留出带来额外调用时重新计算并冻结，优先简化无收益环节或另列尚未覆盖项，不悄悄突破上界。

每批仍最多 24 次、45 分钟；每个比较单元先预约完整两侧上界，单个正常任务仍最多一次自动修订。多个批次共享当前周期余量和后续累计账本，不重置总额。超时、取消、结果未知、额度错误或版本变化停止原周期，不自动续发。对已明确只是批次准入不足、没有未知派发的情况，可以另批继续同一冻结候选；先确认下一完整单元和足够时间可预约。截止临近就延后，不能启动已知完不成的单元。

用量控制落实到单次请求：记录角色、输入／输出大小、相关材料覆盖和耗时；材料裁剪先验证必要原理、图注、参照与局限仍完整。首个真实单元建立按角色的用量基线，后续相同范围异常增加时先核查重复材料、无关历史与异常输出，不以继续重试解决。现有模型上下文／输出限制继续生效；如需改变，作为明确配置差异记录，不能用截断核心内容换省钱。

相同请求、基线版本、工程、来源、图件、路由、评价及配置的已完成有效基线结果可以跨周期复用，明确标注原运行和哈希，不算新派发；任何一项相关输入改变就重新生成。候选真实输出仍重新运行。新评价仅复用严格匹配的校准，不复用旧结论冒充新版通过。默认不复跑未改变的完整实验，开放式学习试验仅在最终合格候选上运行一次。

工程修复和来源只读走查不占模型调用，但记录本地时间与资源。到达三个周期上界时给出阶段结果与未解决原因；若仍有明确新假设和价值，可提出下一阶段的具体范围，不能无期限自动增加周期。授权额度充足不构成必须用满的理由。

## 9. 成本和负荷如何判断，怎样保护核心功能

成本报告按案例及角色分开，列任务成功／失败、首次通过／修订、实际尝试、输入／输出／缓存 token、缺失用量、provider 时间、排队时间、端到端时间和实际请求范围。配置值与服务实际返回值分开；未暴露的返回配置记未确认，不默认为已验证。没有账单不推算现金费用。

完整稿有额外输出开销；当前 D1 属于“六页＋逐页稿＋完整稿”，其成本不能代表普通讲解或不带完整稿的 PPT。失败路径的用量也保留；成功率差异必须先解释，不能拿失败基线计算省钱比例。

优先采用不改变科学质量的节省办法：复用原 PDF 与冻结解析、去重相同材料、仅为实际使用图件准备高清资产、按任务发送所需材料、同一次生成完成已请求稿件、对未改变且哈希一致的评价校准复用记录。片段缩减必须保留相关图注、定义、参照和限制；不能为降低 token 删掉必要原理。

训练保持单模型请求串行，在线维持既有调度。每个新训练单元前检查在线队列和本地资源；在线有待运行用户任务时延后训练单元，不插队，也不自动取消在途用户任务。训练与在线进程分开不代表远端账号额度隔离，共用账号时记录竞争情况，不能保证远端无影响。

进程 CPU／峰值内存明确所属进程和采样范围；若记录本地模型客户端，独立记录，不混称整机或远端计算。响应和页面操作发现退化时停止发起后续训练，保存正在运行单元的状态。常用存储、导出和阅读操作继续可用；无收益的常驻进程、整机监控平台、在线加角色与无限重试不作为默认优化。

成本本轮设置硬调用上限、批次期限和单元准入。token、耗时和内存先建立同请求的实际分布，未验证前不编一个“平均必须低于某数”的成功标准。若候选在同样成功且必要解释完整的任务上增加调用，或用量／耗时增加超过 20%，触发明确收益复核；该 20% 是本轮预定复核触发值，不是实测性能或自动拒绝线。没有具体质量收益就不启用，不能靠一次较快结果宣称稳定提速。

## 10. 开放式学习试验：先修曝光合同，再谈学习效果

当前开放作答入口已经存在，但本轮正式启动前须完成零调用检查：

- 学习材料按实际教学案例与可见范围绑定，不能仅按论文名统一塞入整份材料包。两套规则的材料控制分支使用相同材料；若候选的变量就是资料组织，教学／资料效果必须另行分开设计，不能声称只变了教学。
- 目标题目与此前练习不同；按研究、问题、目标答案和原图逐项检查重叠。目标资料是答题所需输入；目标助手答案、评分细目、评价备注和目标提示不进入独立作答输入。
- 复述、设计、提纲各用固定初始画像的独立克隆，记录原始作答、实际曝光、版本、历史和来源。模型先验不能靠提示清除，记额外知识，不把模型自报状态写成掌握。
- 需要读图的目标，给所有分支提供相同的必要原图及定位；如果只给文字，就把任务限定为文字证据分析，不能声称检验了原图阅读。不能从原图不可见却回答流畅推断理解。
- 教学分支只使用成功交付的对应产物，不传完整 TaskRun、反馈或评价。失败教学记未运行，不能用失败草稿、固定模板或另写的目标答案替代。

本轮建议把重复控制合并为四个预先固定条件：未看此前材料、只看相同此前材料、材料＋基线实际教学、材料＋候选实际教学。目标必要资料四者相同，区别仅在此前曝光。前两个条件本来不受规则版本影响，不必复制两套再称不同教学条件。

三类任务各四个条件，一次原始作答＋一次独立评价，共 24 次。另最多 4 次用于学习评价正反例校准、8 次用于实施前选定的一类任务全四条件复测，总计最多 36 次；不能看完结果才挑最容易出提升的题。重复和停止条件在学习协议内先冻结，必要时未运行如实记录。

产物留出全部验收后才进入学习试验；若某侧预定教学失败，保留对应分支缺失，不能再声称完整的基线／候选教学比较。可以报告有效候选教学相对材料控制的限定表现，但不得伪造缺失对照。学习评价失败与产物发布结论分别列出；单次模拟和少量复测仍不证明真人学习或稳定因果收益。

汇报任务检验的是证据组织与提纲，不代表初学者已能操作软件、独立产出可用 PPTX。若今后检验实际制作为新任务，需要单独安排文件与操作验收，不把提纲正确换算为制作能力。

## 11. 实施阶段、交付与停止条件

| 阶段 | 具体工作与交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| R0：零调用诊断与协议准备 | 根因追踪表；评价细目与例子；候选设计；原图／材料／版本清单；精确预算；必要合同及回归测试 | 已知问题可定位；分清已完成与待实现；无泄漏；剩余额度和每例上界可核查 |
| R1：评价校准 | 最多 6 次；保存每维预定判断、实际判断、位置和来源 | 全部适用项 valid，能区分遗漏、深度、事实错误与真实局限；失败先修评价并新冻结 |
| R2：D1 首个真实比较 | 首周期普通请求重新生成两侧，后续按条件复用有效基线；首稿、修订、独立评价、用量与失败证据 | 候选必要原理完整、参照正确、修订无新阻断错误、工作记录未污染正文；未达标停止该候选并诊断 |
| R3：D2／D3 开发与日常回归 | 讲解及方案真实比较；条件变更记录；按改动选择浏览器回归 | 候选三类开发无阻断失败，没有确认退步；候选冻结，额度能覆盖完整留出 |
| R4：三类留出与文件验收 | H1–H3 配对；实际 PPTX 渲染／备注／完整稿检查；方案与讲解直接检查 | 候选全部必要维度通过、实际文件一致、收益具体、成本可解释；不足保留基线 |
| R5：学习试验 | 曝光检查；四条件开放作答；独立评价及预定复测 | 输出原始作答和限制，按真实运行范围写结论，不保证一定出现提升 |
| R6：发布或保留 | 结论报告、工程验证、Git 提交、有效版本验证及回退记录 | 发布仅覆盖已验范围；新请求确实装载对应规则／合同；旧任务与历史稿保留原版本 |

R0 的最小可实施产物包括：来源追踪合同、首稿／修订版本关联、必要解释评价细目、逐例预算、兼容旧协议的新增额度版本与前序消耗核实、学习曝光与目标泄漏测试。A–C 各自经过所需的 R0–R4；失败有依据才进入下一候选，R5 只针对最终合格候选，R6 汇总实际完成范围。新增接口／字段／文件名由实现阶段确定；不能把这里的拟议合同当成已经存在的能力。

工程基线是当前构建及 159 项测试通过。下一轮运行与改动相符的检查：输入隔离、普通讲解无额外 PPT、真实 PPT／完整稿原路径、方案来源／条件／版本、取消／未知不重发、预算继承、修订事实变更定位、无效评价拒绝、学习曝光隔离。测试重点是有意义的输入与失败场景，不写仅复述实现的断言。

界面未改时按影响选择浏览器路径；影响生成、修订、导出或调度时，检查对应操作和错误流程。真实 PPT 成功后用实际文件渲染检查原图、轴／图例、裁剪、文字和备注，完整稿对照保存页面；失败不另造 PPT 以完成验收。讲解、方案直接检查其实际输出及所支持导出，不增加别的产物凑闭环。

## 12. 发布、回退与最终报告

发布需要：已指定缺口有可核对改善；候选的三类开发与留出无阻断失败；事实、必要解释、可理解推理、范围、图稿和文件合同满足；没有已确认退步；成本增量有具体收益依据；相应工程检查通过。平均分不能抵消事实错误。旧案例失败可以证明原路径有缺口，不能证明所有用户请求都会失败，也不能拿它作成功提效基线。

基线已知失败不等于比较无效，也不要求把基线改到通过后才比较。两侧实际尝试与结果须可核查；有失败草稿时按真实稿评价，无产物时记录生成失败，不编内容分数。结果未知或评价无效时不能当作已确认基线劣势，按停止条件处理。

不足时结论写“保留在线基线”，保留候选、未确认项、剩余预算、下一缺口及未运行案例。若只完成开发，就只报告开发；若三类产物通过但学习未完成，就只报告限定产物改进。发布不是宣称广泛科学质量或真人学习已证实。

启用规则／合同与版本用 Git 提交；实际新请求核对加载哈希，禁止静默模型回退、历史草稿换版本或在途任务追随新规则。回退采用新提交，并验证未来请求恢复指定版本，保留比较证据及历史。实现任务在 `main` 提交结束，只暂存本任务内容，不推送、不重写历史。

最终交付包含根因与候选说明、冻结协议、逐例前后结果与来源、首稿／修订新增错误、真实成功文件、调用／用量／负荷、失败与未知、留出状态、开放作答原文及曝光、发布或保留结论。交付时用户只需知道“改好了什么、仍缺什么、为何值得这些消耗”，内部记录按需查看。

## 13. GitHub 学习的使用方式

沿用上一周期归档的 [DSPy GEPA 官方资料](https://github.com/stanfordnlp/dspy/blob/bc8af7ed3d5ee0b892211e5c03274396442a413c/docs/docs/diving-deeper/gepa-in-depth.md)与 [promptfoo Rubric 官方资料](https://github.com/promptfoo/promptfoo/blob/0c7829916095bf274501b2b6438a0223d66b966e/site/docs/configuration/expected-outputs/model-graded/llm-rubric.md)：保留具体失败反馈和逐例追踪，明确通过／失败与评价有效性，固定评价配置。本项目继续使用已有运行器，不因借鉴而安装整个框架。

新方法进入下一候选前写清：解决哪个已观察缺口、改变哪一个层面、依赖与成本增加多少、如何验证、不通过如何恢复。来源固定到官方文档／代码的提交及已读范围；不开默认外部发送，也不把论文或个人笔记上传到新服务。只读调研不算模型能力收益，安装工具不算训练完成。

本方案的首个动作是 R0：完成零调用根因追踪、评价细化、修订与曝光合同检查和预算确认，再冻结一个值得测试的候选。这样下一轮能给出清楚的改善或失败依据，并保护正常用户的三个功能。
