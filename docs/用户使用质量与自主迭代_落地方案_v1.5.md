# 用户使用质量与自主迭代：下一阶段落地方案

v1.5 · 2026-10-08 · 工程起点 `83d2894`（main）。

状态：文档已落地，代码、额度扩展及新评价尚未实施。本次新增产物模型调用为零，不修改运行账本，不启用新教学候选。

本方案承接[小样本闭环 v1.4](小样本闭环与整体交付_落地方案_v1.4.md)及其[实施验收](小样本闭环_v1.4_实施验收.md)，是[整体主方案](科研能力培养与三类Agent协作_整体落地方案.md)的下一阶段执行细则。执行者自主发现问题、实现、评价和取舍；用户继续使用三个核心入口，可随使用提出意见，不承担技术决策、测试组织或逐稿审查。

## 1. 核心目标与真实起点

在明确范围内，让用户拿到可信、易理解、少返工的讲解、PPT／讲稿和研究方案，检查工作流是否比合理使用同一模型更有帮助。每个改动回答：用户有什么困难、如何减少、证据是什么、成本是多少、还有什么限制。

上一轮短闭环、分层时间、优雅暂停、来源范围及完整稿实际原图核对已实现，生产构建、202 项测试和四组浏览器回归通过。两页图稿和六页 PPT／完整稿实际导出、打开、渲染；资源变化方案有范围内设计走查证据。工程通过不等于广泛科学质量或教学效果通过。

遗留问题：短讲解实测约 145 秒，30–60 秒目标未达成；完整稿四项普通警告未全部关闭；干预身份曾需执行者手改；完整多面板图小标签仍有限制；自动选材、跨论文质量和实际实验可行性未全面验证。正式六例比较、C 发布、开放学习、真人效果、国内模型仍未完成。

本阶段走产品使用质量路线。已验证的工程改进可以提交，局部样本不作为新教学候选发布证明，不拼接成旧正式比较通过报告。

## 2. 累计要求与执行者职责

新的自主权和资源不覆盖以前要求。启动与收尾逐项核对以下约束，落实证据写入当轮记录。

| 累计要求 | 执行与检查 |
| --- | --- |
| 三个核心入口服务日常使用 | 论文讲解、论文 PPT／完整稿、研究方案均扫描影响；不强制先完成课程、考试或另一种产物 |
| 科学事实、解释与边界优先 | 回实际原文／原图检查方法、比较和推理；不编参数、条件、结果或引用；速度和美观不能抵消重大事实错误 |
| 最小完整任务→针对修复→必要整体回归 | 保留必要上下文、方法、图注和单位；不写重复长导读；跨段或共享组件变化才扩大回归 |
| 简单的用户路径 | 沿用现有布局，来源、笔记、偏好和历史服务主流程；辅助内容按需展开；内部角色、评测、额度不搬到前台 |
| 图件和编辑边界 | 优先原论文图件，保留轴、图例、标签、比例尺；定位失败用原页或手选；不新增逐条自动截图识别、素材专区、研究方案转 PPT |
| 正常保存／导出合同 | 只有成功完成当前核对的保存版本可正常导出；阻断／未核对版本保留草稿；手改、恢复与完整稿失效规则沿用主方案，不改警告等级放行事实错误 |
| 预算与历史保护 | 同一累计账本，失败／取消／未知计数，未知用量不填零；不清历史、不续发旧 attempt、不加第四候选绕约束 |
| 自主推进且考虑限制 | 常规可逆取舍自行处理；无收益停止分支；不默认加代理或评审委员会；仅必要授权／不可逆边界才交用户决策 |
| GitHub 与客观评价 | 检查代码、测试、失败案例及适用条件；方法落实到检查；star、宣传、模型高分和测试数量都不能单独证明效果 |
| 提交与资料保护 | 编辑前检查 git status，已有／并发改动属用户；只暂存本任务，审查最终差异并验证后在 main 提交，报哈希，不擅自推送／重写历史 |
| 未完成范围如实保留 | 国内模型、真人学习、正式参赛材料、多用户部署无新证据就保持未完成；自主授权不扩成对外发布授权 |

执行者负责技术问题、原文／原图走查、浏览器操作、实际文件和内部对照。用户自发意见作为问题线索，不要求用户写评测题、逐页审稿或找专家。缺领域人员或目标用户反馈不阻塞工程工作，但执行者和“小白”模型扮演的反馈不写成真人效果。

## 3. 多方面扫描，按影响选择问题

每轮先扫描下表，再选择最多两个主要问题，避免“全面”变成全量重做。优先顺序：事实错误／资料丢失→任务无法完成→理解与返工→等待与成本→非核心美化。频率缺数据时标未知，不凭想象写高频。

| 检查面 | 实际关注点 |
| --- | --- |
| 来源与事实 | 原文已有依据是否漏选，核对实际输入是否支持结论；数字、单位、组别和比较是否一致 |
| 解释与阅读 | 是否回答当前问题，术语／测量／判断是否连接，是否重复或过长；深浅调整与追问是否保留上下文 |
| 操作与可发现性 | 普通入口能否开始、看来源、改稿、保存、返回；是否依赖隐藏 source ID 或开发者手修 |
| PPT／完整稿 | 原图、裁剪、标签、备注、页序、转场、密度；预览和实际导出分别检查 |
| 研究方案 | 资源是否支持建议；替代解释对应测量与比较；条件变化是否更新设计；未知是否具体 |
| 等待与失败 | 排队／生成／核对／修订／保存／渲染时间；取消、缺材料、服务故障和恢复是否清楚，旧稿是否保留 |
| 模型边界 | 长上下文遗漏、小字读图、结构失败、结果波动；区分本地错误、材料缺口与模型限制 |
| 数据与环境 | 凭据／个人资料不进 Git 和普通日志；现有 Host／Origin、指令注入防护、记录隔离不回退；不影响用户服务 |
| 偏好与迁移 | 临时要求与长期偏好不混淆；相邻问题仍正确；开发成功不推成跨论文教学收益 |

每项记录触发输入、用户可见现象、来源／版本、影响入口、根因证据、改动变量、验证与剩余边界。复用现有记录和脚本，仅补必要字段，不另建评测平台。

## 4. 首轮实施顺序

| 步骤 | 动作 | 关闭条件 |
| --- | --- | --- |
| 0：零调用准备 | 冻结方案、实现、来源、问题和评价；核实预算及旧请求／在线准入；从现有 observation 拆耗时 | 对照、最坏调用、证据位置和停止条件可复核，未知保留 |
| 1：已有内容缺口 | 对完整稿四项警告补实际来源、收窄结论、补可靠出处或减少无依据解释 | 新正文／备注／完整稿与核对输入一致，逐项有处置依据；保存新版本，不删旧警告；正常核对与导出 |
| 2：使用负担和效率 | 选一个已定位瓶颈，减少重复导读、无关来源或无效重复步骤；必要时改等待／失败提示 | 相同任务的事实和必要解释不退化，阅读／返工或等待有改善，否则保留旧流程 |
| 3：三任务对照 | 按第 5 节运行，保存各侧首稿、核对、失败与实际文件 | 三对结果完整或注明未运行原因；内部原文和文件走查完成，结论限定任务及预算 |
| 4：针对修复与迁移 | 定位通用根因，复测受影响入口；共享改变做工程回归，必要时完整稿／资源变式回归 | 修复有复测；曝光评价题转开发案例，不能继续当未见验证；无收益结束分支 |
| 5：交付 | 提交改动、文件、逐任务比较、成本和限制，更新状态 | 科学、解释、文件、操作和效果分别报告，不只报测试数量或花完额度 |

第 1 步不强求警告全部消失。跑台方法要补核对实际片段，不能混同完整原文与压缩输入；人组织范围和最长寿子集按原文限定；mRNA 基础解释有可靠出处才补，找不到则保留限制或删掉非必要无依据段落，不虚构引用。

速度目标沿用 v1.4：短讲解 30–60 秒、90 秒诊断，小制作 2–5 分钟，完整制作按规模判断。记录排队、首可读、完整合格答案及最终文件；失败不算快速成功，进度不冒充可读答案。少数样本报告逐例时间，不计算不可靠的 P95 或宣称显著提速；调整目标写实测理由，不靠扩大期限证明改善。

## 5. 公平、有限、可复核的评价

### 5.1 新任务与材料独立性

第一轮各入口一个新任务，生成前固定目标、材料、范围和标准，不从生成后挑成功段落。普通入口取得材料，冻结源文件与版本；评价答案不进入生成输入。

| 任务 | 最小完整范围 | 核查重点 |
| --- | --- | --- |
| 讲解 | 一个方法／结果问题，保留必要上下文与比较 | 测量→比较→读数→判断能讲清；出处支持；推断与未知区分 |
| PPT／备注 | 新开发图的两至三页 | 方法到结果连接，轴／组别／统计标记可读，实际备注和 PPTX；完整稿或共享导出变化另做整体回归 |
| 方案 | 新问题与明确资源，问题→替代解释→测量／比较→分析→限制 | 不编条件；分不清的替代解释承认；新增资源变式和固定追问各自预约调用 |

这只是选题规则，当前尚未生成新冻结案例。已跑 Xu／蛋白题不改名算新任务；优先新合法可用材料。Passos／Bell、握力／血脂继续保留，不为凑新题消耗留出；确需使用时记录曝光、退出旧留出身份并调整验证。不具备可核查资料的任务不运行或仅作诊断，不让模型自造标准。

### 5.2 合理对照与同等资源

A 为同模型简化流程：相同用户目标、可用资料、图像能力、输出范围和必要保存／导出工具，使用合格提示，生成＋核对。B 为冻结的当前智能体，经正常入口运行。首轮每侧两次产物调用，先预约整对；模型版本、设置、来源、实现和环境绑定，运行顺序交替或随机。

可用资料相同，智能体自动选材属于受评能力；不能事后手补遗漏再称首轮成功。实际输入范围、token 各自记录。若为定位问题改成完全相同片段，另记受控诊断，不混为端到端效果。对照不能刻意禁原图、合理提示或导出制造劣势。

两次预算评价首轮表现，不代表正常最多四次流程全部能力。需要修订的结果保留原等级和成本，后续修订单列，不覆盖首轮；一题一次不证明稳定性。固定追问、资源变式、额外模型评分和重复都另计调用。

简化流程复用 provider、来源、核对和正常导出合同；失败稿可供内部评价，不能人为放行未核对／阻断版本给用户。正常使用成本与受控资源比较分开报告，不把人为缩减预算导致的失败说成模型绝对不能完成。

### 5.3 分项判定，错误不能被高总分抵消

| 维度 | 记录与判断 |
| --- | --- |
| 任务完成 | 直接可用／少量修改可用／大量返工／失败；局部措辞或裁剪可属少量，核心事实、方法或结构重做属大量；所有失败／取消／超时／未交付进分母 |
| 事实与边界 | 关键主张逐条绑定原文／原图／条件，列具体错误和遗漏；编造关键数字、条件、引用或反转结论直接失败 |
| 解释支持 | 必要术语、比较作用、推理连接和未解释处；执行者检查这些要素，但真人理解仍待真人反馈 |
| 使用与文件 | 普通入口的操作、追问、手选、修改次数及实际文件；隐藏输入／手修计入，不拿预览代替文件 |
| 时间与成本 | 排队、可读回答、完整答案、文件及分阶段时间；全部调用、已报告 token 和未知；不能只选最好一次；现金未核对仍未知 |
| 鲁棒性 | 只记录实际触及的缺条件、长材料、难定位图和服务故障；不为全面额外跑所有边界组合 |

不合成掩盖问题的总分。逐任务列 A／B 等级、错误、解释缺口、返工、时间和成本；胜／平／负只描述本例。只有三个任务就写具体范围，不报告广泛成功率、统计显著或普遍教学收益。

### 5.4 自主评价的独立性边界

确定性检查负责格式、来源定位、状态、文件打开和实际图像绑定；执行者回原文／原图核查主张与设计，现有模型核对用于发现问题，不默认追加第三份付费评审。同一模型换角色或线程不成为独立事实裁判。

输出可匿名、交替顺序检查，减少标签偏好；执行者参与开发且能看过程，仍为内部评价，不能叫独立盲评。标准在生成前冻结，不利结果、分歧和未知保留；重判保留旧判定及理由，不静默改分。

用户自发反馈记录任务背景、具体困难、观察和原话，区分偏好与事实；不自动上传遥测，不要求额外测验。领域人员／其他用户以后真参与才另记角色与过程。缺该层证据仍交付内部结论，真人学习与长期效果继续未验证。

## 6. 模型、材料和环境限制

| 限制 | 处理与停止条件 |
| --- | --- |
| 长材料压缩遗漏 | 检查实际片段，补完整必要块；仍放不下则限定任务范围，不称已读全文 |
| 小字／复杂读图 | 原始分辨率回查，沿用原页、手选或裁剪；两页可读不代表整份所有细节可读，无法确认就保留未知 |
| 多角色自洽错误 | 回原文／原图核实，不能用多数模型同意关闭事实问题 |
| 慢调用与波动 | 减少已证实的冗余步骤，改善等待和恢复；连续两轮针对尝试无收益结束，不无限续时或加角色 |
| 研究条件不足 | 给可做部分、缺条件与备选，不编设备、样本量或参数；草案通过不等于可立即实验／临床应用 |
| 结构失败／取消／服务异常 | 保存原稿和用量，优雅中止，有界核实；新未知／活动迹象时停止付费派发，继续零调用工作 |
| 本地工具不可用 | 保留源文件并报告限制，用可信已有替代；缺实际打开／渲染证据不判文件通过 |

不偷偷更换 provider，国内模型维持暂缓。无法通过工作流改善的能力边界，明确降低承诺或保留手动路径，不宣称算法解决。

## 7. 预算扩展和阶段安排

核对起点累计 108 次＝初轮 44＋前两后续周期 22＋第三周期 42。第三周期原上限 70，剩余 28。v1.4 分路已用首轮 10／12、第二轮 8／12、整体 12／20、修复 7／21，余额分别为 2、4、8、14，合计 28。旧入口另有重复样本和准入约束，不能只看总余额就强塞新比较。

用户已允许增加额度并授权自主取舍。本方案采用增量 30，下一阶段计划上限 **58＝原余额 28＋新增 30**，不要求花满。第三周期计划上限 100；本阶段最多用完后，累计历史 166＝44＋22＋100。后续产物总上限 210 可继续保留，本阶段结束最多 122，不必扩大它或混入初轮 44。本次文档不使运行额度生效。
