日期：2026-10-09。审计代码基线：`8d4756e`。状态：**整体复核已完成，以下整改尚未实施**。本次只修改文档，不改变产品代码、有效 Skill、模型配置和运行账本，不启动付费模型实验。

## 1. 核心结论与责任

工程基础已经可运行，但不能称整体需求已交付。已真实运行的是局部带读试读闭环和各生成任务，不是完整的跨功能教学能力闭环。上一轮把“规则写了”“代码接了”“流程结束”和“用户目标达成”混为一谈，导致完成评价偏高。

最主要的遗漏：用户说 PPT／方案是小功能，指用户侧轻量、直接生成、下载后自行修改；这不降低它们在内部学习验证中的价值。**前台三个入口独立，后台教学、汇报和设计交叉检验**，两者必须同时成立。

此前 54 个编号只覆盖用户端功能，内部协作放在单独章节，没有同等细致的验收追踪。现在补齐内部能力、成本和模型路径编号，并把规则存在与效果成立分开。此问题不归因于用户表达不清，也不要求用户重新完成问卷。

## 3. 状态定义

| 状态 | 必须满足的证据 |
| --- | --- |
| 规则已配置 | 提示词或 Skill 有要求；不声称程序保证或行为稳定。 |
| 工程已接通 | 输入、状态、材料、输出有实际代码路径，相关确定性验证通过。 |
| 真实单例通过 | 指定模型、规则版本、材料和目标下，内容及必要产物验收通过。不得外推其他范围。 |
| 部分实现 | 有代码或运行基础，但用户目标的关键环节缺失。 |
| 待实现／待验证 | 分别说明没有对应实现，或有实现但缺运行证据。 |
| 失败／未知 | 有明确失败则保留失败；远端终态不明则保留未知，不当作成功或零成本。 |

“本次调用成功”“任务 completed”“没有 blocking”“页面排版正确”“学生真的会了”是五种不同结论，必须分开记录。

### 5.1 闭环 A：把产物做好

固定来源与目标 → 导师生成讲解／PPT／方案 → 必要的独立内容核对 → 对代表性产物做小白试读或试讲 → 汇总具体问题 → 导师一次定向修订 → 原问题及受影响内容复核 → 成品与原失败分别保存。

在线通常只运行任务所需环节；内部诊断可运行完整链。PPT 要另外检查真实文件的图文和排版，方案要检查设计与实际限制。审稿通过不等于小白已经学会。

### 5.2 闭环 B：检验导师是否教会

固定能力目标 → 导师实际教学 → 小白在隔离输入下独立完成新设计／汇报／证据解释 → 校验原始作答 → 定位根因 → 导师补教或修正原教学 → 同题纠错单列 → 新条件任务再次独立作答 → 判断改进是否保留 → 汇总可复现缺口供 Skill 迭代。

示例目标：理解“一个对照排除哪种替代解释”。带读讲明原实验；汇报要求解释选用哪个比较支撑结论；新方案改变对象或资源，要求重新选择对照。三条线共用能力目标，但小白独立任务不得先看助手目标方案或标准汇报。

### 5.3 每次交接的最小记录

复用已有 TaskRun、材料快照、OpenLearnerRecord、版本和账本，新增缺失字段而非重建平台。记录：能力／目标 ID、任务与父任务 ID、论文及来源版本、实际可见教学和材料哈希、角色／规则／模型、原始回答、问题位置与依据、反馈去向、修订前后版本、复核结果、费用和终态。

反馈必须区分材料缺失、事实错、推理错、必要基础未教、教学衔接断点、学生误用、表达不清和用户条件不足。校验报告不能整份塞给小白以泄漏目标答案；公开补教、目标提示、直接改写分别标记。同一错误在三个产物中重复出现不算三份独立证据。

### 5.4 接续旧实现的方式

`server/internal-learner.ts` 已有开放作答与曝光隔离，`scripts/internal-learning.ts` 有旧协议的准入和条件比较；新 `mentor-iteration.ts` 的报告结构不能自动进入旧学习阶段。下一步建立有版本的适配／共同运行合同，验证材料、教学、文件验收与预算来源后接入。不得为了跑通删除旧门槛、伪造通过、重置历史账本，也不另写一套丢弃原基础的训练器。

### 5.5 Skill 采用的具体规则

每次候选只解决能指向真实输出的具体问题，冻结旧版、候选、输入和判据。比较时双方取得各自真实使用的最终材料，自动补入的基础资料不能漏掉；评价标准不能在看见结果后改成偏爱新版的指标。

采用至少满足：目标缺口确有改善、关键科学内容无新增退步、涉及的生成和阅读路径不回退、未参与修改的任务在约定范围内通过。若新版排版更好却术语或推理变差，应定向修订并重验，不能按总分掩盖。blocking、评审无效、关键请求 unknown 或最终规则未受测时，不能标为已完成该范围验证。

首期由执行者自主完成有记录的采用决定，通过现有规则文件、版本和 Git 发布即可，不要求新增发布平台。保存决策、对应证据和上一有效版本，检查真实后续请求加载哈希；发现退步回退对应规则，不清理失败历史。代码里只有 reviewed-candidate 文件时，状态仍是候选，不是已采用。

## 9. 不能遗漏的验收场景

| 场景 | 要观察的实际行为 |
| --- | --- |
| 新导入论文 | 背景、目的、价值后进入首个学习单元；不过多确认；未可读材料明确提示。 |
| 当前实验中改重点／深浅 | 不跳转、不丢问题；局部和持续要求区分；后续可再次调整。 |
| 看不懂并要求查资料 | 带读能按缺口补查并回到论文；不把外部背景冒充原文。 |
| 跨页方法—结果—图 | 实验目的、分组、对照、读数、结论连贯；数字和来源可回查。 |
| 回答与 PDF 分别选句 | 引用归属正确、可编辑追问、可取消；原文和 Markdown 校验不混用。 |
| 同页多来源／前情＋当前 | 能打开对应正文或图注；翻译范围正确；回到回答保留位置。 |
| 同类图连续出现 | 第一次解释读法，后续聚焦结果但说明变化；用户要求可重讲。 |
| 长段与总结 | 长讲不被固定小块破坏；总结覆盖关键实验和证据，未读部分不装作读过。 |
| PPT 普通生成 | 无精读门槛；原图可读、文本可编辑、讲述提示独立；科学警告和版本一致。 |
| 方案参考在后半篇 | 选中相关方法／结果而非只看前言；自由限制进入检索和生成。 |
| 方案有 warning／blocking | 必要提醒在预览和导出一致；阻断内容不能标可交付。 |
| 旧 PPT 与历史笔记 | 新界面可访问旧成果，不新生成、不修改历史归属。 |
| 关闭／断网／重启 | 保存身份与资料，恢复原任务；不重复收费，不无限假思考。 |
| 独立设计与汇报失败 | 记录未经改写的原答，反馈正确归因，补教后用新题检验；不能直接抄目标产物。 |
| 小白与校验者不一致 | 回源定位，不多数投票、不机械逼改；合理不同方案不误判。 |
| 最终规则采用 | 精确版本、最终输出和采用理由对应；验证后续加载及可回退性。 |

自动测试负责确定性契约；浏览器负责真实可操作性；文件渲染负责实际成品；真实内容审阅负责科学与教学质量。四者不互相替代。模拟学生只能支持限定条件下的诊断，不能代替真人科研能力提升证据。
