# 内部迭代的规模与验收范围

用户允许按情况用小样本节省成本；这不是将完整产物限制为小样本的授权。每轮根据缺陷选择局部回归或较完整场景。局部回归通过，只能说明对应问题得到验证。

## 当前入口（2026-10-25 核对）

| 项目 | 原行为 | 当前行为及边界 |
| --- | --- | --- |
| 活动诊断 PPT 页数 | 清单仅允许 3–6 页 | 允许 1–16 页，与产品范围相同；默认 4 页可覆盖。不是所有实验均需 16 页 |
| 活动诊断材料 ID | 最多 20 个 | 带读/PPT 最多 100 个，与正常输入一致；方案仍遵守产品最多 12 个来源选择项 |
| 活动诊断调用额度 | 固定 8 次 | 清单 callLimit 可设 4–64，默认 8；准备时冻结并在运行前核验，报告按实际额度计算余额。额度是成本边界，不是目标调用次数 |
| 方案诊断内容范围 | 固定简短 design-draft | plan.requestedScope 可选 direction / design-draft / full-plan；生成要求随范围变化 |
| 方案诊断深度 | 固定 standard | plan.verbosity 可选 brief / standard / deep |
| 方案每阶段修订额度 | 固定 maxCalls=2 | plan.maxCalls 可选 2 或 4，沿用产品的有界修正；修正前草稿保留，按每阶段最终保存版本评价，并校验完整父子链 |
| 带读流程 | 当前诊断走正常带读 | 未额外强制片段模式；短循环工具的 fragment-v1 属于明确的局部诊断，不得把其结果当完整带读验收 |

## 仍存在的产品与材料边界

- PPT 成品最多 16 页。带读单次结构化输出最多 10 节；PPT 的辅助导读最多 3 节，不限制其实际幻灯片数量。
- 方案正文最多 12 节；正常入口的参考材料自动选择最多 12 项摘录、约 18,000 字符。章节数量不等于质量，完整方案应有实质设计。
- 带读/PPT 的材料包通常最多约 20,000 字符，普通 PDF 长材料还会经过相关段落选择。增加 sourceIds 并不保证全文全部送入模型。实际暴露的段落与图件必须依据角色输入核对，不能仅凭上传成功宣称全文读完。
- 方案诊断的两阶段是“初版→资源变化后的修订”这一实验形状；修正草稿可以增加历史版本，不能将历史版本数量固定为两版。它不限制产品中的持续修订。
- 较早脚本中的固定批次、校准池和六页场景是对应实验的预设；旧冻结记录不改写。继续使用这些工具时，必须明确是局部回归还是整体验收，不能将旧预设当通用能力上限。

## 后续迭代约定

先说明本轮想发现什么，再选择材料范围、产物规模与预算。视觉主线问题要跑足以展开研究的页面并逐页检查；方案完整性要实际选择 full-plan；带读要检查指定范围的方法—观察—判断与迁移推理。保留费用账本、未知结果与真实耗时，不为多跑次数而重复已通过的同一检查。阶段性验收混合局部与完整场景，记录未覆盖范围，不以少数评分代替产品结论。
