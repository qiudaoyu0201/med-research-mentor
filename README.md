## 启动

默认首页是论文研究工作台。无需创建课题即可点击或拖动导入一个 PDF（30 MiB、100 页以内）；导入后进入该论文主聊天，可直接提问。课题与论文可重命名、移动、归档；讨论、笔记和阅读位置保存到后台，草稿和提问引用按论文保存在浏览器。最多两个不同论文的聊天或 PPT 修改同时执行，同一论文顺序执行，等待任务可逐项取消并恢复问题编辑。资料默认读原始 PDF，选中实际文字后可解释或引用，预填后由用户发送；提取内容仅作当前来源核对。输入区统一通过加号添加 PDF、PNG、JPEG，也可拖入或粘贴；点击发送才上传。PDF 开启新论文聊天，补图留在当前聊天。PPT、设置和个人记录直接在当前前端打开。阅读起点默认手动整理；设置中可显式开启自动整理，`TUTOR_READING_GUIDES=manual` 仍会禁用自动调用并保留主动按钮。

<http://127.0.0.1:4317/prototype> 保留固定示例布局，用于视觉对照；该页的 PDF 仍仅本地预览，不解析或生成教学内容。原型浏览器检查继续面向 `/prototype`，历史教学检查面向 `/assistant`。

新界面验证：`npx tsx checks/browser-prototype.ts`，先启动服务。检查任务、来源联动、笔记恢复与导出、PDF 添加、键盘操作及桌面／手机布局，并确认原型没有发起后端请求。截图保存到 `runs/prototype/`。

真实工作台检查：`npx tsx checks/browser-workspace.ts`，默认连接 `http://127.0.0.1:4318`。请先以 `PORT=4318`、单独的 `TUTOR_DATA_DIR` 启动正式构建服务，避免测试记录加入个人论文库；可用 `TUTOR_BASE_URL` 改地址。检查真实 PDF 导入、课题归组、来源锚点、停止、笔记与刷新恢复、四种屏宽。浏览器模拟运行状态与固定示例均为零模型调用；实际正文行为另用 `npx tsx scripts/workspace-live-check.ts`，单轮最多六次调用、不自动重发，同样建议使用隔离数据目录。报告与截图保存到 `runs/workspace/`。隔离浏览器验收还需设置 `TUTOR_READING_GUIDES=manual`，避免自动概述调用模型。第二轮调度界面检查使用 `npx tsx checks/browser-scheduling.ts`（同样使用隔离目录，零模型调用），覆盖等待／取消、生成时导航、草稿及引用恢复和四种屏宽。`npx tsx checks/browser-materials-tools.ts` 检查附件、PDF 文字层、PPT、设置／记录和布局；`npx tsx scripts/second-round-check.ts --generate` 主动运行真实模型样本，最多16次调用，`--generate --parallel` 仅运行双聊天／第三任务取消样本。

Windows 双击 **启动导师.cmd**，保持启动窗口运行，浏览器访问 <http://127.0.0.1:4317>。退出按 Ctrl+C。脚本优先选择系统安装的新版 Node，避免其他软件自带的旧 Node 抢占 PATH。

需要 Node.js 22.13 或更新版本。当前已验证环境：Node 24.19.0、Codex CLI 0.160.0、Windows、Microsoft Edge。首次使用脚本执行 `npm ci`，已有依赖时不会重新安装。更新源码后执行 `npm run build`。

开发启动：

```powershell
npm.cmd run dev
```

## 试用顺序

1. 在导航导入 PDF，或在输入区添加 PDF 和问题一起发送。导入后进入该论文主聊天，可直接提问，或主动整理研究起点。
2. 点击资料查看原始 PDF，选文字后引用提问；点击来源回到已知片段或页。可以放大或展开阅读后返回原回答，也可补充原文或添加 PNG／JPEG 清晰补图。无可用文字的 PDF 不会自动 OCR。
3. 在设置中分别选择讲解程度（简洁／常规／深入）和学习重点（综合理解／补基础／研究思路／方法与图表／机制），按聊天保存。自然语言调整默认只作用于本轮，“以后都……”才更新聊天偏好；回复也能选部分文字追问。切换论文保留各自草稿和引用，生成任务继续在所属聊天执行。
4. 保存笔记、收藏解释或主动反馈理解情况。个人记录可编辑、撤销、删除、保存待解决问题和回到原讲解，设置偏好按聊天保存。
5. 进入 PPT 汇报，选择页数与重点，带上当前材料及笔记。逐页预览／编辑，保存并核对，或用自然语言修改指定页；恢复版本并导出当前保存版本。
6. 在电脑上拖动分界或用方向键调节布局；空间充足时可固定原文对照，窄窗口切换阅读后返回。设置中可选择主题／字体、恢复默认布局。
7. 进入并列的研究方案专区，只输入医学问题即可创建课题；按需补资源／来源、选择本轮范围和建议，起草并轻量核对。分节手改后保存，再核对或导出选定保存版 Markdown。未知条件保留在草稿，核对失败不丢内容，来源／版本冲突保留候选；完整跨专区同步与独立迁移尚未开放。

方案验证：`npx tsx checks/browser-research-plan.ts` 使用隔离服务，默认 `127.0.0.1:4327`，零模型调用。`npx tsx scripts/research-plan-check.ts` 对同一隔离服务主动运行两份实际方案任务，每份限制 2 次，合计最多 4 次，不自动重试；报告和产物在 `runs/research-plan-implementation/`。`--verify-existing` 只复核已有记录和导出，不再生成。未配置国内平台时这些样本使用现有 Codex，不算国内验收。

历史开发规则比较和完整旧工具仍可直接访问 `/assistant`，产品导航已移除旧工具与原型链接。

## 模型与数据

`npm run model:check` 默认检查 Codex 登录和目录；国内兼容接入只读取配置。加 `-- --generate` 发起一次当前模型的短文本请求。目录或配置存在不代表有推理权限。Codex 路径使用现有账号额度，`CODEX_BIN` 可指定其可执行文件；该路径不读取或修改登录文件，不使用环境中的付费 API Key。

国内接入使用服务端环境变量：`TUTOR_PROVIDER=compatible`、`TUTOR_MODEL_BASE_URL`（HTTPS 基础地址，含 `/v1` 等实际前缀）、`TUTOR_MODEL`、`TUTOR_MODEL_API_KEY`。多模态型号需显式设置 `TUTOR_MODEL_IMAGES=true`；默认 `TUTOR_MODEL_OUTPUT_MODE=json_object` 并本地校验，接口确实支持严格 schema 时才选 `json_schema`。输入字符额度和输出 token 额度分别可用 `TUTOR_MODEL_MAX_INPUT_CHARS`、`TUTOR_MODEL_MAX_OUTPUT_TOKENS` 调整。程序读取进程环境，不自动加载 `.env`；重启服务后生效。凭据不进入前端或普通日志。配置／生成失败不会回退到其他模型。

同一环境运行 `npm run model:check -- --generate --image <PNG或JPEG路径> --cancel`，最多三次尝试，保存文本、图像、结构与主动停止探针的输出和账本到 `runs/model-probe/`；格式通过仍需人工对照图片核查内容。若响应先于停止完成，标为 `completed-before-stop`，不能据此认定停止能力通过。实际 API 金额未配置价格时保持空值。此接口目前只通过模拟传输工程检查；目标国内模型的真实核心教学与 PPT 必须另行验收。

实时资料会发送至云端，文件和运行记录保存在 `data/`，导出在 `exports/`，检查截图在 `runs/`。这些目录不提交 Git。服务仅监听 127.0.0.1，并检查 Host 与 Origin，不用于公网部署。默认关闭环境、shell、网页、MCP 和应用工具访问；发现非文本工具项即停止任务。

模拟新手只取得固定画像、问题、可见讲解/图注、已教概念和复读断点；不取得原始方法资料、完整核对报告或案例参考答案。核对角色取得本任务材料，独立检查。相同模型仍可能共同出错。

产品中的模拟新手负责表达试读；另有开发用学习模拟，保存固定画像、真实可见讲解、实际作答与应用证据，支持跨轮恢复。两者与真实用户的主动反馈分开，不将答对一次或自称理解当作永久掌握。未接入 TinyTroupe、CAMEL 或 Generative Agents；只借鉴已核查的机制。
