# 医学科研入门导师 · 初版 0.1

本机网页默认打开接入真实后端的论文研究工作台，支持课题归组、PDF 导入、连续讨论、原文追问与笔记保存。既有完整教学和汇报 PPT 工具保留在 `/assistant`，固定布局示例保留在 `/prototype`。实时讨论使用本机已登录的 Codex 和 GPT-6.1 Sol。

按[论文研究工作台与 PPT 专区落地方案](docs/论文研究工作台与PPT专区_落地方案.md)（v1.2）完成 A 与 B1 的首轮核心流程：导入后的正文起点、原文／回复／已登记图件追问、依据查看、保存笔记与继续讨论。入门起点采用实际摘要或正文摘录及规则问题；模型生成的轻量概述、B2 图片准入与 C 独立 PPT 专区仍待实施。实测结果见[研究工作台首轮验收](docs/研究工作台首轮实施验收.md)。

最新实施依据为[研究工作台第二轮优化方案](docs/研究工作台第二轮优化_落地方案.md)（v1.3）：一篇论文一个主聊天、两个聊天并行、发送后附件检查、句子引用与讲解深度、当前前端中的 PPT 专区及可调整布局。A 阶段已实现并完成工程验收：单论文主聊天、双名额调度、同论文顺序执行、可取消等待和生成时切换／编辑。B 至 E 尚待实施；验证及边界见[第二轮 A 阶段验收](docs/研究工作台第二轮A阶段_实施验收.md)。

已按整体方案完成 A 至 E 的首轮实现：标准 skill 与有实际作答的学习模拟、主助手按需协作、统一对话与句子追问、单页修改与版本恢复、个人收藏及主动反馈。分阶段验证和边界见[整体方案实施验收](docs/整体方案实施验收.md)。基础资料沿用[迁移验收](docs/基础资料迁移与四场景验证_验收.md)，历史基线见[后端优化验收](docs/主助手后端优化验收.md)。

## 启动

默认首页是论文研究工作台。无需创建课题即可点击或拖动导入一个 PDF（30 MiB、100 页以内）；导入后自动进入该论文主聊天，查看实际提取内容并开始实时讨论。课题与论文可重命名、移动、归档；讨论、笔记和阅读位置保存到后台，草稿和提问引用按论文保存在浏览器。最多两个不同论文的聊天或 PPT 修改同时执行，同一论文顺序执行，等待任务可逐项取消并恢复问题编辑。资料面板提供原文段落、图件及对应 PDF 页，选定内容后预填问题，由用户发送。图片导入将在内容准入检查完成后开放。PPT 入口目前连接 `/assistant` 的现有工具。

<http://127.0.0.1:4317/prototype> 保留固定示例布局，用于视觉对照；该页的 PDF 仍仅本地预览，不解析或生成教学内容。原型浏览器检查继续面向 `/prototype`，历史教学检查面向 `/assistant`。

新界面验证：`npx tsx checks/browser-prototype.ts`，先启动服务。检查任务、来源联动、笔记恢复与导出、PDF 添加、键盘操作及桌面／手机布局，并确认原型没有发起后端请求。截图保存到 `runs/prototype/`。

真实工作台检查：`npx tsx checks/browser-workspace.ts`，默认连接 `http://127.0.0.1:4318`。请先以 `PORT=4318`、单独的 `TUTOR_DATA_DIR` 启动正式构建服务，避免测试记录加入个人论文库；可用 `TUTOR_BASE_URL` 改地址。检查真实 PDF 导入、课题归组、来源锚点、停止、笔记与刷新恢复、四种屏宽。浏览器模拟运行状态与固定示例均为零模型调用；实际正文行为另用 `npx tsx scripts/workspace-live-check.ts`，单轮最多六次调用、不自动重发，同样建议使用隔离数据目录。报告与截图保存到 `runs/workspace/`。第二轮调度界面检查使用 `npx tsx checks/browser-scheduling.ts`（同样使用隔离目录，零模型调用），覆盖等待／取消、生成时导航、草稿及引用恢复和四种屏宽。

Windows 双击 **启动导师.cmd**，保持启动窗口运行，浏览器访问 <http://127.0.0.1:4317>。退出按 Ctrl+C。脚本优先选择系统安装的新版 Node，避免其他软件自带的旧 Node 抢占 PATH。

需要 Node.js 22.13 或更新版本。当前已验证环境：Node 24.19.0、Codex CLI 0.160.0、Windows、Microsoft Edge。首次使用脚本执行 `npm ci`，已有依赖时不会重新安装。更新源码后执行 `npm run build`。

开发启动：

```powershell
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
npm.cmd ci
npm.cmd run dev
```

## 试用顺序

1. 打开示例论文，选带读、方法或图表，再打开教学示例。点击依据回到左侧证据位置，术语可展开和收藏。
2. 在设置中切换实时模式。科研对话承接目标和材料；“一句话／通俗说明”的普通背景问题可直接解释，论文事实继续核对，模拟试读可主动请求。选中原句后点“针对这句话追问”，调整讲解深度。实际阶段可见，可停止并查看未核对草稿。明确任务最多六次，含规划最多七次，最多一次修订；失败不自动重试。
3. 上传文本型 PDF（30 MB、100 页以内），检查提取文字、选择当前页资料。拖动圈选图件，补充完整图注；可保存圈选与图注，供后续原图嵌入。扫描文件可查看页面、手动补文本，不提供自动 OCR。
4. 打开汇报 PPT，编辑标题、要点与讲稿后，选择指定页“保存并核对”；也可按文字要求改写该页。比较或恢复旧版，再按保存版本导出。当前版本流程固定页数，增删页与重排仍属于未核对草稿。上传论文先实时生成并核对大纲。
5. 收藏段落或主动标记“读过／仍不理解／已理解”。设置里的个人学习记录可编辑、撤销编辑、删除、保存待解决问题和回到关联讲解。会话及记录刷新／后台重启后恢复；不会从下一步按钮推断掌握。
6. 规则比较面板保存基线与候选。静态模式零模型调用，只检查规则完整性；实时模式每批至多四个案例，基线与候选各最多 32 次，包含内容审阅。精确基线可复用，候选实跑。内容或评价未完成时不能保留候选；保留记录存入本机资料。

## 模型与数据

`npm run model:check` 只检查登录和目录；加 `-- --generate` 发起一次短文本请求，使用现有账号额度。目录存在不代表有推理权限。`CODEX_BIN` 可指定 Codex 可执行文件；不要求粘贴密码或 token，不读取或修改登录文件，不使用环境中的付费 API Key。

实时资料会发送至云端，文件和运行记录保存在 `data/`，导出在 `exports/`，检查截图在 `runs/`。这些目录不提交 Git。服务仅监听 127.0.0.1，并检查 Host 与 Origin，不用于公网部署。默认关闭环境、shell、网页、MCP 和应用工具访问；发现非文本工具项即停止任务。

模拟新手只取得固定画像、问题、可见讲解/图注、已教概念和复读断点；不取得原始方法资料、完整核对报告或案例参考答案。核对角色取得本任务材料，独立检查。相同模型仍可能共同出错。

产品中的模拟新手负责表达试读；另有开发用学习模拟，保存固定画像、真实可见讲解、实际作答与应用证据，支持跨轮恢复。两者与真实用户的主动反馈分开，不将答对一次或自称理解当作永久掌握。未接入 TinyTroupe、CAMEL 或 Generative Agents；只借鉴已核查的机制。

```powershell

npm.cmd run eval           # 静态规则回放，零模型调用
npm.cmd run eval -- --live --small # PCR 开发 + Ct 留出，最多 28 次（含基线、候选及内容审阅）
```

当前本机已接入 Xu 2018 正文 PDF，示例可查看 15 页原文；Figure 1、6 提供图件所在原页并保留图注，PPT 按比例嵌入原页。固定讲解仍是局部教学示例，自动提取的文字尚未逐段校对。没有正文文件的安装会回退到注明范围的局部中文证据摘要，缺图时明确占位。讲解使用已登记正文证据；本轮按用户授权额外核验了补充材料，具体已读范围见迁移验收。临床适配、所有图形类型、真实学习效果尚未验证。
